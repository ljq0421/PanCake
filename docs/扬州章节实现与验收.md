# 扬州章节实现与验收

本章依据同目录《游戏策划案-扬州-V1.0》《游戏策划案-扬州-V1.1》实现。冲突条目使用V1.1的详细规则。美术采用可替换几何占位，操作音复用项目现有合成音效。

## 本次确认的策划口径

- 扬州继续与天津、武汉、西安、广州共用金币，不改造城市独立经济。
- 广州Day12一星完成后开放扬州；读取已有广州通关存档时补齐解锁。
- 测试直达扬州与Day8练习只在 `--dev-ui` 模式显示。测试直达正常推进扬州存档；Day8练习不保存成绩和金币。
- 优先顾客类型比例及专属订单偏好。每日模板权重作为普通茶客的基础池及整体趋势参考，不承诺同时满足互相冲突的边际比例。因此实际收入也不强行等于策划估算。
- 小费沿用项目整数金币，四舍五入。普通/老茶客/游客/结伴分别为10%/15%/20%/10%。

## 入口和操作

启动主场景，经营首页进入早餐地图，广州通关后点击“前往扬州”。开发启动示例：

```powershell
& "D:\Godot\GodotSharp\Godot_v4.7.1-stable_mono_win64_console.exe" --path . --log-file "$env:TEMP\yangzhou-play.log" -- --dev-ui
```

扬州经营首页可选已开放日期、购买设备、查看最佳成绩及三星收藏。每次开店有5秒可操作准备时间，随后自动营业。

1. 在砧板按住鼠标左右往复切丝，一块豆干产出多份备料。静止按住不会增加进度。
2. 从干丝备料盘拖1份到漏勺。按住漏勺下拉浸入0.3秒，再向上提起；重复3次后锁定最佳品质。松手、出界、暂停或失焦会取消当前未完成的浸入，不凭空增加次数。
3. 点击“调味”，0.3秒后把完成的干丝拖入当前顾客托盘。1烫和2烫也允许出餐，分别扣10分和5分。
4. 用“+2”按钮装笼，或从底部生坯补给按钮拖单个生坯入笼；同一层只能一种点心。点击盖笼，等熟后揭盖，再点击出笼入盘。满盘时保留笼内成品。
5. 绿杨春茶点击取用，0.3秒后拖入托盘；点心从成品盘拖入托盘。
6. 点击上方茶客切换托盘，之前放好的商品保留。凑齐后必须点击“整套出餐”，暂存商品不会提前结算。
7. 底部按钮免费补满原料。补给完成前不增库存。暂停、失焦暂停、退出确认都冻结生产及顾客时钟。

| 竹蒸笼 | Lv1六格并保留过蒸品质；Lv2八格自动保温；Lv3双层各八格、独立计时、快蒸与手动出笼 |
| 蒸制品质 | 三丁7/10/13秒、烧卖5.5/8.5/11秒分档；过蒸仍可卖，品质随成品入库、随托盘交付 |
| 补给 | 豆干3块、三丁坯12、烧卖坯12、调味8、茶6；0.8秒/0.6秒免费补满 |

| 订单 | A～L固定配方；类型比例按最大余数分配，种子随机打散；专属偏好加权抽取 |

| 教学 | Day1耐心乘1.2，保护期不离店；70秒后等待玩家完成最后订单，允许主动放弃 |
| 评分 | 满意度仅统计成功完成订单；错商品保留原库存并记错；食物品质扣分逐份累加；离店清空该顾客托盘 |
| 星级 | Day12一星14组/70%，二星17组/82%，三星18组/90%且交付Perfect干丝≥10份 |
| 收藏 | 三星解锁蟹黄汤包图鉴和三星城市徽章；地图节点转为金色；不增加汤包制作线 |
| 存档 | 复用v3格式与共享金币；重玩仅补收入纪录差额；写盘失败回滚；最高星级独立于收入纪录保存 |

## 实现位置

- `Data/Yangzhou/chapter.json`：商品、模板、顾客偏好、12天数值、设备参数及升级价。
- `Scripts/Yangzhou/YangzhouCatalog.cs`：配置读取与校验。
- `Scripts/Yangzhou/YangzhouProduction.cs`：切丝、三烫、分层蒸笼、原料和成品库存。
- `Scripts/Yangzhou/YangzhouOrders.cs`：固定种子计划、专属偏好、顾客托盘与品质评分。
- `Scripts/Yangzhou/YangzhouSession.cs`：准备/营业/收尾/结算时钟、来客保护、出餐和统计。前几城使用逐件交付，扬州明确整套出餐，因此采用章节独立会话，避免改变既有交付逻辑。
- `Scripts/Core/YangzhouSave.cs`：解锁、升级、金币入账及收藏。
- `Scripts/UI/YangzhouHub.cs`、`YangzhouSurface.cs`、`YangzhouMapEntry.cs`：经营首页、可替换占位交互面和地图节点。
- `Scripts/Gameplay/YangzhouDayScreen.cs`：营业UI、输入、暂停与结算；由现有 `GameController` 接入主场景。

## 验证

- `dotnet build --no-restore`：0警告、0错误。
- `YangzhouSelfTest`：92项通过，覆盖1,200个随机种子、制作和库存边界、正确/错误托盘、耐心分段、高压保护、三星按干丝份数统计、12天完整生产、零初始资金升级成长、存档往返及写入失败回滚。
- `YangzhouVisualCapture`：1080p普通模式21项、720p开发模式22项通过。使用真实Godot鼠标输入，验证往复切丝、原生拖拽、三烫、调味、装笼/出笼、四桌订单、整套出餐、暂停/失焦、实际主场景地图往返、退出，以及练习模式隔离存档。
- 回归：天津StageOne～StageFour、武汉、西安、广州自检均通过。
- 自动生产模拟从0金币按Day4干丝Lv2、Day6蒸笼Lv2、Day9干丝Lv3、Day10蒸笼Lv3推进，12天都能完成全部顾客，最终日三星。此结果证明生产和成长链路可达，不替代真人手感与难度验收。

## 后续美术接入边界

本版暂不制作城市背景、人物、食品、蒸笼正式美术或专属环境音。占位面保留视觉状态及输入边界，换资源时应保留拖拽命中区、订单暂存模型和所有生产规则。后续打包导出时需将本章JSON连同项目现有其他JSON配置包含进导出过滤器。
