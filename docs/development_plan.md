# Project Cake 分阶段开发计划

> 计划版本：0.2  
> 对应设计文档：`docs/game_design.md` 0.3；五区成长详见 `docs/five_area_progression_redesign.md`  
> 引擎：Godot 4.7.1  
> 目标：先验证单张煎饼的操作手感，再构建最小经营循环

## 1. 执行原则

1. 当前唯一高风险核心是面饼、酱料和折叠是否能形成可控、可理解、可重复提升的连续鼠标操作。
2. 核心手感未通过真人试玩前，不批量生产顾客、配料和摊位美术。
3. 每个阶段都有独立可运行产物和明确验收条件。
4. 自动检查证明逻辑稳定，不能替代真实鼠标操作和视觉验收。
5. 新想法默认进入待办池，不在当前阶段中插入实现。
6. 场景结构、稳定节点和固定布局优先写入 `.tscn`；脚本负责数据、输入、状态切换和刷新。

## 3. 建议核心模块

| 模块 | 职责 |
|---|---|
| `PancakeModel` | 保存覆盖、厚度、湿度、火候、破损和酱料数据 |
| `PancakeRenderer` | 将逻辑数据更新为遮罩纹理并驱动 2D Shader |
| `ToolController` | 管理拿起、拖动、放下和工具状态 |
| `StrokeSampler` | 按移动距离采样鼠标轨迹，保证帧率无关 |
| `CookingController` | 推进局部凝固、成熟和焦化 |
| `FoldingController` | 管理受控折线、拖拽进度和结构结果 |
| `PancakeScorer` | 从同一份逻辑数据计算品质和反馈标签 |
| `OrderService` | 生成订单并校验材料和制作要求 |
| `CustomerService` | 管理顾客进入、等待、评价和离开 |
| `BusinessDayService` | 管理单日流程、收入、口碑和日结 |
| `ProgressionService` | 管理摊位、工具和配料解锁 |

数据模型与渲染必须分离。不能通过读取最终屏幕像素决定品质，也不能让 Shader 成为唯一业务状态来源。

## 4. M0：工程基础

### 目标

建立可重复运行、可测试、可调试的 Godot 4.7.1 工程基础，不实现完整玩法。

### 工作内容

- 固定 Godot 4.7.1 作为项目版本并记录开发环境。
- 设置 1920×1080 基准画布、窗口缩放和中央安全区域。
- 建立主场景、操作台场景和调试场景。
- 建立基础输入映射。
- 建立日志、调试覆盖层和测试入口。
- 确认当前 Mobile 渲染器可以完成动态 2D 遮罩更新；没有明确限制时不切换 Forward+。
- 设计数据参数资源，允许不改代码调整面糊流动、凝固、刮板宽度和阈值。

### 产物

- 可启动的主场景。
- 1920×1080 操作台灰盒。
- 可显示鼠标轨迹、帧率和逻辑网格的调试层。
- 最小自动测试入口。

### 验收

- 项目在 Godot 4.7.1 中无错误启动和退出。
- 16:9、16:10 和超宽窗口下，中央操作区位置稳定。
- 鼠标局部坐标与鏊子逻辑坐标转换正确。
- 调试层可以单独开关。

## 5. P0：核心操作原型

### 目标

验证面糊厚度、破洞、刷酱和折叠能否通过连续鼠标输入形成可控差异。

### 范围

- 只使用临时美术。
- 不做顾客、经济、正式 UI 和大量配料。
- 只完成一张煎饼从倒面到折叠的自由练习。

### P0.1 面饼数据模型

- 建立暂定 256×256 的逻辑网格。
- 保存覆盖、厚度、湿度、火候和破损数据。
- 实现网格重置、快照和调试可视化。
- 记录模拟更新耗时。

#### 自动验收

- 相同输入数据产生确定性相近的结果。
- 重置后所有字段恢复初始值。
- 无越界写入和无效数值。
- 网格数据可被评分模块读取。

### P0.2 自动定量倒面与T形摊饼器

- 点击面糊勺后在鏊心自动倒入一次固定面糊团，并直接切换到 T 形摊饼器；不再要求玩家控制倒面时长和落点。
- 实现按距离采样、围绕鏊心由内向外的螺旋摊饼轨迹；单纯放射状直推不生效。
- 实现沿半径向外推面、画圈速度控制厚薄、厚度均匀化、凝固阻力和反复经过薄区形成破洞。
- 加入工具轨迹、作用半径和厚度热力图调试显示。

#### 操作验收

- 玩家可以有意制作中心厚、边缘厚、局部薄和带孔面饼。
- 同一路径在 30、60、120 FPS 下结果近似。
- 鼠标快速移动时轨迹不会出现大面积断裂。
- 破洞出现前有足够视觉和声音预警。

### P0.3 动态渲染

- 准备临时生面糊、熟面饼、焦化和破边纹理。
- 将逻辑数据上传为动态遮罩纹理。
- Shader 表现覆盖、厚度、湿润、成熟和破洞。
- 更新频率和纹理尺寸可配置。

#### 性能验收

- 目标 PC 上持续操作时保持稳定帧率。
- 动态纹理更新无持续内存增长。
- 画面显示与逻辑热力图一致。

### P0.4 刷酱

- 实现按住酱料按钮的时长控制刷子含酱量，满刷容量足够覆盖一张典型面饼。
- 实现宽幅、按距离采样的刷酱轨迹；速度不影响浓淡。
- 刷子经过区域即形成一层；不论鼠标是否松开，只要刷子离开后再次经过同一区域，就叠加一层浓度。连续采样自身的重叠不重复计层。  
- 实现补蘸和补刷，不实现吸油纸。
- 加入酱料覆盖和浓度热力图。

#### 操作验收

- 玩家可以有意做出均匀、局部过多、局部缺失和断续刷痕。
- 酱料分布在最终评分和画面中一致。

### P0.5 折叠原型

> 状态：2026-08-01 已完成自动检查、Mobile 渲染验证与真人鼠标验收。

- 将面饼划分为受控折叠区域。
- 实现抓边、拖动、越过折线和落下。
- 实现厚度、火候和破损对折叠的基础影响。
- 两侧折叠完成后统一自动装入纸袋，不提供额外包装选择。

当前灰盒原型约束：

- 先验证左右两个受控折叠区，不加入完全自由布料物理和 P1 配料阻力。
- 选择折叠工具后显示折线与抓边提示；鼠标拖动实时改变折片，只有越线松开才提交。
- 折叠开始后锁定倒面、刮板和刷酱，避免折叠结果与原始业务数据不同步。
- 小裂口与严重撕裂均继续完成两侧折叠并自动装袋；损伤只通过原有完整度和折叠结构评分体现。

#### 操作验收

- 折叠不是点击播放动画，而是由鼠标拖动完成。
- 破洞和薄区在折叠后保留其位置影响。
- 明显过厚、过脆和破损会产生不同失败表现。
- 折叠失败后不会出现无法继续或无法重置的状态。

### P0 阶段门槛

组织至少一次真人试玩，连续制作至少 20 张煎饼。只有同时满足以下条件才进入 P1：

- 测试者能理解主要失误原因。
- 测试者能通过练习主动改善均匀度。
- 修补有价值但不能恢复完美结果。
- 连续操作约 10 分钟没有明显手腕疲劳。
- 面饼、酱料和折叠三部分中没有一项需要整体推翻交互方案。

若未通过，继续迭代 P0，不增加顾客和经营内容。

## 6. P1：完整煎饼垂直切片

> 实现状态：2026-08-01 已完成代码、自动检查与 Forward Mobile 冒烟；P1 真人验收尚未完成。由于 P0 连续制作 20 张的总门槛仍未完成，本状态不等同于正式通过阶段门槛。

> 本节记录已经实现的历史垂直切片范围，其中“两种酱料”等测试内容不代表当前新存档默认解锁状态；现行开局仅有甜面酱，辣酱后续解锁，五区成长以 `docs/five_area_progression_redesign.md` 为准。

### 目标

完成一位顾客、一张订单、一张煎饼和一次评价的完整闭环。

### 范围

- 1 种经典杂粮面糊。
- 2 种酱料。
- 鸡蛋、薄脆、火腿肠、葱花。
- 1 名顾客。
- 3 至 5 种订单组合。
- 基础修补工具。
- 临时或首批正式美术。

### 工作内容

- 完成局部火候与翻面；鏊子火力固定使用当前默认值，不提供玩家调节。
- 完成配料拖放、方向和基础结构影响。
- 完成操作状态机和工具可用范围。
- 完成订单生成、展示和校验。
- 完成制作时间、顾客耐心和出餐。
- 完成品质评分、热力图、标签和顾客反馈。
- 增加新手提示，但不强制每一步等待确认。
- 加入基础音效：面糊落下、刮板、滋滋声、翻面、刷酱、折叠和出餐。

> 音效实现状态：2026-08-02 已完成七类原创确定性音频资产、场景绑定与实际交互触发检查；真人听感验收仍未完成，详见 `p1_audio_report.md` 与 `../tests/manual/p1_audio_playtest.md`。

### 自动验收

- 订单正确性判断覆盖所有组合。
- 评分模块对厚度、破洞、火候、酱料和结构拥有独立测试。
- 修补标签和评分上限正确保存。
- 状态机不存在跳转死路。
- 暂停和恢复不会继续推进火候或顾客耐心。

### 真人验收

- 玩家第一次游玩可以在有限提示下完成订单。
- 玩家能指出顾客不满意的具体原因。
- 正确但粗糙、错误但漂亮、修补后可接受等不同成品得到不同反馈。
- 单张制作时间暂定落在 35 至 70 秒范围内。

## 7. P2：最小经营循环

### 目标

将完整煎饼垂直切片扩展为一个可以重复游玩的营业日。

### 范围

- 1 个清晨移动煎饼车初始状态。
- 3 名顾客。
- 10 种订单组合。
- 每个营业日固定 2 分钟；顾客持续到访，不设置每日固定顾客数。剩余 10 秒显示打烊提示，归零立即日结，当前制作、待出餐和排队订单均不允许延时完成。
- 金币、口碑和日结。
- 工具升级的具体种类、效果和数量待定。
- 火腿肠、肉松和里脊三种首批手动购买解锁配料。
- 最小存档。

### 工作内容

- 实现顾客进入、排队、等待和离开。
- 实现单日营业状态机。
- 实现收入、成本、浪费和口碑。
- 实现日结复盘和问题统计。
- 实现工具升级，验证升级改善条件但不替代操作。
- 实现食材永久解锁与进货；取消“今日上架”，已解锁内容永久进入订单候选池。
- 为火腿肠、肉松和里脊分别实现独特操作特性。
- 以 `docs/five_area_progression_redesign.md` 为现行规则，按“煎饼 → 成品饮品 → 油条 → 现磨豆浆 → 蒸品”重构五个固定功能区域；移除鸡蛋仔现行入口，蒸品使用已包好的半成品并采用分层独立计时。
- 将中央鏊子和实际操作面相对初始场景等比缩小 20%，保持模拟网格和评分口径不变。
- 实现最小存档：日期、金币、口碑、升级、解锁和设置。

### 自动验收

- 单日计划到访顾客均结算后可完整推进到日结；离开的顾客也计入当日已处理客流。
- 收入、成本、浪费和修补支出计算一致。
- 存档后重启能恢复所有最小进度。
- 未解锁配料不会进入订单池；已解锁配料即使库存为 0 仍可能被点单。
- 升级不会开启第二个鏊子；购买对应自动化升级后，核心动作可以按升级定义自动完成，并继续正确消耗原料、时间和费用。

### 真人验收

- 一局 5 至 8 分钟内有明确节奏变化。
- 排队压力不会迫使玩家放弃观察成品。
- 肉松和里脊明显改变操作，而不是只改变订单文字。
- 日结能解释当天主要失败原因并提示下一步。
- 玩家愿意主动开始第二个营业日。

## 8. P3：正式美术与内容扩展前评审

P3 不是自动进入的大规模制作阶段。P2 完成后先评审：

- 核心制作是否足够有趣。
- 单鏊子是否仍能支撑长期压力。
- 修补是否过强或过弱。
- 新配料能否持续产生不同操作。
- 顾客反馈是否准确且不啰嗦。
- 经营层是否喧宾夺主。

只有评审通过后才规划：

- 更多现实配料。
- 摊位视觉升级阶段。
- 熟客和供应商事件。
- 招牌配方。
- 荒诞搞笑配方。
- 更长的经营进度。

## 9. 美术生产计划

### 9.1 P0 临时素材

- 简单几何操作台。
- 临时鏊子、工具和食物色块。
- 临时面糊、熟面饼、焦化和酱料纹理。
- 不生产正式顾客。

### 9.2 P1 首批正式素材

- 工作台背景和前景遮挡。
- 鏊子底图。
- 面饼基础纹理组。
- 勺子、刮板、刷子、铲子和夹子。
- 4 种基础配料及少量外形变体。
- 1 名分层顾客和基础表情。
- 最基础的订单卡和品质图标。

### 9.3 P2 营业素材

- 另外 2 名顾客。
- 肉松和里脊。
- 从移动摊车向半固定摊位过渡的一个升级状态。
- 日结界面。
- 金币、口碑和升级图标。

### 9.4 每批素材验收

- 视角、线宽、光源和色板一致。
- 透明通道干净，无明显白边和杂点。
- 运行尺寸下轮廓清楚。
- 枢轴和交互位置记录准确。
- 不包含 AI 生成文字。
- 原始图、提示词、参考图和授权记录完整。
- Godot 完成导入后，在真实主场景中检查，而不是只在图片查看器中确认。

## 10. 测试策略

### 10.1 单元测试

- 网格坐标和鼠标坐标转换。
- 距离采样。
- 厚度移动和守恒容差。
- 凝固、成熟和焦化。
- 破洞阈值。
- 酱料浓度叠加。
- 修补标签和评分上限。
- 订单校验。
- 收入、成本和口碑。

### 10.2 集成测试

- 单张煎饼完整状态机。
- 暂停和恢复。
- 顾客从进入到评价的完整流程。
- 单日营业到日结。
- 保存、退出和恢复。
- 新配料解锁与订单池。

### 10.3 真人操作测试

自动测试不能覆盖：

- 刮板是否顺手。
- 画面是否能看懂厚薄。
- 声音是否能帮助判断火候。
- 折叠是否有控制感。
- 修补是否令人满足。
- 10 分钟连续拖动是否疲劳。

每个阶段必须保存试玩版本、记录参数和整理问题，不以“自检通过”替代产品验收。

## 11. 主要风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 模拟过于真实 | 结果不可预测，玩家不知道为何失败 | 减少隐藏变量，强化热力图和视听反馈 |
| 模拟过于简单 | 多次制作没有技巧提升 | 保留轨迹、速度、时机和覆盖差异 |
| CPU 动态纹理过慢 | 操作时掉帧 | 先降低网格与更新频率，再评估 SubViewport 或 GPU 方案 |
| 折叠实现失控 | 穿模、抖动、无法复现 | 使用受控折线与有限区域，不做完全自由布料 |
| AI 美术不一致 | 顾客和工具像来自不同游戏 | 固定基准图、色板、线宽和批次验收 |
| 配料越来越多 | 操作台拥挤、难以寻找 | 右侧固定 4×3 小料盘；鸡蛋、薄脆和香葱等改从补充容器直接拿取 |
| 自动化过早或过强 | 前期学习被跳过、后期完全无决策 | 把自动化放在中后期，保留原料、容量、速度、设备调度和购买成本约束 |
| 修补过强 | 失误没有代价 | 使用时间、资源和品质上限三重成本 |
| 修补过弱 | 玩家频繁整张重做 | 普通失误至少提供一种挽救路径 |
| 内容扩张过早 | 核心不好玩但资产大量堆积 | P0 真人验收不通过则禁止进入 P1/P2 扩产 |
