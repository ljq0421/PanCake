是的，我建议把右页上方的 **“今日小结 / 顾客明细”两块大分页标签删除**。

现在最大的问题不是样式，而是**信息层级表达错了**：它们视觉上明显像“右页内部 Tab”，玩家会自然理解成“只切换右页内容”；但实际上切换的是**整本账本的一整组双页内容**。这会让“账本”的空间逻辑不够成立。

对《早餐铺子》这套偏沉浸式的经营手账，我更推荐 **“翻页导航 + 当前篇章提示”**，而不是把两个 Tab 换成另一组普通按钮。

### 我最推荐的最终方案

把整个营业账本理解成：

> **账本封面/容器 → 第1跨页「今日小结」 → 第2跨页「顾客明细」**

当前这张图就是第1跨页。

顶部两个按钮全部拿掉，腾出来的空间直接还给账本内容。然后在**书页外侧边缘**增加非常轻量的翻页控制，而不是把按钮放在纸张内部。

例如当前“今日小结”：

```text
┌──────────── 左页 ────────────┬──────────── 右页 ────────────┐
│ 武汉 · DAY 12                │                              │
│ 营业账本                     │ 今日接待 · 已结束             │
│                              │                              │
│ 今日收入                     │ 完成 / 流失 / 满意度          │
│ ……                           │ ……                           │
│                              │                       ＞      │
│                              │                 翻到顾客明细   │
└──────────────────────────────┴──────────────────────────────┘
```

这个 `＞` 不要做成现代 UI 的方形按钮，而是做成：

**书页边缘露出的小翻页角 / 小箭头 / 半圆形纸质拉页。**

到了“顾客明细”跨页，则左侧出现：

**`＜` 返回今日小结**

右侧不再有下一页。

这样玩家一眼就知道：

> 我不是在右页切 Tab，而是在翻这本账本。

---

### 比“左右方向按钮放底部”再好一点：放在书页外缘中部

你当前右下已经有：

* 「收好账本」
* 「Esc 返回」

因此我反而**不建议把翻页箭头也塞到右下角**，否则三个不同层级的操作会挤在一起。

推荐位置是右页**外侧边缘中下部**，大约：

> 页面高度 52%～65% 区域。

视觉类似一本书页右边缘露出一个小小的：

```text
       )
      ＞
       )
```

顾客明细页则在左页外缘出现：

```text
(
 ＜
(
```

这样三个操作的空间语义就完全分开了：

* **书页外缘箭头** → 翻账本内容
* **收好账本** → 关闭本次结算
* **Esc 返回** → 系统快捷返回

层级会清晰很多。

---

### “今日小结”这个名称还是要保留，但不要再做成可点击 Tab

我建议把它降级成**当前跨页标题**。

现在左上已经有：

> 武汉 · DAY 12
> 营业账本

可以改成类似：

> 武汉 · DAY 12
> **营业账本**
> 今日小结

其中“今日小结”只用一枚很小的暖棕/青绿色手账印记，甚至直接作为副标题，不需要框。

顾客明细页则：

> 武汉 · DAY 12
> **营业账本**
> 顾客明细

这样结构就非常自然：

**营业账本 = 这本书是什么**

**今日小结 / 顾客明细 = 当前翻到了哪一部分**

这比现在右页上方两个并列按钮更准确。

---

### 还可以加入一个很轻的“目的地提示”

单独一个 `＞` 虽然沉浸，但第一次进入时不一定知道下一页是什么。

所以 PC 版可以：

* 常态：只显示小翻页箭头；
* Hover：显示很小的 `顾客明细`；
* 点击：执行翻页；
* 第一次进入账本时箭头轻微晃动一次即可，之后不重复。

例如：

```text
常态
＞

Hover
＜翻页＞ 顾客明细
```

不要长期把“顾客明细”文字挂在那里，否则又会逐渐变回 Tab UI。

---

### 我不太建议用传统的 `1/2`、圆点分页

例如：

```text
● ○
1 / 2
```

功能上没问题，但它明显是“应用程序分页器”，会削弱现在已经建立起来的**经营账本 / 手账**感觉。

同样也不建议：

```text
上一页     下一页
```

这种传统矩形文字按钮。

你现在这套 UI 最值得继续强化的恰恰是：

> **玩家在看营业结束后真正记下来的账，而不是在看一个套了书本皮肤的数据面板。**

---

### 如果想比箭头再有一点特色，可以用“书签侧签”

另一个可行方案是在**整本账本最右侧外边缘**做两个很小的书签：

```text
                    ┌── 🙂
                    │
                    ├── 👤
                    │
```

分别代表：

* 今日小结
* 顾客明细

因为它们挂在**书本外缘**，语义上就属于整本账本，而不是右页。

但我认为你目前只有两个跨页，**书签反而略显多余**。等以后如果增加：

* 今日小结
* 顾客明细
* 菜品统计
* 成长记录

达到 3～4 类以后，再切换为书签导航更合适。

---

## 这张页面我建议这样改

1. **删除右页顶部「今日小结 / 顾客明细」两个大按钮。**
2. 左上继续保留「武汉 · DAY 12 / 营业账本」作为全局标题。
3. 在“营业账本”下面加一行很轻的当前跨页名称，例如「今日小结」。
4. 右页外侧边缘增加一个小型 `＞` 翻页控件。
5. Hover 时提示「顾客明细」。
6. 顾客明细跨页左侧对应出现 `＜`，Hover 显示「今日小结」。
7. 点击后做一个很短的 **150～250ms 纸页翻动/滑页动画**。
8. 「收好账本」继续作为结束结算的主要动作，不和翻页混在一起。

这样处理以后，**右页顶部会立即空出来一大块**，你现在“今日接待·已结束 → 14位 → 完成/流失 → 满意度”的信息也可以整体往上提，页面会比现在舒展很多。

我会优先采用 **“书页外缘翻页按钮”方案**，而不是继续保留顶部 Tab。它最符合现在已经确定的“营业账本”视觉概念，也能明显增强模拟经营的沉浸感。
