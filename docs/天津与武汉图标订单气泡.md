# 天津与武汉图标订单气泡

2026-09-08。天津与武汉营业场景共用 `Scripts/UI/OrderBubbleView.cs`，分别由 `TianjinDayScreen.cs` 与 `WuhanDayScreen.cs` 接入。本页替代《天津库存与订单气泡优化》中“订单气泡”章节的旧文字与底框规则；该文其他库存、食材和输入记录仍按其原有范围生效。

## 已确认的显示规则

- 每份煎饼或热干面独占一条等宽横行。同款数量为2时展开两行，不合并为数量标记。每行紧跟该份主食自己的额外配料图标，不把配料放到公共区域。
- 主食交付完成后只将对应区域变浅绿；其他主食与副食区域保持自己的交付状态。不同主食可不按显示顺序交付。
- 底部共享一条副食横行，每种副食一个图标及“已交付/需求”分数，区域等宽。天津为单卖油条、豆浆，武汉为豆皮、蛋酒。数量大于1仍只显示一个副食图标；部分交付只更新分数，全部交齐才将该区域独立变绿。
- 不显示商品名称、份数序号、顾客类型、状态文案或整单总进度。主食完成仅按用户指定的区域变绿表达，此约束只用于订单气泡，不推广为全局状态规范。
- 正常酱量无图标；少酱、多酱分别使用带“少”“多”的栅格图标。食物与配料使用正式游戏美术，热干面图标组合现有碗与面条图层。
- 气泡底部保留耐心条。展示节点忽略鼠标，原顾客交付区域继续处理拖拽落点；制作、交付判定、订单生成、耐心与经济规则不因本组件改变。

## 材质与实现边界

天津继承暖纸色、深棕描边，武汉继承米白纸色、墨绿描边。组件采用 `StyleBoxFlat` 圆角纸面、单层向下阴影、分隔线与独立绘制的对话尾巴；不再使用旧 `StockUI` 九宫格订单底框或美术耐心框。耐心使用实际 `ProgressBar`。

主食区域与副食区域按交付数据分别更新底色。相同订单刷新复用已有节点，顾客更换订单时重建内容，避免上一单图标或完成状态残留。图标使用透明轮廓裁切与等比适配，不将原始食物画布的空白当成可见尺寸。

## 素材来源与复现

酱量图标位于 `resource/art/TianJin/OrderUI`。按项目透明素材要求，先生成绿色背景，再由 `tools/prepare_order_sauce_icons.ps1` 去绿、裁切并输出透明 PNG。原始绿底图、实际首次及修正提示词保存在 [OrderUI 素材说明](../resource/art/TianJin/OrderUI/README.md)；原始生成 PNG 内同时保留提示词来源信息。其余图标沿用天津、武汉已有食物素材。
