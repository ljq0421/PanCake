# P0.4 简化刷酱实现与验证报告

> 日期：2026-08-01  
> 引擎：Godot 4.7.1 stable

## 最终交互规则

- 已完全移除吸油纸、修补标签和酱料评分上限逻辑。
- 酱刷初始为空；按住酱料按钮时以每秒50%容量蘸取，约2秒到上限。
- 满刷容量以当前面饼的实际覆盖格数为基准，足够将整张面饼完整刷一层。
- 速度不参与酱料浓度计算。
- 连续相邻采样的刷子覆盖重叠不会产生隐藏叠加。
- 不论鼠标是否松开，只要刷子离开后再次经过同一格子就增加一层；来回刷动可直接产生局部过量。
- 刷子半径由9格扩大到16格，距离采样由4格放宽到6格。

## 数据、渲染与评分

- `PancakeModel.sauce_concentration` 是唯一酱料业务数据源。
- Shader 通过独立R8纹理显示酱色，数字键 `6` 显示相同数据的浓度调试图。
- `PancakeScorer` 从同一字段计算覆盖率、平均浓度、均匀度、过量率和标签。
- 均匀一层、局部缺失和多层过量拥有独立自动检查。

## 自动验证

- 0.5秒蘸取约25%，长按在100%停止。
- 相同路径在30/60/120 FPS下结果近似一致。
- 原地连续采样不叠层；同一次按住期间离开再返回，以及松开后重新刷过，都会叠加新层。
- 一条三行之字宽轨迹覆盖典型面饼至少95%。
- 主场景中不存在吸油纸节点。
- 主场景真实按钮长按、刷酱、容量消耗、第二层和调试图路径通过。
- 旧倒面、刮板和动态渲染回归继续运行。

## 性能与截图

动态纹理仍为一张RGBA8加两张R8，渲染上传结构未扩张。最终性能和画面由以下命令复现：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\run_checks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\run_cpu_benchmark.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\run_mobile_smoke.ps1
```

2026-08-01 实测结果：

- 全量自动检查全部通过，包括 P0.4 单元检查、交互检查，以及 P0.2/P0.3/M0 回归。
- 128×128 CPU 基准：刮板模拟平均 7.091 ms/采样，凝固定步平均 0.381 ms/步，动态字段上传平均 7.307 ms/次。
- Godot 4.7.1 Forward Mobile（NVIDIA GeForce RTX 5070）GPU 冒烟通过。
- 240 次连续纹理上传平均 6.233 ms/次，静态内存增量 152.5 KiB，纹理 RID 全程复用。
- 180 个渲染帧平均 16.41 ms，P95 16.88 ms。
- 冒烟轨迹的酱料评分为 68.4；该数值只证明评分和渲染路径工作，不代表交互手感已经通过验收。

## 未完成门槛

2026-08-01 已由用户确认：同一次按住期间，刷子离开后再次经过同一区域时，第二层的视觉加深足够明显。

自动覆盖率仍不能证明蘸酱时间、刷幅、轨迹数量和连续操作疲劳实际合格。必须完成 `tests/manual/p0_4_sauce_playtest.md` 的其余真人鼠标验收项后，才能将 P0.4 标记为完整通过并进入 P0.5。

## 2026-08-02 真人试玩后的流程修正

- 旧的“按住酱瓶给刷子蘸酱”已废止。
- 现在点击酱瓶会先在饼面生成最小可见酱团，继续按住按时间增加用量；甜面酱与辣椒酱的未摊开用量独立保存。
- 玩家随后拿起酱刷，刷动会消耗对应可见酱团并写入原有模型浓度场；评分与 Shader 数据源不变。
- 进入刷酱配料阶段后停止继续累积焦化，避免新手因学习刷酱和放料而必然烧焦。
