# 五槽位独立旅程存档（2026-09-20）

## 玩家操作

正式版、试玩版各自保留五段旅程，互不读取。首页“继续旅程”进入上次使用的存档，“存档管理”可新建、继续、改名和删除。“新的旅程”先选空槽，再播放原有开场，正式出发才创建文件。取消不占槽；满槽时必须先确认删除，不自动覆盖、搬动或轮换。

每段旅程独立保存金币、城市进度、升级、教学、收藏及继续位置。音量、显示等设置仍由原设置服务独立保存。名称默认“旅程 1–5”，去除首尾空白后允许 1–20 个 Unicode 文字字符，允许重名；列表始终显示编号、当前标记、城市、开放营业日、金币和保存时间。

删除确认默认聚焦“保留旅程”，Esc 取消。删除当前档后不自动选择其他档，首页继续按钮禁用。经营手账不再提供重置入口；损坏档提示返回首页存档管理，其他槽位正常使用。存档切换只从首页进入，营业中和待保存结算中没有切档入口。

## 文件与兼容

- 正式版：`user://journeys/slot-1.json` 至 `slot-5.json`。
- 试玩版：`user://demo/journeys/slot-1.json` 至 `slot-5.json`。
- 每槽封装格式版本、旅程标识、名称、UTC 保存时间及原 v3 `SaveData`。改名不改变营业保存时间。
- 各目录的 `index.json` 记录上次选择及旧档迁移完成状态；槽位摘要直接读各槽文件。索引缺失、损坏或选中档异常时，需要玩家主动选择，不擅自加载其他档。
- 首次启动通过 `.legacy-import` 下的副本执行已有 v1/v2/v3 与旧试玩转换，把结果放入槽位 1，保留旧原文件。旧试玩路线仍遵循原有备份后从天津重新开始的规则。无法解析的旧档以异常槽位保留，不静默新开局。已有槽位或迁移完成标记阻止重复导入。

槽位文件采用临时文件加替换写入。创建时索引保存失败会撤销本次创建；切档在读取和索引保存成功后才替换内存；删除先持久化迁移标记和当前选择，文件删除失败恢复选择。失败会显示错误，可重试。单槽损坏不阻断其他槽。异常退出后若只留下已创建的槽位而缺少选择记录，文件仍可从管理页手动继续。

`SaveService` 提供 `GetSlots`、`ActiveSlotId`、`TryCreateSlot`、`TryLoadSlot`、`TryRenameSlot`、`TryDeleteSlot`；城市保留原有 `Data`、保存及结算调用。营业准备时 `BindRun` 绑定当前会话，切档使旧绑定失效；天津、武汉、西安、广州和扬州结算均拒绝跨旅程入账。切档也清除待播放的章节完成消息。
