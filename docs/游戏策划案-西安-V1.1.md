# 五、剁肉机制调整

上一版如果按照“1份肉=剁一次”实现，Day 12会变得明显过于疲劳。

因此正式调整为：

> **一次完整剁肉动作，产出2份标准剁肉。**

例如：

玩家：

取一块腊汁肉  
↓  
按住菜刀左右快速剁约1秒  
↓  
获得：

**2份肉**

存入预剁肉盘。

普通肉夹馍：

消耗：

**1份**

多肉：

消耗：

**2份**

这样多肉依然会迅速消耗库存，但不会直接让鼠标劳动量翻倍。

# 十七、高压保护算法

西安比单纯限制“最多4顾客”更适合增加一个：

## Waiting Pressure

不同订单具有不同压力值。

| 订单 | 压力 |
|---|---:|
| A 单肉夹馍 | 1.0 |
| B 单汤 | 0.3 |
| C 肉夹馍+汤 | 1.3 |
| D 双肉夹馍 | 2.0 |
| E 双肉夹馍+汤 | 2.3 |

当前等待订单压力：

若：

**≥4.0**

下一名顾客：

延后2秒。

若：

**≥5.0**

最多再延后2秒。

累计：

**最多延后4秒。**

**第三：顾客优先级**

> 先做这个上班族还是先做双份游客？

**第四：胡辣汤**

只是偶尔：

**一直盛汤**

说明胡辣汤设计错了。

如果最忙的是：

**一直翻馍**

说明设备自动化太晚或太弱。

如果最忙的是：

**一直剁肉到手累**

说明单次剁肉产量太低。

# 四十七、西安与天津、武汉的最终区别

| 项目 | 天津 | 武汉 | 西安 |
|---|---|---|---|
| 主食 | 煎饼果子 | 热干面 | 肉夹馍 |
| 动作 | 摊/翻/折 | 烫/沥/拌 | 切/剁/夹 |
| 后台设备 | 油条炸锅 | 豆皮锅 | 白吉馍炉 |
| 快速商品 | 豆浆 | 蛋酒 | 胡辣汤 |
| 最重要管理 | 火候 | 流程排序 | **库存预判** |
| 核心技能 | 手速+火候 | 连续操作 | **提前准备** |
| 后期设备作用 | 自动升油条 | 减轻制作步骤 | 自动烙馍 |
| 最终爽感 | 掌控整个早餐台 | 快速连续出面 | **高速组装肉夹馍** |

因此前三座城市已经能够形成非常明显的学习曲线：

> **天津：学会“做早餐”。**  
> **武汉：学会“同时处理不同流程”。**  
> **西安：学会“为了下一波顾客提前准备”。**

西安 V1.1 的数值结构至此已经可以作为实现基线。


我认为这一版最需要在原型里重点验证的不是“26个顾客够不够”，而是 **一次剁肉产2份是否舒服**。如果 Day 10～12 仍然感觉一直在剁肉，优先改成“Lv3一次剁肉产3份”，不要急着砍掉多肉订单，因为**库存快速消耗本身正是西安区别于前两城的重要玩法**。
