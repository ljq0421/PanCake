# 交互轮廓高亮与顾客交付刷新

## 天津酱料碗贴合修复（2026-09-17）

Demo 与正式版共用悬停实现。酱料碗原先沿用向下平移的面糊碗定位路径，边缘搜索仍会偏离绿色碗身；现改为从酱料碗自身的外侧墨线提取轮廓，包含勺柄。悬停、选中及教学提示共用该遮罩，颜色、线宽与命中范围保持不变。

实际视口已核对正式版第 1、6、15 天的 1080p 悬停，以及 `--demo-pilot` 配置的第 1 天 720p 悬停。专项入口为 `InteractionHighlightSelfTest.tscn -- --capture --sauce-only`；Demo 720p 使用 `--capture-720 --sauce-only --demo-pilot`。构建通过。原综合测试在修改前即于第二件商品拖拽交付断言失败，本次没有将其标记为通过。

2026-09-13：按用户确认，交互高亮适用于各城市顾客与设备，使用贴合整个交互物体外形的清晰实线，在悬停、选中或可交付时出现。包含所属把手、勺柄，不加光晕。

## 共享表现

- `InteractionHighlightPresentation` 统一线宽与颜色：普通悬停：天津为 `#FFF06A`、武汉为 `#20B8AA`，其他城市保持浅暖黄；选中为金黄，可交付为较淡的浅绿，拖到正确目标时加强，错误目标为浅红。正常状态不绘制高亮。
- `ArtContourHighlight` 为透明素材提供独立轮廓层，不覆盖素材原有材质或颜色。人物先合并身体与当前表情头部的透明度，再绘制外轮廓，避免脖颈重叠处出现亮线。柜台裁切继续生效。
- `DrawnArtContour` 为直接使用 `_Draw` 绘制的透明素材缓存外轮廓；背景中已有的设备则使用其可见外缘坐标。两种方式均不以整个输入矩形作为描边。
- `ButtonContourHighlight` 用于本体就是圆角按钮的设备，沿现有形状画实线。`PathContourHighlight` 用于背景收银挂件等预设轮廓。
- 所有轮廓层忽略鼠标输入，不改变交付命中范围、库存消耗、耐心恢复、收银或暂停规则。人物轮廓淡入淡出只作用于轮廓自身；减少动态效果设置下直接切换。

线宽统一使用实际渲染像素：天津、武汉普通悬停为 5px，外加 1px 深褐 `#49382D` 衬边；其他城市悬停、候选目标和提醒为 4px；选中、有效和无效交付为 5px。候选目标透明度为 85%，其余激活状态为 100%。路径在像素坐标空间描线，按钮按画布缩放换算宽度。透明贴图按各层实际拟合矩形、变换、图集区域和翻转采样后合并；扩展绘制区域随线宽变化。直接绘图的透明轮廓按实际屏幕尺寸进行四倍采样，填充网孔后向外生成轮廓遮罩，避免内部接缝、简化折角和固定外移造成的空隙。BackgroundArtContour 使用当前背景贴图，在原图坐标指引附近追踪连续墨线边缘，缓存平滑遮罩；距离约束避免误贴到相邻托盘。

## 城市接入

- 天津：画像使用共享合并轮廓；原料碗和托盘、成品、豆浆、垃圾桶与收银挂件使用现有素材或背景外形。煎饼炉取消高亮；炸锅只高亮滤网，按滤网实际升降位置及锅口遮挡裁切，不高亮炸锅机身。
- 武汉：画像使用共享轮廓；面篮、面碗、原料、熟豆皮托盘、工具、垃圾桶和收银挂件贴合原外形。煮面锅及豆皮锅机身取消高亮。漏勺普通悬停采用武汉主题青绿 5px 加 1px 深褐衬边；面熟后持续绿色 5px，鼠标移入也不覆盖熟面提示。
- 西安：画像使用共享轮廓；馍炉、砧板、肉盘、腊汁、馍和汤锅等设备使用原外形。
- 广州、扬州：顾客保留文字卡，按原卡片形状显示悬停、选中描边；广州原生拖拽另显示可交付和正确/错误目标。扬州仍按整盘上桌流程选中顾客，不增加向顾客逐件拖入的交付。设备采用现有程序绘制形状和圆角按钮，不引入新美术。

## 天津交付闪动修复

原 `TianjinDayScreen.RenderCustomers` 把顾客 ID 与已交付数量组成同一个更新标记。每交付一件商品都会使标记变化，继而把整个顾客槽透明度设为 0.35，再用 0.22 秒淡入；画像作为子节点跟随闪动。

修复后，只有顾客身份变化才播放入场淡入，原顾客的部分交付直接更新订单、耐心条和表情。耐心恢复造成愤怒转为焦躁时，不再误播放耐心恶化的染色警示。

武汉、西安代码中未发现同类交付透明度动画；广州、扬州当前使用文字顾客卡。用户已确认未发现明确原因的城市先不处理，保留正常的耐心恢复和表情更新。
