# 交互轮廓高亮与顾客交付刷新

2026-09-12：按用户确认，交互高亮适用于各城市顾客与各城市设备，使用贴合现有外形的细描边，在悬停、选中或可交付时出现。

## 共享表现

- `InteractionHighlightPresentation` 统一线宽与颜色：悬停为浅暖黄，选中为金黄，可交付为较淡的浅绿，拖到正确目标时加强，错误目标为浅红。正常状态不绘制高亮。
- `ArtContourHighlight` 为透明素材提供独立轮廓层，不覆盖素材原有材质或颜色。人物先合并身体与当前表情头部的透明度，再绘制外轮廓，避免脖颈重叠处出现亮线。柜台裁切继续生效。
- `DrawnArtContour` 为直接使用 `_Draw` 绘制的透明素材缓存外轮廓；背景中已有的设备则使用其可见外缘坐标。两种方式均不以整个输入矩形作为描边。
- `ButtonContourHighlight` 用于本体就是圆角按钮的设备，沿现有形状画细线。`PathContourHighlight` 用于背景收银挂件等预设轮廓。
- 所有轮廓层忽略鼠标输入，不改变交付命中范围、库存消耗、耐心恢复、收银或暂停规则。人物轮廓淡入淡出只作用于轮廓自身；减少动态效果设置下直接切换。

## 城市接入

- 天津：画像使用共享合并轮廓；炉面、炸锅、原料碗和托盘、成品、豆浆、垃圾桶与收银挂件使用现有素材或背景外形。
- 武汉：画像使用共享轮廓；面锅、面篮、面碗、原料、豆皮锅、熟豆皮托盘、工具、垃圾桶和收银挂件贴合原外形。
- 西安：画像使用共享轮廓；馍炉、砧板、肉盘、腊汁、馍和汤锅等设备使用原外形。
- 广州、扬州：顾客保留文字卡，按原卡片形状显示悬停、选中细描边；广州原生拖拽另显示可交付和正确/错误目标。扬州仍按整盘上桌流程选中顾客，不增加向顾客逐件拖入的交付。设备采用现有程序绘制形状和圆角按钮，不引入新美术。

## 天津交付闪动修复

原 `TianjinDayScreen.RenderCustomers` 把顾客 ID 与已交付数量组成同一个更新标记。每交付一件商品都会使标记变化，继而把整个顾客槽透明度设为 0.35，再用 0.22 秒淡入；画像作为子节点跟随闪动。

修复后，只有顾客身份变化才播放入场淡入，原顾客的部分交付直接更新订单、耐心条和表情。耐心恢复造成愤怒转为焦躁时，不再误播放耐心恶化的染色警示。

武汉、西安代码中未发现同类交付透明度动画；广州、扬州当前使用文字顾客卡。用户已确认未发现明确原因的城市先不处理，保留正常的耐心恢复和表情更新。

## 验证入口

`Scenes/Tests/InteractionHighlightSelfTest.tscn` 验证真实部分交付、拖拽目标、取消零消耗、新客入场和画像材质/颜色/命中范围保持。传入 `-- --capture` 或 `-- --capture-720` 可保存代表画面到 `.tmp/interaction-highlights`。执行 Godot 时始终指定可写的 `--log-file`。
