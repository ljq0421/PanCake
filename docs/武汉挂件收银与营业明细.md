# 武汉挂件收银与营业明细

2026-09-11，用户确认武汉完全沿用天津挂件收银规则。

## 玩家行为

- 豆皮解锁前使用 `武汉-热干面.png`，解锁后使用 `武汉-热干面-豆皮.png`。两图均为 1672×941，按统一的 1920×1080 设计坐标适配屏幕。
- 顾客整单付款立即进入营业账本，三枚金币飞入右侧挂件投币口后缩小淡出。部分交付、重复或拒绝交付不触发付款；减少动态效果时直接入账，不播放飞币。
- 原点击收钱入口隐藏并禁用。点击挂件查看本次收入、销售额、小费、完成／流失人数、满意度、Perfect 单数及逐单订单、数量、评分和评价原因。
- 明细按订单结束顺序排列，可滚动查看。流失订单显示未完成，不参与满意度平均值。
- 查看期间暂停顾客耐心、营业时钟、制作和飞币。关闭按钮或 Esc 返回营业，保留独立暂停及失焦状态。Tab 焦点留在窗口内，拖拽和制作手势期间不能误开窗口。
- 五位顾客继续保留，顾客、订单气泡及交付区域同步缩放并为挂件留出空间。

## 2026-09-12 共享账本更新

营业中明细与收摊结算已统一为双页营业账本，五城共享。最新页面、筛选、暂停和结算边界见[全章节营业账本](全章节营业账本.md)。武汉继续使用挂件自动记账规则；本文初版素材名由当前 `WuhanArtCatalog` 与武汉工作台说明中的最新资源配置替代。

## 共享实现与布局

`BusinessDetailsView` 与 `CashPendantFeedback` 由天津、武汉共用；`TianjinBusinessDetails` 保留兼容入口。收入始终以 `DayLedger` 为准，界面及动画不进行二次结算。

`DayController.BusinessRecords` 扩展到武汉，在实际完成／流失入口采集快照并按订单 ID 去重，重开和放弃营业清空，不更改存档格式。独立暂停原因与原 `IsPaused` 开关叠加，关闭明细不会清除其他来源的暂停。

`WuhanWorkbenchLayout` 统一两张新图的热干面坐标，更新豆皮锅面和挂件坐标。工作台命中检测显式包含新锅面上沿，避免原先固定 Y=560 的边界截断竖切手势。场景内的顾客分组改为固定布局，保持顾客裁切及工作台遮挡顺序。
