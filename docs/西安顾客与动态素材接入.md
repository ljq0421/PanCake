# 西安顾客、顶部 UI 与动态素材接入

2026-09-11，按用户确认方案完成。本轮仅调整呈现与界面操作入口，保留已有两张营业整图、关卡与制作规则。

## 结果

- 五位顾客取消人物卡片外框及底板，沿用共享身体和表情图，使用共享柜台半身校准。人物下缘对齐柜台，空位不显示标题或占位卡片。
- 每位顾客使用独立的共享订单气泡与耐心条；选中时气泡边框变为金色。西安肉夹馍逐份显示，多肉和加汁使用附加图标，汤显示数量。部分交付只更新对应商品，立即同步耐心及表情。
- 顶部仅一排营业日、时间及收入、收钱、暂停。取消常驻教学和库存汇总，操作反馈显示三秒后消失。熟馍、预剁肉、肉锅、腊汁和汤库存显示在对应操作区域。
- 暂停菜单包含继续营业、当天教学、返回首页；查看教学期间保持暂停，返回继续使用原退出确认。菜单节点位于交付热区之后，保证鼠标命中菜单，不会穿透到顾客。
- Day 1～5使用肉夹馍整图，Day 6～12使用肉丸锅整图；不叠加独立设备，不改变高级设备机制。

素材目录为 `resource/art/XiAn`，本轮检查时共55张PNG。原始PNG未修改。`XianArtCatalog`按透明度裁掉留白并缓存纹理，动态绘制和订单共用目录素材。

| 配料叠层 | 标准肉量覆盖层-v2、多肉追加覆盖层、腊汁覆盖层 |

## 实现入口

- `Scenes/Gameplay/XianDayScreen.tscn`：人物位置、气泡、顶部状态、局部库存与暂停菜单。
- `XianDayScreen` / `XianWorkbench`：绑定原交互、菜单、状态、共享人物与订单气泡。
- `XianSurface` / `XianArtCatalog`：制作状态纹理、覆盖层、裁边缓存；使用原热区处理手势及拖拽。
- `OrderBubbleView.ConfigureXian` / `RenderXianState`：西安图标配置、选中及耐心更新。原天津、武汉调用方式不变。
