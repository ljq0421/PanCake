# 旅途收藏：顾客图鉴

## 已确认规则

- 正式版、试玩版同步。素材目录 `Global/Customer` 的12张PNG是6位人物各一张立绘与一张表情图，因此图鉴实际为通用6位、天津18位、武汉10位，共34位。
- 通用：年轻女性、普通男上班族、普通女上班族、学生、外卖骑手、出租车司机；天津：现有天津素材中的18位；武汉：现有10位武汉自定义顾客。图鉴归属不修改任何城市出场池。
- 通用人物在各城累计；城市人物只在所属城市累计。按稳定外观标识识别人。正确整单不限品质，每单一次，同日多次接待、重玩和无限营业日均可累计；独立教学、错单、部分交付、流失不计。
- 1次：人物介绍和口头禅；3次：趣闻；5次：熟客印章，无数值奖励。不展示草稿中的口味和出场时间。
- 采用两份人物草稿，补齐年轻女性、男上班族、女上班族、老大爷熟客四位的文案；通用出租车司机文案去掉天津限定。运行时最终文案在 `Scripts/Core/CustomerCollection.Catalog.cs`；旧草稿的分组与解锁建议属于历史方案。

## 页面

- 首页“旅途收藏”内切换早餐收藏与顾客图鉴，进入时默认早餐。
- 顾客分类为全部／通用／天津／武汉。武汉随城市开放，未开放不展示人物详情；全部进度分母固定34，分类显示本分类人数。
- 每页8张卡片、4列2行；切分类回第一页，翻页默认选中该页第一位。右页展示正常表情半身像、称呼、小记、口头禅、趣闻、接待记录和阶段印章。
- 未入册显示匿名剪影及入册条件；未满3次隐藏趣闻。浏览不写存档，返回和Esc回首页并聚焦收藏入口。
- 复用两城现有身体、头像与半身校准，不生成图片。成功结算发生里程碑时，在营业账本实际显示的“营业手记”区域汇总新朋友、趣闻和熟客印章；其余时候保留原营业手记。营业中不提示。
- 右页装饰：复用现有手账、星星、日历、爱心图标点缀人物小记、趣闻、记录与照片，口头禅使用浅色引言便签。保留完整人物文案，图标不接收鼠标输入；已检查1920×1080和1280×720的未入册、初遇与长文案状态。局部视觉复查可加 `--visual-only --detail-icons-only --capture`，跳过数据专项，只保留相关图鉴截图。

## 数据与共享影响

- `SaveData.CustomerRecords` 保存每位人物的接待次数、首次入册城市和实际营业日；阶段由次数推导，不保存逐单评价。旧文件缺少此字段时使用空字典，不推算历史数据。
- 共享 `DayController` 完成整单后暂存在 `DayPlan`，按订单去重；`SaveService.CommitDay` 在原事务中合并，原保存失败回滚、重试防重、存档槽归属和两版隔离机制继续生效。
- 扬州沿用已有营业账本的人物映射，在独立结算事务中汇总正确完成的整盘订单；备餐入托盘不计，流失、未接待和有失误的订单不计。复用共享目录、合并与提示逻辑，不改变扬州经营规则。
- 西安、广州的共享交付入口自动支持通用人物；天津人物在其他城市出现不会推进天津图鉴。
