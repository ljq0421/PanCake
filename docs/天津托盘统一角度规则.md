更适合做的是建立一套**天津工作台美术生产用的统一屏幕透视规范**，以后所有托盘、浅盘、备货盘都按这套规范画。

其中最关键的一点是：**不要让每个托盘都做成左右对称、各自向自己中心收拢的等腰梯形。** 天津当前桌面前后沿基本水平，所以矩形托盘的前后边应该基本保持水平，而左右“纵深边”统一朝**画面中央方向**偏斜。

# 一、先规定天津托盘的统一角度规则

建议定义两个参数。

### 1. 横向边角度 `β`

托盘的前边、后边：

**β = 0°，允许误差 ±0.5°**

也就是说：

> 托盘横边基本与屏幕水平线平行。

不要因为托盘位于右边，就把整个 Sprite 顺时针/逆时针旋转 5°。

所以 Godot 中矩形托盘原则上：

```text
RotationDegrees = 0
```

透视应该画进素材本身，而不是旋转整张图。

---

### 2. 纵深边偏角 `α`

这是最重要的参数。

定义：

> 从托盘前沿向后沿看时，左右两条纵深边相对于屏幕竖直方向，统一向画面中央 x≈960 偏转。

因此：

* 左半桌托盘：向后时**向右偏**
* 正中央托盘：接近竖直
* 右半桌托盘：向后时**向左偏**

可以用这条简化公式：

```text
α ≈ 8° × |Xcenter - 960| / 760
```

最大控制在：

**8°左右，不建议超过 9°。**

这不是在还原真实3D相机，而是建立天津统一的**弱透视规范**。

---

# 二、按照当前天津页面位置，直接规定各托盘角度

下面这些可以直接作为后续美术制作标准。

| 物件       |   当前大致位置 | 横边 | 向后纵深边 |       推荐偏角 |
| -------- | -------: | -: | ----- | ---------: |
| 生油条盘     | 左侧 x≈460 | 0° | 向右偏   |     **5°** |
| 熟油条沥油盘/架 | 左侧 x≈460 | 0° | 向右偏   |     **5°** |
| 金币盘      |   x≈1110 | 0° | 向左偏   | **1.5～2°** |
| 成品盘      |   x≈1360 | 0° | 向左偏   |     **4°** |
| 豆浆托盘     |   x≈1600 | 0° | 向左偏   |   **6～7°** |
| 鸡蛋托盘     |   x≈1450 | 0° | 向左偏   |     **5°** |
| 香葱托盘     |   x≈1450 | 0° | 向左偏   |     **5°** |
| 薄脆托盘     |   x≈1700 | 0° | 向左偏   | **7.5～8°** |
| 火腿托盘     |   x≈1700 | 0° | 向左偏   | **7.5～8°** |

这就意味着右侧四只食材盘**实际上应该有两种角度**：

### 左列：鸡蛋 + 香葱

统一：

**向后左偏约 5°**

### 右列：薄脆 + 火腿

统一：

**向后左偏约 8°**

而不是四只盘都用完全相同的对称梯形素材。

---

# 三、右侧托盘应该长什么样？

这一点对刚才生成的“右侧食材托盘母版”很重要。

假设这是右侧第一列鸡蛋盘：

```text
          后边
       ┌──────────┐
      /          /
     /          /
    └──────────┘
          前边
```

示意图有所夸张。

重点是：

**左边和右边应该整体朝同一个方向偏。**

而不是：

```text
        ┌────────┐
       /          \
      /            \
     └──────────────┘
```

第二种是典型的：

> “这个托盘自己拥有一个消失点。”

正是附件审查认为目前需要解决的问题之一。

---

# 四、所以右侧食材托盘不应该只有一个“万能PNG”

这里我会对刚才的方案再修正一下。

原来我建议：

> 鸡蛋、薄脆、香葱、火腿完全共用一个托盘母版。

现在结合天津真实位置，我认为最好改成：

## 同一个造型母版，派生两个透视版本

```text
TianjinIngredientTray_Master
│
├── RightTray_A
│   └── 后方左偏 5°
│
└── RightTray_B
    └── 后方左偏 8°
```

其中：

### A 型

用于：

* 鸡蛋
* 香葱

### B 型

用于：

* 薄脆
* 火腿

它们必须保持：

* 相同配色；
* 相同描边；
* 相同盘壁高度；
* 相同圆角；
* 相同内部结构；
* 相同尺寸系列；

**只改变纵深线方向。**

这样既统一，又符合所在位置。

---

# 五、还要统一“近大远小”的程度

除了角度，还应该规定第二个透视参数：

### 后边宽度 / 前边宽度

不要做得太夸张。

天津属于卡通弱透视，我建议：

### 前排四只食材托盘

```text
后边宽度 ≈ 前边宽度的 95%～97%
```

例如：

前沿：

```text
200 px
```

后沿：

```text
192 px
```

就足够了。

不要：

```text
前沿 200
后沿 160
```

那会出现很强烈的摄影透视，与天津背景不匹配。

因此天津托盘基本可以理解成：

> **轻微梯形 + 整体向画面中心剪切**

而不是明显梯形。

---

# 六、不同桌面深度，盘面俯视程度也要规定

目前页面中还有前后两层。

## 后排：金币 / 成品 / 豆浆

因为更靠桌面后沿，可以稍微“立”一些：

建议托盘整体包围框：

```text
可见顶面深度 / 托盘宽度
≈ 0.28～0.32
```

### 前排：鸡蛋 / 薄脆 / 香葱 / 火腿

更靠近玩家，应略微看到更多盘面：

```text
可见顶面深度 / 托盘宽度
≈ 0.32～0.38
```

差别不要特别大。

这样玩家会自然感觉：

**前排更近，后排更远。**

---

# 七、前壁高度也统一规定

天津现在部分托盘还有一个问题：

有些盘子前壁很厚，有些像一张薄纸。

建议：

### 普通食材浅盘

前壁视觉高度：

```text
约托盘整体高度的 12%～16%
```

例如素材最终主体高 100px：

```text
前壁约 12～16px
```

足够表达厚度。

不要做到 25～30px，否则会显得像盒子。

---

# 八、两个圆碗不能套这套“5° / 8°矩形规则”

面糊碗、酱料碗需要单独处理。

因为它们是圆形容器。

附件本身也指出，圆形器具不能拿矩形透视边直接判断。

建议规定：

### 碗口长轴

始终：

**水平 0°**

### 碗口椭圆比例

建议：

```text
高度 / 宽度 ≈ 0.55～0.65
```

不要特别扁。

然后：

* 勺柄
* 刷柄
* 碗侧装饰

可以轻微响应所在位置的纵深方向。

但**碗本体不需要旋转5°**。

---

# 九、垃圾桶同样不要强套托盘规范

垃圾桶属于：

**高立体容器。**

允许有明显侧面，而且玩家会接受它略微转向。

因此不用规定：

> “垃圾桶必须左偏8°”。

只要保证：

* 底部接触桌面；
* 顶口椭圆方向合理；
* 不与旁边豆浆托盘形成冲突；

即可。

---

# 十、可以把整个天津桌面划成 5 个“角度带”

这样未来新增任何托盘时，不需要每次重新讨论。

| X坐标区域       | 托盘向后方向        |
| ----------- | ------------- |
| x=0～400     | 向右约 **7～8°**  |
| x=400～750   | 向右约 **4～6°**  |
| x=750～1150  | **0～2°**，近似竖直 |
| x=1150～1550 | 向左约 **3～6°**  |
| x=1550～1920 | 向左约 **6～8°**  |

这套规则非常适合《早餐铺子》这种：

**固定1920×1080、固定背景、固定工作台**

的游戏。

以后程序只要知道器具在哪个区域，就知道应该使用哪个透视版本。
