**这一轮最值得做的，是让天津与武汉具有不同的“制作手感”，而不是仅仅使用不同幅度的果冻动画。**

我建议把两城的方向定为：

> **天津：摊得开、落得脆、折得利落。**
> **武汉：拌得动、翻得稳、切得爽。**

下面按照你已有的制作流程，细化到**玩家操作、视觉变化、声音落点、实现方式和需要补充的素材**。本轮不增加操作次数，不改配方、火候时长和设备自动化规则，也不重新加入已经删除的饮品制作设备。

文中的幅度和时长都是**首版调参建议，尚未在你的项目中实测**；像素以1920×1080设计分辨率为参考。它们用于安排表现，不意味着额外增加等待时间。

# 一、先明确两城各自的动效重点

| 城市／食物   | 建议突出的质感            | 主要动效              | 不应该做成            |
| ------- | ------------------ | ----------------- | ---------------- |
| 天津·煎饼果子 | 薄皮、铺展、脆料、折叠后的饱满感   | 面糊摊开、刷酱、配料落稳、饼皮收合 | 整张煎饼一直像橡皮糖一样弹    |
| 天津·油条   | 表面酥脆、轻微蓬松、出锅利落     | 入油冒泡、颜色变化、提篮、沥油   | 炸锅和油条一起大幅晃动      |
| 天津·豆浆   | 成品饮品、拿取清楚          | 提起、落稳、交付          | 增加摇匀、冲泡、插吸管等步骤   |
| 武汉·热干面  | 面条柔软、酱料附着、筷子带动内容物  | 入碗聚拢、淋酱、局部牵拉、逐渐拌匀 | 整只碗旋转，或筷子自动转圈    |
| 武汉·三鲜豆皮 | 薄皮与厚馅的层次、整片翻动、分块利落 | 铲起翻面、铺馅、刀痕、分块入盘   | 像布一样甩动，或者切完向四周爆开 |

**我建议本轮把主要精力放在四个动作上：天津摊饼与折叠、武汉拌面与豆皮翻切。**其他动作负责把它们连接成完整、舒服的制作过程。

# 二、天津：围绕“从一摊面糊，变成一份饱满早餐”

## 1. 倒面糊与摊饼：天津最重要的连续操作

这两个动作需要分开设计。

### 倒面糊：表现“落下以后向外铺”，不是“一个圆突然放大”

建议的表现顺序是：

**操作被接受 → 一小股面糊落到炉面 → 接触位置稍微鼓起 → 向周围铺开。**

面糊下落时可以略微拉长，接触炉面后则横向展开。不要在落地后向上弹两三次，也不要让整只面糊碗跟着压扁。

第一版可以只使用一小块面糊落料素材，加上已有的饼面基础层；无需制作真实流体。

尤其注意：**落料动画只负责从“没有面糊”过渡到“可以摊”，不能擅自把整张煎饼自动摊完。**

### 摊饼：刮板跟手，饼面跟着有效操作改变

我建议同时呈现三个层次：

**刮板的位置立即响应鼠标。**它是玩家正在控制的工具，不应拖着一条很明显的延迟轨迹。

**刮板附近的面糊轻微受到带动。**可以在工具后方出现一小段浅色弧形铺展痕迹，或让接触区域边缘移动少量像素。

**整张饼的覆盖范围由现有摊饼进度决定。**玩家停手，制作进度不再因为展示动画继续增加；达到现有辅助完成条件后，才把剩余不规则边缘快速收整。

可以把玩家看到的效果理解为：

> 鼠标向右移动，刮板立即向右；附近面糊被推开，饼面逐渐完整。
> 而不是鼠标划一下，系统自动播放一整圈摊饼动画。

**第一版不必追求完整的轨迹涂抹系统。**可以先用“进度控制整体铺展＋刮板附近的局部痕迹”。待这一版手感成立后，再考虑把覆盖形状做得更贴合鼠标轨迹。

### 摊完后的反馈

完成时只需要一次很小的收尾：

饼面边缘整理到位，刮板轻轻抬起，配一个短促的刮擦收尾声。

**不要让已经贴在炉面上的整张饼鼓起来庆祝。**天津的第一个满足感应该来自“我把它摊圆、摊完整了”，而不是来自弹跳。

---

## 2. 加蛋、刷酱和小料：同样是加入食材，运动方式必须不同

这里最容易出现的问题，是所有食材共用同一条“飞过去＋放大缩小”的动画。

我建议按材质区分：

| 内容 | 建议的动作              | 落定后的表现            | 声音落点         |
| -- | ------------------ | ----------------- | ------------ |
| 蛋液 | 小股落下，形成金黄色局部，再铺成蛋层 | 很快贴平，不反复回弹        | 接触炉面时短促“滋”一下 |
| 酱料 | 刷头经过时，酱料覆盖层随路径显现   | 留下两三块简洁刷痕，再收成完整状态 | 刷头接触时轻微刷擦声   |
| 香葱 | 少量较大的葱花小簇错开落下      | 在饼面内快速停住          | 一次轻落料声即可     |
| 薄脆 | 整片落下，轻微倾斜后落平       | 几乎不变形，最多轻轻弹起一点    | 短、轻、偏脆的接触声   |
| 火腿 | 落下时中部稍微压一下，两端略晚落稳  | 很小的柔软回弹           | 比薄脆更柔和的落料声   |

你现在采用蛋液容器的版本，可以直接表现蛋液铺开，**不需要为动效重新增加敲蛋壳的操作**。

刷酱也一样：**当前是点击就继续点击。**可以由一次点击触发很短的刷头动作，但不要借机改成玩家必须来回刷满整张饼。

### 葱花特别适合做“少量错峰落下”

建议一份葱花由几簇简化素材表示，各簇相隔几十毫秒落下。

它们不是库存单位，只是一份配料的视觉拆分。散布范围应固定在煎饼内部，不能随机飞到炉外，也不要用大量细碎粒子破坏你现有的大色块画风。

### 薄脆与火腿的区别要一眼看懂

薄脆适合“轻碰、落平”；火腿适合“稍软、贴合”。

**不要因为都有落料动作，就都套用上一轮7%左右的标准果冻形变。**薄脆基本保持原形，火腿才可以有约3%～5%的局部或整体轻压缩。

### 食材动，托盘不动

天津附件中的5°／8°是托盘素材的纵深透视规范，不是让整张托盘在程序中旋转的角度；横边应继续保持水平。动效应放在被拿取的食材和工具上，不能把托盘一起摇起来。

---

## 3. 翻煎饼：强调“薄片被托起”，不是“圆形图案转半圈”

建议拆成：

**铲子托起 → 饼面离开炉面 → 经过侧面姿态 → 显示另一面 → 落回炉面。**

这里最重要的是中间那个“侧面姿态”。第一版可以通过饼面视觉层纵向压缩、正反面素材切换和小幅上下位移组合完成。

需要避免直接把整张图在屏幕内旋转180°来冒充翻面。我们需要看到的是**从这一面翻到另一面**，而不是原地转向。

建议表现得轻快一些：

饼面离炉高度较小，落锅时横向稍宽、纵向稍扁，随后立刻恢复。声音重音放在落锅接触的那一刻，接一小段滋啦声。

**这里的果冻幅度应小于装袋后的成品。**薄饼落在炉面上可以柔软，但不该像一个厚面团弹起来。

翻面可用时的提示，也不要依赖持续晃动煎饼。保持已有状态提示，配合小铲的轻微就位动作即可。

---

## 4. 折叠与装袋：天津最值得精修的“完成动作”

上一轮已经建立通用装袋回弹，这一轮应进一步解决：

**玩家能否看见“饼皮把配料包起来”的过程？**

建议的视觉顺序是：

**饼边抬起 → 向内收合 → 成品稍微压实 → 进入纸袋 → 袋身撑开并落稳。**

折叠方式应服从你已经确认的成品形状，不要为了动画另设计一种折法。

### 折叠阶段：只动需要折进去的部分

不建议把整张展开饼直接缩小，再突然替换成折叠成品。优先考虑两种实现：

**低成本版本：**增加一张与现有成品衔接的“半折叠状态”，通过短位移和姿态切换完成过渡。

**更细腻的版本：**把饼皮分成中间区域和可折叠边片，以折线为支点向内收合。

第一次实现，前一种就可以先验证效果。没有必要直接搭复杂骨骼。

### 装袋阶段：外包装可以比饼皮更活泼

食物入袋时，袋身横向稍微撑开；整体落稳后，袋口比袋身晚一点点归位。

如果现有PNG没有拆出袋口，就先用整份成品的小幅压缩，不必为了这个细节立即重画素材。

**这段的节奏应该是“收—压—装—稳”，而不是连续四次弹跳。**

还要处理一种高频情况：玩家快速加完料就折叠。此时，尚未落完的配料表现应立即归位并进入折叠，不能出现“饼已经装袋，葱花还在空中飞”。

---

## 5. 油条：把“锅里的动静”和“出锅的动作”分开

油条区不需要成为第二个大型果冻舞台。

| 阶段       | 建议表现                | 保持稳定的部分      |
| -------- | ------------------- | ------------ |
| 生油条入篮／入油 | 油条轻微落稳，接触油面时出现一小簇气泡 | 炸锅、篮框基本不变形   |
| 炸制中      | 气泡局部冒出，油条颜色随真实熟度变化  | 托盘与设备位置不晃动   |
| 提篮       | 篮子沿固定路径升起，到位后迅速停住   | 不做弹簧式上下反复运动  |
| 沥油       | 少量油滴向下，油声逐渐减弱       | 不增加额外的手动抖篮步骤 |
| 放入备餐位置   | 油条短距离落稳，彼此保持清楚间隔    | 不让整盘油条一起弹    |

**“炸好了”的反馈必须对应真实成熟状态。**不能因为颜色渐变动画先播完，就提前出现可取走的表现。

设备升级继续沿用你已经确定的6根／8根容量及自动升起规则。自动升起后，播放的还是同一套提篮、沥油表现，只是触发来源改为设备逻辑，不需要重新要求玩家操作。

### 豆浆只做轻量配合

豆浆保持成品饮品。

拿起时略微抬高，放下时有轻微落稳即可；杯身不明显压扁、不持续摇晃、不新增制作环节。它的节奏应当比煎饼与油条更短，承担快速配餐的作用。

# 三、武汉热干面：重点不是“面在转”，而是“筷子真的带得动面”

**这是我建议本轮投入最多打磨精力的动作。**

你现有的武汉素材已经包含熟面基础层、未拌匀酱料层、半拌匀状态和完全拌匀状态；原方案也明确用`MixProgress`控制状态切换或渐变，并让筷子由程序跟随鼠标。这里可以继续沿用，不需要重新生成几十张拌面动画帧。 

## 1. 生面入锅与提面：软的是面条，不是漏勺

生面被拿起时，可以略微拉长；进入烫面位置后，面团轻轻聚拢。

漏勺、提篮则保持刚性。动态漏勺应该是独立层，不要重新画死在背景锅里。

提面时可以做一个很小的错位：

**漏勺先到位，里面的面条稍晚落稳。**

这样能产生柔软内容物被托起来的感觉，同时不影响工具跟手。

沥水继续使用已有流程。水滴是过程的表现，不增加必须完成的抖动次数，也不因为水滴还没播完而延迟原本允许的倒面操作。

---

## 2. 倒入碗里：把“一份面落进去”的体积感做出来

不要简单地让漏勺里的面消失、碗里出现一张完整面条图。

建议：

**前端面条先进入碗 → 主体跟进 → 面团在碗内稍微摊开 → 回收到正常形状。**

视觉上可以把一份面拆成两三组错峰落下，但它们仍然代表同一份食物。

这一段允许比天津薄脆明显一些的形变：面团落下时略微压扁，再轻轻聚拢。

**碗本身基本不动。**否则玩家看到的会是“碗在弹”，而不是“面条很柔软”。

声音可以是一声轻柔的落面声，接很弱的碗内接触声，不需要夸张的液体飞溅。

---

## 3. 芝麻酱与小料：突出“酱留在面上”

芝麻酱不要表现得像水一样在碗里绕着流。

我建议：

一小团酱落在面上，向周围扩展成两三块简洁的酱料区域，然后停住，等待后面的拌面动作把它分散。

这也与现有素材中“局部、大块、非真实液体”的表现方向一致。

葱花可以复用天津的错峰落料组件，但落点限制在碗内。

辣酱／辣油采用更短、更薄的铺展；牛肉采用块状落料，轻压一下后停住。**不要让这些配料都围绕碗旋转一圈再落下。**

已有的原味、葱花、辣味、牛肉等配方判定保持不变，动效只表现本次实际加入的内容。

---

## 4. 拌面：同时控制“工具、局部面条、整体状态”

这三个层次分开，才容易调出舒服的感觉。

### 第一层：筷子立即跟手

玩家左右划，筷子就左右移动；画小圈，筷子就沿小圈运动。

不强迫玩家必须顺时针，不要求画标准圆，也不把每次移动都解释成“播放一次转圈”。

**筷子的接触点要跟手，允许稍有滞后的只是面条。**

### 第二层：局部面条被牵动

筷子附近的两三簇粗弯面条，可以沿移动方向偏移约2～6像素，伴随小幅倾斜或拉长。

较远的面条动得更少。玩家停手后，局部面条快速回到稳定位置。

这比让整张面条贴图绕碗心匀速旋转，更接近我们希望表达的“正在拌”。

也不用模拟几十根真实面条。**两三簇可牵动的粗弯条，加上下面的主体层，就值得先做原型。**

### 第三层：拌匀程度读取真实进度

颜色与状态继续由`MixProgress`决定：

**酱集中在局部 → 部分面条变为酱色 → 整体均匀。**

不要启动一个固定时长的渐变后就不再管玩家输入。否则玩家停手，面还会自己慢慢变成拌匀状态。

葱花、牛肉等订单配料应保持独立层。切换面条状态时，不能把已经加进去的小料一起替换掉。

### 完成时：面条归拢，不是整碗蹦起来

建议在拌匀成立时，让局部面条归位，主体稍微聚拢，配一声短促收尾。

随后进入已有的可交付状态。**拌面与拖碗交付继续分开，不把松手自动解释成出餐。**

---

## 5. 武汉拌面最需要检查的三个错误

**错误一：只有筷子动，食物没有反应。**
补局部面条的牵动与酱料分散，而不是把筷子摆幅继续放大。

**错误二：鼠标已经停了，画面还继续拌。**
需要明确区分“正在运动”和“已经停手”。Godot的鼠标移动事件并不保证在停手时再发送一条零位移事件，因此不能仅靠等待下一条事件来结束拌面表现。([Godot Engine documentation][1])

**错误三：面条运动后超出碗口。**
面条与配料应裁剪在碗内部，并由前碗沿遮挡。不要通过缩小整碗来掩盖溢出。

---

# 四、武汉三鲜豆皮：最重要的是“动作过程可见，但操作不加码”

这里继续保留你此前的流程：

**倒浆 → 加蛋 → 定型 → 向上划翻面 → 加三鲜糯米馅 → 成熟 → 横竖各划一次切八块 → 自动入盘 → 批量交付。**

Lv3自动翻面、第一刀后锁品质、每锅八块与备餐盘容量规则，都不因为动效重做而改变。

## 1. 倒浆与加蛋：同样铺展，但不能像天津圆饼

技术上可以复用天津的倒料与覆盖层组件，但豆皮的铺展终点应服从锅面和现有豆皮轮廓。

建议先在落料处形成一小块，再向已有形状铺开，最后边缘收整。

加蛋时让黄色覆盖层迅速形成，不需要反复晃锅，也不增加搅蛋操作。

**单击加料仍然是单击。**即便当前原料由锅面点击推进，也可以通过相应勺子、原料来源和落料方向增强联系；是否改成“先选择原料”属于另一项交互调整，不应悄悄混进这一轮。

---

## 2. 翻面前：让铲子与饼边响应上划

目前最值得增强的，不只是翻面完成动画，而是**达到翻面判定之前的那一点响应**。

建议玩家开始向上划时：

铲子逐渐进入托起姿态，豆皮靠近铲子的一边轻微抬高。

达到现有有效手势条件后，才完成整片翻面；没有达到条件就松手，则轻轻放回原位。

这样会从：

> 划一下 → 播放动画。

变为：

> 我在向上托 → 它被我带起来 → 翻过去了。

**不增加力度、速度或Perfect判定。**这里只让已有手势在确认前有可见的预备动作。

---

## 3. 整片翻面：比天津更平整、更收敛

建议采用：

**托起 → 整片离锅 → 经过薄侧面 → 换面 → 落锅。**

与天津的区别主要在于：豆皮整片轮廓更完整，落锅后迅速稳定，避免大幅波浪和持续弹性。

可以共用一套翻面表现组件，但使用不同参数。天津略轻快，豆皮略有分量；两者都只移动食物与工具，不让锅身跟着压缩。

**翻面时锅面上的阴影可以与食物分离一点。**这一点很有价值：食物升起时，阴影仍留在锅面，能加强离锅感，而不需要把飞行高度拉得很夸张。

Lv3自动翻面时直接播放同一套托起、换面、落锅动作，不再需要玩家提供上划预备过程。

---

## 4. 铺三鲜糯米馅：有“厚度”，但不增加涂抹任务

建议表现为：

**一份复合馅料落下 → 中间稍微堆起 → 工具短距离推平 → 形成已有糯米馅状态。**

三鲜糯米馅仍然作为一份复合配料，不拆成玩家需要分别添加的多个小料。

这里可以让馅料的局部比外皮更软一些：落下时稍压、堆起的部分缓慢贴平，但豆皮外围保持稳定。

**不建议本轮把它改成长按铺馅或覆盖率小游戏。**一次点击足以触发短暂的推平表现，先把现有步骤做好看。

后续成熟颜色和状态继续读取真实烹饪进度，不由这段铺馅动画自行决定。

---

## 5. 切块：让刀痕跟着手势出现，最后八块分开

这是豆皮第二个重点动作。

### 手势进行中就要有反应

玩家开始划刀时，刀具进入切割姿态，刀痕随手势向前延伸。

不要等整个方向判定结束以后，才突然显示完整网格。那样玩家仍然只是在触发一张状态图片。

刀痕可以吸附到预定切割线，继续使用宽松的方向识别，**不要求精准描线**。

### 横竖两次手势如何对应八块？

按照2×4的八块布局，我建议把它明确表现为“批量切割手势”：

**横向手势对应一条横切线；纵向手势对应三条纵切线。**

纵向手势成立时，另外两条平行刀线以很短的错峰补出，让玩家看到“一次操作完成这一组切割”，而不是要求重新划三次。

这样既解释了八块的形成，又保留你已经简化的两次操作。

**不能在这一轮重新变成四次独立划刀。**

### 切完才分块

最后一次有效切割成立后，各块沿切缝分开约2～4像素，再轻轻落定。

不要向四周弹飞，不要掉出锅面，不要让切缝宽得像已经被拿走了一块。

声音可以在有效切割时给出短促、偏利落的切声；一组补出的平行切线不必每条都响一声，否则容易像连续敲击。

### 保留第一刀锁品质的时点

品质锁定应发生在现有规则认可第一刀的时刻，而不是等待第一条刀痕动画播放结束。

否则视觉润色会无意中改变火候难度。

---

## 6. 自动入盘与批量交付：表现“这一锅备好了”

建议入盘使用短路径，八块可以分成两组稍微错开到位，但整体快速结束，不要八块轮流飞行、逐个等待。

已经在备餐盘里的旧豆皮保持不动。新一锅入盘时，只让新增的那些块落稳。

备餐盘满时继续执行已有处理规则，不能为了让动画播完自动清空旧食物，也不能暗中改变部分入盘规则。

批量交付时同样如此：

**本次实际交付多少，就只让对应数量进入交付表现。**

不要把整盘十六块一起压缩，也不要因为表现分成多个小组，就重复扣库存或重复结算。

# 五、建议先试的关键动作参数

这些参数用于首版调试。已有动作阶段比表中更短时，应缩短表现或与收尾重叠，而不是延长经营流程。

| 动作          |      建议表现时长 | 建议形变／位移           | 主观方向        |
| ----------- | ----------: | ----------------- | ----------- |
| 天津面糊接触并初步铺开 |  0.16～0.24秒 | 下落时拉长，接触后铺展       | 柔软，但不反弹     |
| 天津薄脆落稳      |  0.10～0.16秒 | 极小位移，基本不形变        | 轻、脆、快       |
| 天津火腿落稳      |  0.14～0.20秒 | 约3%～5%轻压缩         | 比薄脆柔软       |
| 天津煎饼翻面      |  0.26～0.36秒 | 离炉约14～24像素；落锅轻压   | 轻快、薄片感      |
| 天津折叠并衔接装袋   | 约0.40～0.55秒 | 饼皮收合；袋身约4%～7%撑开   | 连贯，不连续弹跳    |
| 武汉面条入碗      |  0.20～0.30秒 | 内容物约4%～7%形变       | 柔软、聚拢       |
| 武汉拌面过程      |     随输入持续变化 | 局部约2～6像素牵动        | 工具跟手，面条略有余韵 |
| 武汉拌面完成收尾    |  0.15～0.22秒 | 小幅归拢              | 迅速落定        |
| 武汉豆皮确认后的翻面  |  0.30～0.42秒 | 整片小幅离锅，落锅形变约2%～3% | 平整、有分量      |
| 武汉豆皮切开分离    |  0.10～0.18秒 | 切缝分开约2～4像素        | 利落、可读       |
| 武汉豆皮自动入盘    |  0.20～0.30秒 | 短路径、少量错峰          | 一锅完成的满足感    |

**摊饼与拌面不设“固定播放时长”。**它们的主体应由操作驱动，只有完成后的收尾才适合用固定时长。

# 六、Godot实现上，建议拆成“输入、状态、收尾”三种驱动

不要把所有动作都堆到一个越来越大的`JellyVisual`组件里。

## 1. 三种驱动，各自管理自己的部分

| 驱动来源       | 负责内容               | 天津例子       | 武汉例子                  |
| ---------- | ------------------ | ---------- | --------------------- |
| 玩家输入       | 工具位置、动作预备姿态、局部食物牵动 | 刮板跟手       | 筷子跟手、上划托起预览           |
| 制作状态与进度    | 食材层、熟度、混合程度、切割状态   | 饼面覆盖、成熟颜色  | `MixProgress`、豆皮成熟与切块 |
| Tween／固定动画 | 已确认动作的移动与短暂收尾      | 落料、翻面、装袋回弹 | 入碗、落锅、分块入盘            |

Tween适合动态目标和短属性变化；折叠、装袋这类多节点配合且时序固定的片段，可以交给`AnimationPlayer`编排。Godot官方也将两者分别定位于动态插值和更复杂的动画时序。([Godot Engine documentation][2])

**不要每收到一次鼠标移动，就重新创建一个“筷子移到鼠标”的长Tween。**持续跟手部分直接更新目标姿态，停手后的归位再交给短Tween。

## 2. 热干面优先采用这样的视觉分层

```text
NoodleBowlRoot
├── HitArea                    固定交互范围
├── BowlBack                   碗的后部
├── InnerFoodMask              碗内有效显示区域
│   └── FoodMotionRoot         只移动内容物
│       ├── NoodleState        未拌匀／半拌匀／拌匀
│       ├── LocalNoodleStrips  可被筷子牵动的局部面条
│       └── Toppings          已添加的订单配料
├── BowlFrontRim               前碗沿遮挡
└── ChopsticksRoot             跟手工具
```

这里的遮罩应该是**碗内部可容纳食物的区域**，而不是整个碗PNG的轮廓。

Godot的`CanvasItem.clip_children`可以根据父节点绘制区域的透明度裁剪子节点。使用时注意其限制：裁剪节点不能嵌套，也不应放在`CanvasGroup`内部。([Godot Engine documentation][3])

天津炉面、豆皮锅内的落料范围也可以沿用这个思路，但分别使用自己的形状。

## 3. 输入坐标与表现坐标必须统一

摊饼、拌面和划刀，都建议先把输入转换到对应工作区域的局部坐标，再计算路径、距离和姿态。Godot提供输入到局部画布坐标的转换方式；不要把物理屏幕像素与场景局部坐标混在一起。([Godot Engine documentation][4])

验收时要特别比较不同窗口尺寸下，同样的相对划动是否得到相近反馈。

## 4. 同一属性只由一个动画来源控制

比如筷子根节点的位置由输入负责，筷子装饰层的轻微倾斜由表现组件负责。

不要让输入代码、Tween和`AnimationPlayer`同时修改同一个节点的同一个`Scale`或`Position`。Godot官方明确提醒应避免多个Tween竞争同一属性；重播应创建新的Tween，而不是复用已结束实例。([Godot Engine documentation][2])

使用Shader控制拌匀进度时，也要避免几碗面共用同一个可变参数。修改共享`ShaderMaterial`会影响所有使用它的实例，应使用适当的实例参数或独立材质资源。([Godot Engine documentation][5])

## 5. 快速操作和中断，要比“完整播完”优先

建议每个表现都知道自己属于哪一份食物、哪一次动作。

玩家开始折叠时，归拢这份煎饼尚未结束的落料表现；食物被丢弃时，清理它的残留特效；玩家拿起已入盘食物时，及时结束它的装饰性落稳动作。

**动画可以被打断，库存、配方和品质不能因此被重复处理。**

# 七、这轮美术优先补“能动的局部”，不再大量增加完整成品图

建议先检查现有PNG能否拆分，再决定补绘：

| 内容          | 优先处理方式         | 确实缺少时再补       |
| ----------- | -------------- | ------------- |
| 天津倒面糊／蛋液／刷酱 | 复用现有工具、基础层和覆盖层 | 简洁落料形状、短刷痕    |
| 天津翻面        | 复用已有正反面／制作状态   | 极简侧面过渡姿态      |
| 天津折叠        | 复用展开与折叠成品      | 与现有成品对齐的半折叠状态 |
| 天津装袋        | 先用现有整份素材验证     | 可独立运动的袋口或袋身分层 |
| 武汉拌面        | 继续使用已有三阶段状态    | 两三簇粗弯面条牵动层    |
| 武汉碗内遮挡      | 从现有碗素材拆分       | 前碗沿、碗内遮罩      |
| 武汉豆皮翻切      | 复用已有整片与八块状态    | 侧面、可独立移动的单块豆皮 |
| 两城共用辅助效果    | 复用已有蒸汽与简洁特效    | 少量水滴、油滴、接触阴影  |

**“八块状态图”与“八块能够分别移动”是两件事。**现有图片里各块边界清楚，就可以尝试拆分；否则需要补单块素材。仅仅对一张整体八块PNG做缩放，无法得到真正的错峰入盘。

同理，完整的热干面状态图能解决“拌匀程度”，但不能独自解决“筷子带动局部面条”。这一轮新增素材应该优先弥补这种运动能力，而不是再增加一张更漂亮的静态成品。

# 八、我建议的实际制作顺序

**先验证两项连续操作：天津摊饼、武汉拌面。**这两项决定玩家是否真的觉得跟手。先不加大量蒸汽、星点和完成特效，单看工具与食物的联系是否成立。

**然后打磨两项动作收尾：天津折叠装袋、武汉豆皮翻切。**重点检查中间姿态、接触时刻和声音同步，保留既有操作次数。

**最后补齐连接动作：倒料、投料、提篮、入碗、自动入盘。**这些动作应服务主流程，不与主动作争抢注意力。

验收不只看录屏好不好看，还要实际连续操作。至少检查：停手后制作是否停止推进；快速加料再折叠是否有残留；自动翻面是否仍然自动；切块动画是否改变品质锁定时间；满盘和批量交付是否保持正确数量；暂停、丢弃和关店后是否留下悬空工具或特效。

**这一轮完成后的理想效果是：即使隐藏城市标题，只看玩家怎么制作，也能分辨两个章节。**

天津让玩家感受到：**“我把饼摊开，把配料包成了一份早餐。”**

武汉让玩家感受到：**“我把面拌匀，又把一整锅豆皮切成了可交付的八块。”**

果冻感只负责让这些动作更柔软、更舒服；真正让两城有区别的，是**食物如何响应玩家的手。**
