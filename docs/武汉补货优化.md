# 武汉补货优化

2026-09-10，按用户确认实施：保留生面手动补货与豆皮批量备餐，取消小料及蛋酒的库存管理。

## 当前规则

| 对象 | 规则 |
|---|---|
| 生面条 | Lv1／Lv2／Lv3 容量为 8／10／12，每局满库存；免费补货，约 1 秒后补满 |
| 面条补货中 | 剩余生面仍能拖入漏勺；归零才阻止下锅，不影响其他工作；重复补货不重启计时 |
| 低库存提示 | 剩余不超过 2 份时显露补货入口；正常库存悬停显露；满库存按钮禁用 |
| 基础调味、葱花、辣油、卤牛肉 | 持续供应，无库存数字或补货入口；配方、加料顺序、重复加料限制与已加标记保留 |
| 豆米浆、三鲜糯米馅 | 保留制作动作，不新增原料库存 |
| 豆皮成品 | 每锅 8 块，备餐盘最多 16 块；盘满留锅，卖出腾位后自动入盘 |
| 豆皮备货提示 | 当前同屏订单尚缺数量大于盘中数量、且锅空闲时显示“订单缺豆皮，做一锅”；开锅后显示“制作中”，待入盘和焦糊分别提示处理动作 |
| 蛋酒 | 沿用 Day 6 解锁与原存档键，解锁后持续供应；有效拖拽每次交付一杯，不设补货按钮、缺货或等待 |
| 蛋酒展示 | 展示三杯，拖取暂留两杯，成功交付后补位；补位动画不锁定下一次交付 |
| 暂停与失焦 | 面条补货、制作与补位动画冻结，禁用交付；减少动态模式只缩短动画，不缩短补货逻辑计时 |

需求只统计同屏正在入场或等待服务的顾客，各豆皮订单行减去已交付数量后求和。离场及已完成顾客不触发缺货提醒。没有订单缺口时不催促备货。

## 升级与兼容

- 备料台升级只增加生面容量；界面使用生面图标，按钮说明目标容量，悬停显示升级前后容量。
- 价格暂保留 Lv2 ¥120、Lv3 ¥300，待真人试玩评估，不凭静态分析调整经济数值。
- 删除小料的旧容量配置和蛋酒库存运行时，不使用极大数模拟无限库存。
- 日配置、订单、商品价格、存档升级键及城市通用机制不变：同屏上限 5 名、正确部分交付恢复 15% 耐心、完成顾客满意度统计、小费舍入与点击收钱继续沿用共享逻辑。
