# 天津工作台：订单纸、挂签与经营动态

2026-09-15，按本次已确认方案实施。

## 实施结果

- 天津订单显式使用暖纸样式：306 设计单位宽、2 px 暖棕线、6 px 耐心条；数量文字保持深棕。原运行时实际宽度为 304，场景声明 332，本轮统一到确认的 306，压缩的是纸面留白。复杂订单仍可增高，主食、配料、副食分数和独立变绿规则保留。
- 顾客订单底部锚点和交付区不变。正确完成后独立纸面副本盖小勾／Perfect 星章，0.35 秒后淡出；原纸收起，替代天津爱心和散落星星。副本最多 5 张，释放与顾客队列无关。
- HUD 只对天津挂签底板应用暖纸材质；没有降低文字透明度。真实入账立即刷新金额，最后一枚飞币抵达触发一次挂件晃动及数字强调；连发替换当前晃动，不排队累积。
- 原三阶段背景各生成局部干净底图，挂件、刮板、铲子独立。刮板仅在有效划动时拿起并保留比例，铲子成功翻面时短暂移向饼炉后归位。
- 油锅已有气泡减轻并加局部波纹；摊饼边缘舒展不超过 1%，松手约 0.2 秒收稳；每面首次成熟出现一次低透明度蒸汽。
- 豆浆拖动使用视觉预留，拿起少显示一杯，取消恢复；库存只在成功交付时扣减，避免重复显示或重复扣除。
- 暂停、明细、失焦、离开和切换减弱动态时清理对应瞬时效果；恢复不补播。减弱动态保留静态完成反馈与真实数字变化。没有新增音效、经营规则或存档字段。

### 性能观察

同一五顾客夹具，在素材与明细预热后分别采样 60 帧。普通视口记录：1080p 减弱动态／正常动态约 16.708／16.763 ms，720p 约 16.721／16.883 ms，两组节点数均为 600。完成副本压力测试后节点回到基线。

该数据是 Godot `TimeProcess` 监视值，受帧率限制和后台窗口影响，不等于纯 CPU 或 GPU 渲染耗时，也不是最低配置性能承诺。录屏模式有额外编码开销，单独记录，不混入普通视口比较。

### 环境信息

使用 `D:/Godot/GodotSharp/Godot_v4.7.1-stable_mono_win64_console.exe`、GL Compatibility。环境仍输出根证书存储读取错误；无头测试另有已有 `FoodInk` shader compiler 的 sampler 提示，实际图形视口未出现该提示。本次测试断言通过，这些环境输出保留在日志中。

## 复现

从项目根目录执行，APPDATA 和日志使用独立可写路径：

```powershell
$env:APPDATA = Join-Path (Get-Location) '.tmp/tianjin-living/repro-profile'
dotnet build --no-restore
& 'D:/Godot/GodotSharp/Godot_v4.7.1-stable_mono_win64_console.exe' --headless --path . --log-file (Join-Path (Get-Location) '.tmp/tianjin-living/repro.log') res://Scenes/Tests/TianjinLivingWorkbenchSelfTest.tscn
```

实际画面：去掉 `--headless` 并添加 `-- --capture`，通过 `Start-Process -WindowStyle Hidden` 启动。录屏可加 `--fixed-fps 60 --write-movie .tmp/tianjin-living/repro.avi`，用户参数为 `-- --living-film --capture`。素材复现使用已记录的生成稿和 `tools/prepare_tianjin_living_art.ps1`。
