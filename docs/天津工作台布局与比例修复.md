# 天津工作台布局与比例修复

日期：2026-09-07。依据当前主工作台截图、实施方案及用户再次确认的“三列两排，优先让大小协调、桌面饱满”调整。

第三轮正在修正盘内密度与信息归属：右侧调整已完成，设备向桌前平移约 50 设计像素的提议等待用户确认，尚未执行，左下、中下留白尚未完成最终处理。

## 最终行为

- 保留店铺画风、顾客柜台基线、三级炉子及炸锅显示尺寸、炉面划动和炸篮投放几何。
- 天津营业页面启用 `PancakeWorkstation.UseServingTray`，该选项必须在节点加入场景树前配置；默认关闭以保留实验台等旧场景。
- 配料改为三列两排：左列面糊／酱料，中列薄脆／火腿，右列鸡蛋／香葱。未解锁食材隐藏后保留空位。
- 面糊、薄脆、火腿拖入；鸡蛋、香葱点击；摊面和抹酱保持原划动规则。槽位显示对应操作提示，并按步骤、库存和补货状态高亮。
- 豆浆杯显示框为 102×110，袋装煎饼为 158×116；碗使用 228×136 专用框，食材托盘使用 280×128 框，均等比适配。盘内食材区域由 180×66 增至 232×96，补货按钮移至食材下方的右侧，名称、操作提示和数量收拢在器物底部。生油条盘为 240×128，熟油条架为 240×142。油条、成品及豆浆的拖拽显示同步调整。
- 成品和豆浆托盘按单份食物收紧，垃圾桶降为次要视觉层级；成品取用热区覆盖袋子高于托盘的部分，提示位于袋子右侧，并处理了顾客与成品的显示层级。
- 装袋后使用 0.22 秒移动表现进入炉边固定托盘，期间不能取餐。动画由工作台 Tick 推进，与营业一同暂停；减少动态效果时立即到位。转移与到位阶段不在炉面重复显示成品。
- 成品托盘一直保留；装袋成品存在时隐藏空托盘文字，避免成品遮挡标签。交付或丢弃后才能制作下一张，不新增成品容量。
- 成品、熟油条和豆浆直接拖给顾客，保持唯一 ID 绑定、提交时复查、无效投放回弹和取消输入规则。
- 订单卡分为状态、商品、配料、耐心条四层，数量放在商品名称下方，配料可换行。耐心条独立零内边距样式，设计高度 8。
- 短时反馈显示在 HUD 下方，忽略鼠标输入，不覆盖顾客交付区域。

此文更新《天津工作台交互优化方案》中“成品、豆浆和垃圾桶位置保留”的旧布局结论；制作分工和交付规则继续有效。

## 复现

从项目根目录运行；截图场景使用临时测试存档，默认输出到 `.godot`。

```powershell
dotnet build --no-restore
$env:APPDATA = Join-Path (Get-Location) '.godot/enlarged-userdata'
New-Item -ItemType Directory -Path $env:APPDATA -Force | Out-Null
& "D:\Godot\GodotSharp\Godot_v4.7.1-stable_mono_win64_console.exe" --headless --path . --log-file .godot/stage4.log res://Scenes/Tests/StageFourSelfTest.tscn

# GUI 捕获须使用 Hidden 启动，场景完成后自行退出。
$captureProcess = Start-Process -FilePath "D:\Godot\GodotSharp\Godot_v4.7.1-stable_mono_win64_console.exe" -ArgumentList '--path . --log-file .godot/capture.log res://Scenes/Tests/VisualCapture.tscn -- --capture-day11 --capture-bagged' -WindowStyle Hidden -PassThru
$captureProcess.WaitForExit()
```

可组合参数：`--capture-720`、`--capture-bagged`、`--capture-refilling`、`--capture-low-stock`、`--capture-partial-order`、`--capture-pause`、`--capture-workbench-level=2`（或 3）；使用 `--capture-output=绝对路径` 指定输出文件。

视觉验收采用 Godot 实际渲染的 Day 11 五顾客截图，覆盖 1080p、720p、装袋、补货、低库存、部分交付、暂停和三级设备。鼠标流程通过 Godot 输入事件测试；尚未进行由玩家主导的连续营业手感评测。
