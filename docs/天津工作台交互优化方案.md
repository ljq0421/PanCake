# 天津工作台交互优化方案

依据：2026-09-07《分析操作交互优化》讨论、用户修正及当前工作区实现。

## 目标与决策

保留“点击操作设备与撒料、拖拽移动实物、划动加工食物”的操作分工，减少前置状态和精准瞄准负担，不改配方、火候、库存容量、经济及耐心数值。

| 项目 | 决策与落实 |
| --- | --- |
| 出餐前选顾客 | 改为直接把装袋煎饼、熟油条、豆浆拖给顾客。松手位置决定对象，无默认目标、无点击选中。 |
| 顾客接餐区域 | 订单和人物整块区域可接餐；原有高亮、吸附、回弹复用。顾客之间只增加 5px 容错，避免跨人误投。 |
| 原出餐口 | 天津营业界面隐藏该投放入口，原位置显示“成品拖给顾客”。成品、豆浆和垃圾桶位置保留。 |
| 摊面 | 判定、时长、轨迹表现全部保留。 |
| 酱料 | 用户确认保持当前工作区实现。本版本酱罐只展示库存，在炉面划动开始抹酱；不新增点击酱罐门槛。 |
| 摊面与抹酱手感 | 现有两套轨迹和工具表现保留；暂不采用讨论中未经试玩验证的时长建议。 |
| 鸡蛋、香葱、薄脆、火腿 | 维持鸡蛋和香葱点击、薄脆和火腿拖入；已有落料反馈保留。 |
| 炉边与炸锅按钮 | 当前已按互斥状态在同一操作区显示，保留现有上下文按钮，不重复改造。清理文字明确为“清理炉面”“清理炸锅”。 |
| 垃圾处理 | 可移动的装袋煎饼、库存油条拖入垃圾桶；焦糊批次在对应设备清理。去掉点击垃圾桶自动挑选焦糊设备的行为。 |
| 投放容错 | 炉面向外扩展 24px、炸篮 18px、垃圾桶 8px。实际目标区域优先于相邻容错区，保持吸附到现有预设点。 |
| 补货 | 小料补货按钮由 66×52 扩为 66×56，豆浆由 58×48 扩为 66×56。保留低库存提示、补货进度、满库存隐藏和防重复点击。 |
| 暂停与取消 | 保留 Esc 取消、失焦取消拖拽和暂停时冻结工作台。 |

## 出餐规则

- 顾客正在等待，且订单仍缺少该类商品时，接餐区可用。进入中、离开中、已完成、数量已足够或原料投放均不接收。
- 高亮表示能够接收该类商品，不承诺配方或火候完全正确。错误配方仍按现有规则接收并评分，保留读单与制作的决策。
- 多件订单逐件累计。成功交付后只扣除对应商品，订单未齐时顾客继续等待。
- 交付绑定顾客唯一 ID；吸附结束再次检查状态和绑定版本。顾客离开或槽位换人时，物品回弹，不消耗库存，也不转交其他人。
- 不再根据选中顾客高亮其配料；保留配方小图、阶段可操作提示与库存提示。
- 共用订单控制器保留旧选择式接口供武汉和开发场景使用；天津营业页面使用显式顾客 ID 交付。

## 验证

自动验证覆盖：天津 15 天直接交付完整闭环；真实拖拽给非首位顾客；无效顾客不扣煎饼、豆浆、油条；吸附途中离开与换人；Esc 与失焦取消；扩展命中与相邻目标优先级。界面以五顾客状态检查 1920×1080 和 1280×720。

验收重点：连续出餐无需点人、无旧出餐目标提示；相邻订单之间无误投；清理两台设备可分别操作；补货与取料热区不重叠；摊面与酱料操作保持原样。

验证结果：`dotnet build` 成功，0 警告、0 错误；StageFour 1556 项、StageTwo 136 项、StageThree 116 项、Wuhan 30 项全部通过，共 1838 项。五顾客直接交付画面已检查 1080p 与 720p，截图位于 `.godot/direct_delivery.png` 和 `.godot/direct_delivery_720.png`。鼠标实际舒适度仍需连续营业试玩评价。
