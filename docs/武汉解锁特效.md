我建议把天津 Day7 做成一次**“早餐旅程真正展开”的里程碑**，而不只是弹出一条“恭喜解锁武汉”。

最适合你现有美术和页面体系的方案是：

> **天津营业小结 → 手记中出现新旅程提示 → 地图连线、武汉点亮 → 武汉明信片展开 → 玩家选择出发 → 武汉第1天。**

其中，**今日收入仍然是当天结算的高潮，武汉解锁则负责制造“接下来还有新东西可玩”的期待。两者不要同时出现。**

下面按“武汉解锁后，天津仍保留后续经营与已有进度”来设计。因此，这里不盖“天津通关”章，而是表现“新的目的地开放”。

---

## 一、Day7营业结束：先完整结算，再引出武汉

### 1. 不在工作台收摊瞬间弹出解锁窗口

最后一位顾客离开、当天营业结束时，正常进入营业小结。

保留你已经确认的顺序：

**今日接待 → 顾客评价 → 最受欢迎、今日亮点 → 收入揭晓 → 营业手记。**

不要在金币还在跳动时，同时出现“武汉解锁”“新菜品”“新顾客”等提示。那样会让收入和解锁争夺注意力。

### 2. 把“营业手记”变成连接下一章的入口

Day7的手记可以使用专属文案，例如：

> **在天津忙碌了七天，早餐旅程有了新的方向。**

手记出现后，稍停约 **0.3秒**，从书页右侧伸出一小截浅青绿色纸签。纸签上带一个小小的热干面图标，文字明确写：

> **新城市已解锁 · 武汉**

纸签只轻弹一次，然后安静停留。不要反复闪烁，也不要盖住收入数字。

页面底部的按钮，在本次结算中调整为：

| 位置  | 按钮        | 作用               |
| --- | --------- | ---------------- |
| 主按钮 | **展开新旅程** | 进入武汉解锁演出         |
| 次按钮 | **留在天津**  | 返回天津经营手账，继续原来的经营 |

**不要看完手记就自动跳走。** 玩家可能还想看今日收入、评价和明细，应由他主动点击“展开新旅程”。

另外，按钮应从出现时就使用上述文案，不要先显示“继续营业”，等玩家准备点击时突然换成“展开新旅程”。

---

## 二、点击“展开新旅程”：播放约4～5秒的地图解锁演出

建议将**额外自动演出控制在约4.4秒**，不包含前面的营业小结，也不包含玩家阅读明信片的时间。

这段演出的重点不是展示很多特效，而是让玩家看懂：

**我从天津出发了 → 地图扩大了 → 武汉可以去了 → 那里有新的早餐玩法。**

### 推荐分镜

以下时间可作为第一版调参起点。

| 时间             | 画面与动效                                   | 声音与重点               |
| -------------- | --------------------------------------- | ------------------- |
| **0.00～0.60秒** | 一张奶油色纸页从右向左擦过，营业账本退场，世界地图显露；视野直接容纳天津与武汉 | 一声轻柔翻纸声，不经过首页       |
| **0.60～1.70秒** | 天津节点轻亮一下，旅行虚线从天津逐段延伸至武汉                 | 很轻的路线描绘声；视线沿路线移动    |
| **1.70～2.30秒** | 武汉节点从未解锁状态变为浅青绿色，热干面图标弹出，周围闪两三颗小星星      | 一次短促、明亮的解锁音，这是主要强调点 |
| **2.30～2.90秒** | 武汉明信片从节点附近向前展开，落到画面中央略偏右的位置             | 纸片展开声               |
| **2.90～3.80秒** | “下一站，武汉”出现；热干面主图轻弹落位，升起少量蒸汽；本章特色说明淡入    | 音乐开始带出武汉章节氛围        |
| **3.80～4.40秒** | 武汉旅行邮戳轻落，出发按钮和保留进度说明出现                  | 轻轻一声落纸音，随后进入静止阅读状态  |

**到这里必须停住，等待玩家选择。**

不要继续自动播“坐车旅行”“到达武汉”“新店开张”“教学介绍”等一串动画。第一次跨城应有仪式感，但不应该变成一段很长的强制观看流程。

### 地图还有一个重要细节

天津保持原本的暖金色，不变灰、不关闭，也不额外盖上“全部完成”。

武汉从灰色节点变为浅青绿色节点，表示的是：

> **已解锁，可以前往。**

而不是：

> 已完成武汉，或已收集武汉全部早餐。

“城市开放”和“城市完成”应使用不同的视觉状态。

## 三、果冻感放在哪里：节点和食物可爱，地图与文字保持稳定

这次可以加入你希望的果冻感，但不建议整张地图、整本手账都一起弹。

### 武汉节点：最明显的一次弹性反馈

节点出现时，可以使用一段约 **0.4秒** 的缩放：

**0.86 → 1.12 → 0.98 → 1.00**

看起来像一枚新的早餐贴纸“啪”地贴到了地图上。

节点落稳后，只保留一次小光环向外扩散。不要持续强烈呼吸，否则会干扰后面的明信片阅读。

### 明信片：纸张的轻巧，不是橡皮的软塌

明信片从较小状态展开时，建议：

**缩放0.93 → 1.02 → 1.00，倾斜约－3° → 0°。**

整体稍微向上移动，再轻轻落定。正文开始出现时，明信片应基本稳定，避免文字在晃动过程中让玩家阅读。

### 热干面：比城市标题更值得“动起来”

热干面图可以有一次约 **5%** 的轻弹，随后两小缕蒸汽缓慢上升、淡出。

这样，玩家看到的不只是“武汉”两个字，而是**一碗即将亲手制作的新早餐**。

标题与说明文字只做短距离位移和透明度变化，不做挤压变形。

### 镜头：尽量克制

不建议全屏震动、长距离追踪镜头或大幅旋转地图。第一版甚至可以固定地图视野，只让路线、节点和明信片运动。

**主要的动感集中在“武汉点亮”的瞬间，其余动作都为这个瞬间服务。**

---

## 四、武汉明信片：既宣布解锁，也告诉玩家“为什么值得过去”

这一页不要做成常规系统对话框，也不要只是：

“武汉已解锁。确定。”

建议以**世界地图为背景，武汉明信片为主体**。明信片展开后，背景仍能看见一部分天津到武汉的路线。

### 推荐内容

**小标题**

> 新城市已解锁

**主标题**

> **下一站，武汉**

**主视觉**

一碗热干面作为大图，三鲜豆皮作为较小的章节特色贴纸。保留空白，不必同时展示整张工作台、所有设备和一排顾客。

**核心文案**

> **从摊煎饼，到拌一碗热干面。**

这句话比“解锁全新章节，开启更多挑战”更具体，也能直接表达玩法变化。

**特色说明**

> 本章特色：热干面 · 三鲜豆皮

这里建议写“本章特色”，而不是把两道食物都写成“立即获得”。具体哪道菜首日可用、哪道菜后续开放，应与武汉的实际日程配置一致。

**底部按钮**

> **前往武汉**　　留在天津

**按钮下方的小字**

> 天津的营业进度与设备升级都会保留。

最后这句很重要。它是在消除“去了武汉，我的天津店是不是就没了”的顾虑。

### 颜色怎么用

明信片纸张、描边继续使用统一的奶油米白和暖棕色；浅青绿色用于城市标签、邮戳局部和装饰。

主按钮继续复用你现有的金黄色主按钮，次按钮使用乳白色底板。**不需要因为换城市，就把整套按钮规则也换掉。**

---

## 五、点击“前往武汉”：让同一张明信片连接到武汉经营手账

这里建议保留你现有的页面结构：

**武汉解锁明信片 → 武汉经营手账 → 开始营业 → 武汉工作台。**

但不要在中间再插入一个“欢迎来到武汉”的确认弹窗。

### 1. 出发转场：约0.6～0.8秒

点击“前往武汉”后，按钮短促下压，明信片略微向前放大，背景地图淡出。

随后用明信片的奶油色纸面完成遮挡，再揭开武汉经营手账。

可以做成这种视觉连续性：

> **地图上的武汉明信片，成为了武汉手账里的第一张城市记录。**

不必真的制作复杂的三维翻书。用纸页遮挡、位置变化和前后两张页面的衔接，就能表达这个过程。

### 2. 武汉经营手账：直接定位第1天

进入后，默认选中 **“武汉 · 第1天”**。

这一页只需要让玩家立即看清：新城市、首日早餐，以及“开始营业”按钮。不要重复播放刚才的节点点亮、邮戳和长篇介绍。

城市内营业日应从武汉第1天开始显示；若另有“旅程总天数”，应单独统计，避免让玩家看到“武汉第8天”而产生混淆。

### 3. 玩家点“开始营业”后，才进入实际经营

在玩家主动开始前，不出顾客、不启动营业倒计时。

进入工作台后，建议让武汉的第一单尽快体现新的操作：**先完成一碗热干面**，通过实际操作认识烫面、加料、拌匀，而不是再看一轮大段文字。

这样，解锁演出承诺的“新玩法”，能够在进入章节后马上得到回应。

## 六、选择“留在天津”或跳过动画时，也要有完整设计

### 留在天津：不是拒绝奖励，只是暂时不出发

无论玩家在营业小结还是明信片页选择“留在天津”，都返回天津经营手账；在保留后续营业的方案下，默认接续天津Day8。

武汉仍然保持已解锁。

后续提醒放在现有入口中即可：世界地图的武汉节点保留一个小“新”纸签，或在天津手账里留一条“武汉已开放”的轻提示。

**不用在首页新增独立的“前往武汉”按钮，也不要每次进入菜单都重新弹窗催促。**

### 跳过演出：直接显示明信片最终状态

演出期间提供“跳过”，键盘也可用Esc触发。

跳过后，直接显示已经展开的武汉明信片和两个按钮，而不是直接把玩家送进武汉。

也就是：

**跳过动画 ≠ 放弃解锁 ≠ 自动出发。**

用于跳过的那次按键或点击应被消耗，不能穿透到刚出现的“前往武汉”按钮。演出结束后，也不要让最后一次加速点击顺带启动下一章。

提供减少动态效果模式时，可直接用短淡入呈现最终明信片，取消地图运动和弹跳，但保留所有文字信息。

---

## 七、程序上一定要分开：“已经解锁”和“看过演出”

这一点比动画细节更重要。

**武汉的解锁不能等到动画播放完才写入存档。** 否则玩家跳过、切后台或中途退出，就可能出现进度不一致。

建议在天津Day7被正式判定完成、营业结算成功时，就保存当天收益与武汉解锁结果；演出只负责呈现已经发生的变化。

| 状态            | 建议何时更新                  |
| ------------- | ----------------------- |
| **武汉已解锁**     | 天津Day7完成并成功结算时          |
| **武汉解锁演出已看过** | 明信片最终状态展示完成，或玩家跳过到最终状态时 |
| **当前城市**      | 玩家确认前往，且目标界面准备就绪后       |

触发条件以“完成天津Day7”为准，不额外增加满意度、金币支付或购买设备的门槛。主动“放弃本日”则不应被当作Day7完成。

重玩Day7时，不重复发放同一份收益或重复触发首次解锁；演出中途退出后，武汉也不能重新变回未解锁。重新进入时保留入口或补一个静态提示即可，不必强制重播整段。

### Godot中的实现分工

这套演出可以主要用现有PNG素材和程序动画实现：

| 部分                 | 实现建议                                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| **整体分镜与音效时点**      | 用`AnimationPlayer`组织固定时间轴，便于调整路线、节点、明信片和音效之间的节奏。它适合这类时间关系较明确的复杂动画。([Godot Engine documentation][1])                                  |
| **节点弹跳、卡片展开、按钮反馈** | 用`CreateTween()`创建局部动画，必要时通过`Parallel()`让位移、缩放和透明度同时变化。([Godot Engine documentation][2])                                             |
| **跨页面纸页遮挡**        | 将遮罩放在常驻界面宿主中的独立`CanvasLayer`，利用其独立绘制层级覆盖页面切换。([Godot Engine documentation][3])                                                       |
| **跳过与中断**          | 停止相关动画；Tween可用`Kill()`中止。随后由统一函数显式设置最终视觉状态，不让多个Tween继续争抢同一个属性。([Godot Engine documentation][2])                                      |
| **武汉资源准备**         | 可在结算或解锁演出阶段调用`ResourceLoader.LoadThreadedRequest()`，检查加载状态后再取得资源；不要过早调用`LoadThreadedGet()`，否则仍可能阻塞。([Godot Engine documentation][4]) |

建议由一个统一的解锁演出控制器管理播放、跳过、关闭和最终状态；收益结算与城市解锁逻辑放在独立的数据逻辑中，不绑定到盖章动画的回调上。

## 八、第一版优先做什么

你之前准备的**世界地图、武汉城市节点、武汉旅行明信片、解锁轻光效、星闪、蒸汽，以及主次按钮底板**，都可以作为这套演出的基础。

第一版重点完成三个部分就够了：

1. **结算后的新旅程纸签与按钮**：让玩家明确知道武汉已经开放。
2. **地图连线、武汉节点点亮、明信片展开**：完成跨城里程碑的仪式感。
3. **明信片到武汉第1天的顺畅衔接**：让玩家尽快接触新早餐，而不是继续确认弹窗。

纸飞机飞行、列车旅行、完整翻书、复杂烟花都可以暂缓。它们不应挡在这条核心流程前面。

结合你此前“Demo太平缓、缺少继续解锁冲动”的试玩反馈，我会把这次设计的检验重点放在：**玩家是否看懂了武汉会带来不同的操作，是否放心保留天津进度，以及是否愿意主动点击“前往武汉”。** 不能只看解锁动画本身是否热闹。

**这次真正要交给玩家的感觉是：天津的努力没有被清空，而是在地图上换来了一间能做新早餐的店——现在就值得过去看看。**
