# 全章节营业账本

2026-09-12 实现。布局依据《营业结算页 UI 布局稿-天津》与《本次营业明细页面优化-天津》，覆盖天津、武汉、西安、广州、扬州的营业中查看及收摊结算。

天津随后接入 BookUI 专属美术，底板、图标、贴片及布局以[天津营业账本素材接入](天津营业账本素材接入.md)为准。武汉、西安随后按正式配色规范接入同一 Global/BookUI 素材布局，详见[三章节账本配色接入](三章节账本配色接入.md)；广州、扬州继续使用原共享皮肤，最新截图位于 `.impeccable/review/global-book-ui/`。

## 页面与入口

- 1920×1080 设计画布，1680×900 双页纸质账本，店铺背景暗化 40%。其他尺寸等比居中适配。
- 默认“今日小结”：左页突出本次收入、销售额、小费和热销商品；右页展示完成、流失、完成率、满意度、Perfect 和固定规则生成的手记。
- “顾客明细”以同一滚动容器承载左右配对行，左侧为顾客及商品，右侧为结果、收入、小费、评分和错误原因。普通行约一屏四单，长名称和多商品自动扩展行高。
- 全部、完成、错误、流失四种筛选保留结束顺序与原编号；完成包含错误完成，空结果单独提示。补充记录位于明细末尾。
- 天津、武汉点击现有收银挂件；西安、广州、扬州使用顶部“营业账本”按钮，原收钱规则保留。
- 营业中标记“截至目前”，打开时暂停经营，关闭恢复原焦点及原暂停状态。拖拽或制作手势中不可打开，Tab 焦点限制在账本内。
- 收摊显示“今日收摊”，由“收好账本”或 Esc 返回当前城市经营首页；旧结算弹窗不再叠加。

## 数据口径

`DayController.BusinessRecords` 采集天津、武汉、西安、广州的本局完成及流失快照。扬州使用 `YangzhouSession.BusinessRecords` 和独立适配器。逐单记录仅驻留本次营业，重开清空，不改变存档格式，也不从页面重新付款。

- 完成率＝完成÷（完成＋流失）；未结束的排队订单不进入分母。零记录为“—”。
- 满意度仅按完成顾客计算，无完成订单为“—”。扬州以“组”计数，其余城市以“位”计数。
- 热销按完成订单的商品数量累计，包含错误完成、排除流失，不区分酱量；并列按稳定商品 ID 排序取第一项。
- 手记按完成率 80%、满意度 80 分为四种固定文案。无记录与全部流失有独立提示，Perfect 不改变手记判断。
- 扬州保留整盘交付。有备餐失误的完成单归入错误并显示次数，普通品质下降不等同出餐错误；未入场但计入流失的订单显示“收摊未接待”，已入场后离开显示“等待离开”。
- 缺少食物素材时使用程序图标配商品名称，不替用其他城市菜品图。顾客头像使用现有素材裁去透明留白。

## 共享组件与结算边界

| 组件 | 职责 |
| --- | --- |
| `BusinessBookModel` | 城市、阶段、汇总、逐单快照、筛选、保存状态及补充信息 |
| `BusinessDetailsView` | 双页绘制、筛选滚动、焦点、动画；发出关闭和重试事件 |
| `TianjinBusinessDetails` | 保留原兼容入口 |
| `BusinessBookSession` | 新入口城市的模态生命周期及独立暂停处理 |
| `BusinessBookSettlement` | 通用城市原结算入口调用的保存结果适配 |
| `YangzhouBusinessBook` | 扬州 Session 快照与原结算规则适配 |
| `BusinessBookIntegration` | 西安、广州、扬州页面接线 |

保存仍由城市收摊入口负责。页面展示真实永久金币增量、历史最佳差额、评级及练习状态；翻页、关闭和动效不提交存档。新解锁和可购买升级只在满足条件时显示贴纸，升级资格复用经营首页的只读判断，账本不提供购买。

保存失败显示“未保存”及回滚说明，不显示成功解锁贴纸。西安、广州、扬州保留重试及返回限制，Esc 不绕过限制；天津、武汉沿用原失败后可返回的处理。练习模式不写入金币、设备与章节进度。

广州普通关卡配置、队列、顾客展示与交付槽位统一为五位，扬州等待队列、展示及交付同样为五组；明确的教学保护继续保留。

## 动效

收摊约 1.7 秒依次呈现账本、收入累计、经营数字、Perfect 印章和手记；零 Perfect 不盖章。点击可跳过，切页或关闭结束动效。营业中查看采用短淡入，减少动态效果设置生效。翻页、金币、盖章和完成反馈复用现有音频能力与音量总线。
