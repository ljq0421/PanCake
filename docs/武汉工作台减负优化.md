## 优化结果

| 问题 | 实施内容 |
| --- | --- |
| 大拌面底座抢占中心 | 停止加载和绘制底座，面碗直接落桌；碗主体约 210px，筷子跟随碗定位 |
| 配料与库存入口分离 | 基础调味、葱花、辣油、牛肉从左至右排列；90px 容器、库存和 48px 补货按钮共用模块位置 |
| 桌面变深但下方仍拥挤 | 制作物靠后、原料备货靠前；锅、面碗、豆皮原料各自保持清晰分组 |
| 豆皮备货体量偏大 | 盘体 160×76；每层两排四块、最多两层缩略表示，库存仍为 16；交付预览仍为 100×75 适配框 |
| 蛋酒增加第三条制作线 | 取消机器、底料和冲泡手势；初始 6 杯成品，直接拖给顾客，0.6 秒手动补满 |
| 配料覆盖面条、拖影易不一致 | 碗内统一相对坐标及明确配料比例；桌面和拖影共用 BowlLayers，加料动画共用最终落点 |
| 顾客腿部进入桌面 | 使用柜台半身显示，人物层在 y=580 截止；订单带上移，四位完整套餐均能看全 |
| 长说明压住工作区 | 常驻库存和简短制作状态；操作方法在悬停显示，已加配料用小勾，临时反馈放在桌面后侧空白处 |

保留实体金币盘的当前素材、位置、尺寸及按付款次数累积硬币的行为。保留当前背景、约半屏桌面、订单价格、热干面与豆皮制作规则、顾客订单气泡规则及所有源美术文件。

## 蛋酒行为和兼容

- Day 6 解锁，每局初始 6 杯，备货位最多展示 3 杯代表杯，库存标签始终为准确数量。
- 成功交付才扣 1 杯；无效投放、取消和重复点击不消耗。多杯订单逐杯交付，订单行已满时拒绝继续扣杯。
- 未满时手动补货，0.6 秒后补满；期间不能取杯，重复补货不重启计时，暂停和失焦冻结计时。
- `EggRiceWineRuntime` 使用 `Count`、`CanTake`、`IsRefilling`、`RemainingSeconds`，保留 `TryTake`、`TryRefill`、`Tick`；移除 `TryStart`、底料计数和冲泡状态。
- 产品 ID、拖拽载荷及 `egg_rice_wine_station` 解锁存档键保留；运行时杯数不写入旧存档，无需数据迁移。

## 布局实现约束

布局以 1920×1080 为设计分辨率，通过现有 Godot canvas stretch 缩放。工位内道具、拖拽节点、补货按钮和动画共用几何定义。普通独立道具按可见轮廓等比适配；面碗内容在统一碗内坐标中配置尺寸，不将所有小料自动撑满碗面。

旧文档中 580px 拌面底座、252px 豆皮盘及豆皮放大 1.2 倍的规范由本次替代。保留历史文档用于追溯，不删除未使用源素材。
