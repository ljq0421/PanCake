# Steam Demo 体验优化方向与质量计划 v2

> 2026-09-16 状态更新：用户已确认首批真人试玩完成，并授权按 1 → 3 → 4 → 5 扩展两城。本轮实施、验证、阶段包及人工待验以 [两城 RC1 实施记录](Demo-TwoCities-ReleaseNotes.md) 为准；下文早期三局门槛属于当时计划，不再阻断本轮开发。

更新：2026-09-15。本版依据本次方向评审修订，替代 v1 的目标范围；不设固定上线日期，按体验验证结果推进。

## 1. 已确认目标与范围

核心体验：**做成第一份早餐 → 学会安排营业 → 感受到升级收益 → 到新城市学习新手艺。**

- 面向新玩家公开试玩，积累本体愿望单。天津负责手作满足感与经营基本功，武汉以热干面和豆皮呈现新手艺，西安可见不可玩。
- 采用独立精简路线，首轮 35～50 分钟为观察目标，不强制计时结束。天津 7 局、武汉 6 局是原型基线，不是内容数量承诺。
- 简体中文与英文同步；Demo 独立存档，首发不承诺继承，不自动读取或写入正式版进度。
- 主线宽松推进：正常收摊、至少完成 1 单并保存成功才开放下一局；零完成允许免费重试。保留金币购买与升级顺序选择，低收入与不同购买顺序不另加推进门槛。
- 保留轻量早餐旅行手账、两城衔接和完整结尾。
- **独立挑战、固定熟客身份、回访剧情与人物小记延期，退出本版必做清单。**现有 normal、regular、office_worker 等顾客行为类型继续使用。
- 完整图鉴、第三城营业、额外经营系统、好感度、排行榜和 Steam 成就均不纳入本版。
- 沿用天津、武汉既定收银、丢弃、耐心、满意度、小费和音效规则；其他城市不随本计划迁移交互。

商店页与 App ID 已就绪、未报名新品节，是已有用户说明；不表示已检查后台或完成发布审核。发布仍以实际包与后台状态为准。

## 2. 当前判断与优先级

参考讨论主张两城试玩与西安预告，本版延续该定位。其“声音最缺”的判断需结合当前实现修正：现已有制作与经营音效、挂件收银、逐单账本、开始页、地图、城市页和设备升级；设置已有音量与显示选项，仍标注暂无背景音乐。

源码中的天津教学分支会隐藏工作台提示；存在教学代码不等于新玩家能学会。天津二级炉防焦、武汉二级面锅锁定最佳状态，已能支撑成长体验，需要让玩家感到实际收益。上述结论来自源码检查，不是视口或听感验收。

| 优先级 | 优化方向 | 可观察的玩家反应 |
|---|---|---|
| P0 | 首份教学与手作反馈 | 知道拿什么、放哪里、何时成功和下一步 |
| P0 | 营业安排 | 利用加热空档、提前补货或部分交付争取时间 |
| P0 | 升级收益 | 能说明选择理由，升级后操作更从容 |
| P0／贯穿 | 独立 Demo、保存恢复、双语与可运行小包 | 新建、退出、继续可信，内容与入口一致 |
| P1 | 两城旅行、轻手账与结尾 | 记得学过的早餐，期待下一站 |
| P1／贯穿 | 声音与短衔接 | 动作听得清，城市有氛围，重复游玩不拖沓 |

## 3. P0：第一份早餐与逐渐熟练

### 首份制作

先打磨天津摊饼、翻面、刷酱、装袋；之后覆盖武汉提篮、拌面和豆皮切块。短提示由真实状态驱动，连续手势展示实际进展，无效落点、提前操作、取消与失焦后可以恢复。

首次教学提供明确保护，学会后撤去提示；正常营业遵守既定规则。教程可以跳过和回看，跳过不冒充学会。制作音与动作同步验收，按真实缺口处理听不清、重复响和反馈迟到。

### 营业安排

按“介绍 → 独立练习 → 组合运用”编排，不同时堆入首次配方、缺料与短耐心。重点让玩家发现：

1. 利用一份食物加热的空档处理另一件事。
2. 趁空档补货，减少高峰中的中断。
3. 先正确交付部分商品，恢复耐心总量的 15%。

同屏最多五人；流失顾客不计入最终满意度平均。增加难度优先改变已学机制的组合，不单靠缩短耐心或增加顾客。

### 升级收益

首次购买前呈现对应瓶颈，购买后安排相近压力的营业；升级保留关键手作动作，主要释放监控、补货或等待负担。低收入和不同购买顺序不成为进入武汉的阻断。

第一批原计划止于 T3，而首次升级在 T3 结算开放，缺少升级后体验。本版增加 **T3 同配置重玩验证**：使用真实已购设备，沿用历史最佳收入补差，不新增公开路线局数、不赠送验证用永久金币、不改变既有价格。

## 4. P1：一段完整早餐旅行

- 开张、收摊、城市转换使用短衔接，重复游玩可快速经过。
- 天津收尾呈现掌握手艺；武汉开场介绍新操作，已学订单判断可迁移。
- 轻手账复用经营手账与书页，保留早餐名称、插图、制作要点、城市纪念和真实营业记录。配料变体不扩成大量卡片，豆浆记为供应记录。
- 正确交付合格商品后暂存早餐记录，正常结算保存成功后入册；营业中仅轻提示，详情在结算或主动翻阅时查看。
- 武汉结束展示两城成果、西安预告、回玩、本体商店与反馈入口。只预告已经确定的内容，不承诺整张世界城市清单。
- 配乐从首页与两城小样试听开始，确认听感后扩充；高峰操作提示必须清楚。沿用暂停、明细、失焦和离城时停止营业音效的规则。

主线重玩先用于观察熟练后的乐趣；独立挑战和人物系统只进入后续评审，不因素材可用而自动回到必做清单。

## 5. 执行顺序与质量门槛

第一批交付：**独立 Demo 天津教学＋T1～T3＋升级后的 T3 重玩验证小包。**

1. 独立运行配置、存档、访问边界，以及新建、保存、退出、继续。
2. 首份煎饼教学、独立制作、错误恢复和同步声音。
3. T1～T3 固定计划、首次购买选择及 T3 重玩。
4. 中英提示、实际窗口操作与独立导出包。
5. 首批陌生玩家测试，修正教学和成长问题。
6. 通过后扩天津混合营业、武汉、两城结尾与轻手账，最后完成配乐与发布质量检查。

以下为内部观察门槛，不是市场转化预测：

| 阶段 | 完成依据 | 未通过时 |
|---|---|---|
| 首份制作 | 修正后的 5 人中至少 4 人无需口头指导完成，无教学卡死 | 修提示、落点和状态反馈 |
| 安排与成长 | 至少 3／5 人主动使用一种安排；至少 4／5 人理解所选升级，并记录升级前后行为 | 调瓶颈呈现、练习空间和购买时机 |
| 两城体验 | 新的 5～8 人试玩，记录时长、退出点、疲劳及两城差异；反复出现的阻断已解决 | 压缩重复内容或拆分密集教学 |
| 发布候选 | 实际包完成新建、两城、结尾、退出与继续，无已知丢档、越界或卡死 | 修对应问题再复验 |

不把“自愿回玩人数”设为本版硬门槛；记录是否主动重玩、想改进什么，作为后续挑战设计证据。不存在真实测试者时标注待测，不以自动化测试代替真人结果。
