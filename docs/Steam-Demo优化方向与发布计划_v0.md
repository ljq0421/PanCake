我建议把 Steam Demo 定义成一个**高完成度的“垂直切片”**，而不是正式版的缩小版。Steam 官方对 Demo 的描述也是：展示一小段核心体验，让玩家理解核心机制，同时“还想继续玩”；内容长度要在“足够产生兴趣”和“不要让玩家觉得已经体验完全部游戏”之间取得平衡。([Steamworks][1])

## 一、天津 + 武汉已经够，西安不要完整开放

对《早餐铺子》来说，**天津 + 武汉实际上是很理想的 Demo 组合**。

天津承担的是“让我理解这是什么游戏”：煎饼果子是核心手工流程，随后增加油条、豆浆、补货、设备升级，操作直观，适合完成教学和第一阶段成长。

武汉承担的是“原来每个城市真的不一样”：热干面有烫面、提起、沥水、倒碗、加料、拌匀；豆皮又是倒浆、加蛋、等待、翻面、加馅、切块。它已经足以证明你的“开遍世界早餐铺子”并不是简单换皮，而是**每座城市都拥有新的制作机制**。

这两座城市组合起来，玩家已经可以理解游戏最重要的三个卖点：

> 经营早餐铺 → 学习当地特色早餐 → 前往下一座城市并学习完全不同的操作。

所以我不建议为了 Demo 把西安也全部做完。**2 个精致城市 > 3 个内容完整度参差的城市。**

西安反而应该成为 Demo 最重要的“钩子”。

世界地图中让西安节点可见；完成武汉后播放旅行路线；出现西安明信片；短暂展示白吉馍、肉夹馍或胡辣汤的素材；节点变成类似“下一站”的状态，但暂不可进入。

这样玩家结束 Demo 时的感觉不是：

> “玩完三个城市了，差不多知道这游戏有什么了。”

而是：

> “天津和武汉居然已经差这么多，西安又会怎么玩？”

这个心理状态更适合 Demo。

# 二、我会把 Demo 控制在大约 35～50 分钟

这不是 Steam 的硬性规定，而是结合《早餐铺子》目前 1～3 分钟一天的节奏，我认为比较合适的首轮体验。

| 阶段         |     建议时间 | 玩家获得的东西           |
| ---------- | -------: | ----------------- |
| 开始页面 / 新旅程 |   1～2 分钟 | 理解环球早餐铺概念         |
| 天津前期       |  8～10 分钟 | 学会煎饼              |
| 天津中期       |  8～10 分钟 | 油条、豆浆、升级、压力上升     |
| 天津结算 / 地图  |   2～3 分钟 | 完成第一座城市的旅行感       |
| 武汉         | 15～20 分钟 | 热干面 + 豆皮，证明玩法明显变化 |
| 武汉完成       |   2～3 分钟 | 盖章、旅行手账、收入总结      |
| 西安预告       |   1～2 分钟 | “下一站”期待           |
| Demo End   |        — | 愿望单 / 反馈 / 返回地图   |

这里有一个很重要的调整：

**Demo 不一定需要把天津原本 Day1～Day15 原封不动全部塞进去。**

Demo 应该有自己的节奏压缩版。

尤其你现在设定的**顾客行为差异在 Day10 之后才明显出现**，如果 Demo 把天津压缩到 6～8 天，那么玩家几乎看不到这一层深度。因此 Demo 里可以提前安排 **1～2 个特殊顾客**，让玩家知道正式版后期顾客不只是“不同头像的计时器”。

# 三、目前真正需要优先补齐的，不是西安，而是“Demo 外围闭环”

从我们目前已经做的内容来看，你的**工作台核心内容已经比较丰富**；真正容易让 Demo 显得“开发中”的，反而是工作台以外的流程。

我会这样排：

| 模块              | Demo 优先级  | 当前建议                   |
| --------------- | --------- | ---------------------- |
| 天津完整经营闭环        | **P0**    | 必须                     |
| 武汉完整经营闭环        | **P0**    | 必须                     |
| 开始 / 新旅程 / 继续旅程 | **P0**    | 目前正在补，必须完成             |
| 世界地图            | **P0**    | 必须成为两个城市之间的连接器         |
| 教学系统            | **P0**    | 建议做成操作中教学，不做长文字教程      |
| 存档 / 继续游戏       | **P0**    | Demo 也必须稳定             |
| 设置菜单            | **P0**    | 音量、分辨率、全屏、语言至少要有       |
| 音效 / BGM        | **P0**    | 非常重要，下面单独讲             |
| 营业结算 / 顾客明细     | **P0**    | 你现在正在做的账本方案非常适合 Demo   |
| 设备升级页           | **P0**    | 至少让玩家实际升级一次            |
| 城市完成演出          | **P0**    | 很重要                    |
| Demo Ending     | **P0**    | 西安预告 + 愿望单             |
| 英文              | **P0/P1** | 如果公开 Steam，我强烈建议中英至少同步 |
| 顾客图鉴            | **P1**    | 建议做，但不用完整              |
| 菜谱 / 早餐图鉴       | **P1**    | 我认为甚至比顾客图鉴更值得先做        |
| 旅行手账            | **P1**    | 非常适合你的游戏               |
| 成就              | **P2**    | Demo 不建议投入             |
| 西安完整章节          | **P2**    | 不需要                    |
| 装修 / 大量装饰系统     | **P2**    | 正式版再做                  |
| 大型随机事件系统        | **P2**    | 正式版再做                  |

Steam 官方甚至明确建议 Demo **关闭 Steam 成就**，如果之后希望 Demo 进度继承正式版，可以考虑共享 Steam Cloud 存档，在正式版读取时再补发对应成就。([Steamworks][1])

所以你现在完全没有必要为了 Demo 去做一整套 Steam Achievement。

# 四、顾客图鉴：建议有，但千万不要“补齐”

这是我比较明确的意见。

**完整顾客图鉴不是 Demo 必需功能。**

如果为了 Demo 专门画二三十个顾客、写背景、喜好、解锁条件，会迅速变成一个非常大的支线工程，而且它不是你的核心卖点。

但完全没有“人”的记忆点，又会让经营游戏稍微缺一点生活感。

所以建议做一个很轻的版本，甚至不要叫“顾客图鉴”，叫：

### 「旅途中遇见的人」

玩家第一次遇到某位特色顾客以后，在经营手账中自动增加一张小记录。

每张只需要：

**头像 + 昵称 + 一句话 + 喜欢的早餐。**

例如不是展示大量数值：

> 耐心 73
> 小费率 15%
> 移动速度……

而是更生活化：

> **晨跑大叔**
> “每天都说不要辣，最后还是会加一点。”
> 喜欢：经典煎饼

这种内容的制作成本非常低，却会给游戏带来非常大的“店铺生活感”。

而且 Demo 中只放 **6～10 个特色顾客**就够。

还有一个细节我很建议：

**不要显示“7 / 48 顾客已收集”。**

否则玩家第一感觉是“Demo 阉割了大量内容”。

直接采用自然增长式手账：

> 你遇到谁，就增加谁。

没有锁格、没有问号、没有 7/48。

正式版以后再决定是否把它升级成真正图鉴。

---

# 五、比顾客图鉴更值得做的是「早餐旅行手账」

你现在其实已经无意中把这一系统需要的素材做了很多：

营业账本、今日手记、城市配色、菜品小图标、Perfect 印章、奖励章、城市明信片、城市节点……

把它们连接起来，会非常适合《早餐铺子》。

这可以成为整个游戏的 Meta UI：

> 世界地图负责“我要去哪里”
> 工作台负责“我正在经营”
> 早餐手账负责“我经历过什么”

比如天津完成后自动增加一页：

**天津**

煎饼果子 ✓
油条 ✓
豆浆 ✓

最佳营业：¥XXX
最高满意度：XX
遇见的顾客头像若干

右下角：

**天津早餐铺完成章**

旁边贴一张天津明信片。

然后翻页就是武汉。

这会瞬间把：

> “一个又一个经营关卡”

提升成：

> **“我的环球早餐旅行”**

而后者才是你这个项目真正区别普通餐饮模拟小游戏的地方。

---

# 六、我认为当前项目最缺的一块，其实是“声音”

从我们最近优化的内容看，你现在视觉层已经投入得非常深：

工作台透视、托盘统一、HUD、收银挂件、垃圾桶、工具位、结算账本、世界地图、城市节点……

但对于这种高频拖拽 / 点击 / 等待火候的料理游戏：

**声音带来的提升可能比再增加一套 UI 素材还大。**

煎饼面糊倒下：

**滋——**

刮板摊开：

**沙沙——**

打蛋：

**啪。**

薄脆落下：

**咔。**

油条入锅：

**滋啦。**

漏勺抖动：

**哐、哐。**

热干面搅拌：

轻微碗筷碰撞。

豆皮翻面：

**啪！**

Perfect：

不是普通 UI “叮”，而可以是短促、有满足感的小印章声。

金币进入你现在设计的挂件式收银位：

**叮——**

一天关店：

环境音逐渐下降，再出现翻账本声。

这种游戏是非常依赖**操作反馈**的。

如果目前音频还是比较基础，我甚至会把：

> **完整音效反馈**

放在：

> 顾客图鉴、西安、更多 UI

之前。

---

# 七、再增加三个“小系统”，游戏会明显更有味道

不需要做大型系统。

### 第一是「开店 / 收摊」

一天开始不要直接切进工作台。

1～2 秒即可：

招牌轻轻摆一下。

**“DAY 5 · 天津 · 清晨”**

厨房环境音起来。

营业结束：

最后一个顾客离开。

火炉声音下降。

账本“啪”地打开。

进入营业结算。

你一直强调每天只有 1～3 分钟，这种仪式感尤其重要。

---

### 第二是「第一次制作成功」

玩家第一次完成一种新早餐，不要只出现：

> 解锁豆皮

而可以做成：

**菜谱卡片啪地贴进旅行手账。**

例如：

三鲜豆皮
武汉早餐 ✓

再盖一个小章。

一次只需要 1～1.5 秒。

成本低，但是非常有收集感。

---

### 第三是「城市完成」

完成天津不能只：

> Day结束 → 世界地图 → 武汉解锁。

至少给一个非常短的演出。

账本翻页。

天津印章落下：

**啪。**

旅行线路从天津延伸到武汉。

武汉节点亮起来。

这时音乐切换。

这种 3～5 秒的桥段，很可能成为 Demo 最有记忆点的部分之一。

---

# 八、顾客本身也应该增加一点“反馈表演”

不需要复杂 AI。

现在的满意度系统已经有 Perfect、等待扣分、错配料等逻辑。

可以直接映射三档视觉反应：

**满意：**眼睛弯、轻微点头、冒一个小爱心/星星。

**普通：**正常拿餐离开。

**不满：**皱眉、短暂蓝色不满表情。

Perfect 时：

顾客稍微放大 1.03 倍 → 小弹跳 → 小费金币进入挂件式收银位。

不要弹大大的：

> PERFECT！+1 COIN

你前面一直在降低顶部 HUD 的“系统 UI 感”，这里最好继续沿用同一原则：

**让人物和场景自己告诉玩家发生了什么。**

---

# 九、还需要一个非常重要但经常被忽略的东西：Demo Ending

我建议武汉完成后不要突然：

> 感谢游玩 Demo。

而是完整做一个约 20 秒的结尾。

武汉完成章。

世界地图展开。

天津 ✓
武汉 ✓

旅行路线继续西行。

西安节点出现。

肉夹馍小图标轻轻弹出来。

短暂出现：

白吉馍炉 → 腊汁肉 → 胡辣汤。

然后再把世界地图稍微缩远一点：

中国还有数座城市。

地图外还有：

东京、首尔、曼谷、巴黎、伊斯坦布尔、纽约……

这些**不用真正可玩，也不用全部画完整**。

目的只有一个：

让玩家突然意识到：

> “原来这游戏真的是准备一路开到全世界。”

最后才出现：

**旅程才刚刚开始。**

下面：

**加入愿望单**

**提供 Demo 反馈**

**返回早餐铺**

Steam 官方也建议在 Demo 主菜单或暂停菜单中直接提供反馈入口；同时 Demo 可以从游戏内通过 Steam Overlay 引导玩家前往完整游戏商店页。([Steamworks][2])

这个页面的重要程度，**远高于完整西安章节**。

# 十、还有几个“公开 Steam Demo”必须检查的技术项

你的设计基准一直是 1920×1080，但真正公开 Steam 后，不能只测试这一种分辨率。

至少实际跑一次：

| 项目                     | Demo 发布前 |
| ---------------------- | -------- |
| 1920×1080              | 必测       |
| 2560×1440              | 必测       |
| 1366×768               | 建议       |
| 1280×720               | 建议       |
| 16:10                  | 建议       |
| 窗口化                    | 必测       |
| 全屏                     | 必测       |
| Windows 缩放 125% / 150% | 建议       |
| 连续开始→天津→武汉→退出→继续       | 必测       |
| 强制 Alt+F4 后读档          | 必测       |
| 多次重开 Day               | 必测       |
| 拖拽到非法区域                | 必测       |
| 五名顾客极限压力               | 必测       |

尤其你现在很多 UI、托盘、挂件、桌沿组件的位置都是精确布局，**Steam 用户真实分辨率环境**会是 Demo 比内容数量更大的风险点。

# 十一、如果要做英文版，现在就做，不要最后再翻

因为你大量 UI 已经在往：

**图标化、无文字、场景化**

发展，这其实非常适合国际发行。

Demo 至少建议：

**简体中文 + English。**

并且不要只翻菜单。

必须检查：

订单气泡、教学提示、升级页面、营业结算、设置、Demo Ending、错误提示。

这样未来正式版增加城市时不会因为 UI 固定中文宽度重新改一遍。

# 十二、Steam 本身还有几件现在就值得规划的事情

Steam 当前文档明确说明，Demo 可以只有主游戏商店页入口，也可以拥有自己的独立 Demo 商店页；如果做独立 Demo 商店页，官方要求页面内容准确对应 Demo，并准备 Demo 专属宣传片和**至少 5 张 Demo 截图**。在正式版尚未发行时，主游戏商店页也应该处于 Coming Soon，以承接愿望单。([Steamworks][1])

另外，今天是 **2026 年 9 月 14 日**。如果你之前已经报名了 **Steam 新品节 2026 年 10 月版**，这一届活动是 **10 月 19 日—10 月 26 日**；Steam 当前列出的时间表中，**9 月 14 日（PT）就是希望参加媒体预玩时提交 Demo build 和商店页审核的建议截止日，9 月 28 日（PT）是新品节所需内容提交审核的截止日**。如果没有在 8 月 31 日前报名，则这一届新品节的常规报名已经结束，不影响你单独发布普通 Steam Demo。([Steamworks][3])

而且 Steam Next Fest 每款游戏只能参加一次，所以也没必要为了赶一次活动把西安仓促塞进 Demo。([Steamworks][3])

# 我会把你现在的 Demo 范围正式锁成这样

**可玩：天津 + 武汉。**

**可见不可玩：西安。**

**远景展示：中国另外数城 + 世界城市。**

天津负责“好上手”。

武汉负责“证明每城玩法不同”。

西安负责“让我还想继续玩”。

在此基础上，我认为你目前最应该优先补的顺序是：

**完整声音反馈 → 开店/关店仪式 → 天津武汉章节衔接 → 城市完成演出 → Demo Ending / 愿望单 → 教学打磨 → 存档/设置/分辨率 QA → 轻量早餐手账 → 少量特色顾客 → 顾客轻图鉴。**

**不是西安。**

如果前面这些全部打磨好，即使 Demo 只有两座城市，它给玩家的“完整度”反而会远远高于三座城市都开放但缺少包装、反馈和结束钩子的版本。

而且你目前已经做了大量世界地图、旅行明信片、城市节点、账本、章节色、完成印章等素材，这些非常适合把 Demo 从“两个厨房关卡”包装成**“环球早餐旅程的第一段”**。这才是我认为《早餐铺子》Steam Demo 最应该建立的第一印象。
