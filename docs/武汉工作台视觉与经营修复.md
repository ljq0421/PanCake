# 武汉工作台视觉与经营修复

2026-09-11。按试玩反馈及确认方案实施。本记录更新此前武汉有限生面库存和蛋酒持续供应的规则。

## 实现

- 豆皮使用同一套锅面坐标：从方形源图裁取中间宽幅区域再投影，避免整张压扁。加馅、成熟和切块共用纹理；成熟随第二阶段烹煮进度渐变金黄。
- 整锅与八块使用相同网格，切块时纹理不重新映射。库存保存每块的纹理区域编号与品质，部分入盘、再次补入及拖拽预览沿用对应区域。
- 投料分为移动、落料、铺开、收回；翻面同步抬起与落回；刀具和切痕同步；转移从实际锅面位置开始。操作时长及制作状态机的原有规则保留。
- 漏勺面团等比放大，静置、下锅、提篮、拖动和倒面共享尺寸锚点，并在前篮沿后方显示；下锅动画从松手位置衔接。
- 武汉全部食材无限供应。生面不再消耗库存、触发补货或显示容量；旧补货节点隐藏并禁用。容量升级从商店及购买逻辑下架，旧等级保留、不退款。
- 删除蛋酒订单及套餐、交付入口、教学和新解锁。第 6 天为“双线熟练”；新通关奖励为热干面、豆皮收藏和章节徽章。旧蛋酒收藏与设备字段仍可读取。
- 删除含蛋酒类型后按剩余订单原比例归一化，顾客偏好使用单面、豆皮、面加豆皮。保留价格、顾客数、时长、耐心、星级目标和共享金币机制。

## 复验入口

逻辑测试运行 `res://Scenes/Tests/WuhanSelfTest.tscn` 等上述同名场景。可视化场景为 `res://Scenes/Tests/WuhanRepairCapture.tscn`；参数 `--720`、`--auto`、`--reduced` 分别选择窗口尺寸、自动设备和减少动态模式。

录制使用 `--write-movie <可写 AVI 路径> --fixed-fps 60`。Godot 在初始化时锁定录像分辨率；720p 录制还需临时将视口配置设为 1280×720，捕获场景内部维持 1920×1080 设计坐标。此次临时配置已在录制结束后移除。
