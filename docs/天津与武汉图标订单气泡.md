# 天津与武汉图标订单气泡

2026-09-17 更新。天津与武汉营业场景共用 `Scripts/UI/OrderBubbleView.cs`，分别由 `TianjinDayScreen.cs` 与 `WuhanDayScreen.cs` 接入。本页替代《天津库存与订单气泡优化》中“订单气泡”章节的旧文字与底框规则；该文其他库存、食材和输入记录仍按其原有范围生效。

## 已确认的显示规则

- 两城订单卡统一为 184 设计像素宽（1920×1080 逻辑视口），不随商品或配料数量加宽；武汉抵消顾客列的缩放，保持与天津相同的卡片和图标显示尺寸。高度随商品行数增加，尾巴固定在顾客上方。
- 按用户确认的 [放大示意](../artifacts/order-icon-size-preview/proposal.png)，成品区域从 `62×46` 调整到 `74×54`，配料区域从 `28×22` 调整到 `36×26`；可视成品约放大 20%，配料约放大 20%～30%。通过减少卡片内边距、将商品行高调整到 58，三行订单总高度仍为 203，不增加卡片宽度。按素材可视轮廓等比适配，并保留约 2 个显示像素的透明安全余量。
- 每份煎饼或热干面独占一条等宽横行。同款数量为2时展开两行，不合并为数量标记。成品大图标右侧显示该份主食自己的额外配料；1～2 个提示图标竖排一列，3 个及以上排两列，不横向铺开。没有配料或酱量提示时成品图标居中。
- 主食交付完成后只将对应区域变浅绿；其他主食与副食区域保持自己的交付状态。不同主食可不按显示顺序交付。
- 每种副食独占一行，成品图标始终位于行中央。只点1份时不显示数量；同款多份合并一行，在图标右侧保留“已交付/需求”（如 `1/2`）。部分交付只更新分数，全部交齐才将该行独立变绿。天津适用油条、豆浆，武汉适用豆皮，并兼容旧订单中的蛋酒展示；不改变商品解锁及订单生成规则。
- 不显示商品名称、份数序号、顾客类型、状态文案或整单总进度。主食完成仅按用户指定的区域变绿表达，此约束只用于订单气泡，不推广为全局状态规范。
- 正常酱量无图标；少酱、多酱分别使用带“少”“多”的栅格图标。食物与配料使用正式游戏美术，热干面图标组合现有碗与面条图层。
- 气泡底部保留耐心条。展示节点忽略鼠标，原顾客交付区域继续处理拖拽落点；制作、交付判定、订单生成、耐心与经济规则不因本组件改变。

## 材质与实现边界

天津继承暖纸色、深棕描边，武汉继承米白纸色、墨绿描边。沿用现有 `OrderBubbleUI/frame-*.tres` 美术边框、顶部装饰、行分隔线与独立绘制的对话尾巴，耐心使用实际 `ProgressBar`。窄卡片布局由两城显式启用，西安继续使用原有宽度和横排布局。

主食区域与副食区域按交付数据分别更新底色。相同订单刷新复用已有节点，顾客更换订单时重建内容，避免上一单图标或完成状态残留。图标使用透明轮廓裁切与等比适配，不将原始食物画布的空白当成可见尺寸。

2026-09-17 图标边缘修正：天津、武汉窄卡片不再直接绘制紧贴轮廓的 AtlasTexture。保留更柔和的半透明边缘，仅忽略极低透明度的画布残留；在运行时纹理四周补足约 2 个显示像素的透明余量，并生成 mipmap，避免描边在纹理边界被截断及小图缩放时轮廓断裂。处理结果按素材和图标尺寸共享缓存，沿用原素材及天津描边，不修改源图片、西安布局或制作台素材。

## 素材来源与复现

酱量图标位于 `resource/art/TianJin/OrderUI`。按项目透明素材要求，先生成绿色背景，再由 `tools/prepare_order_sauce_icons.ps1` 去绿、裁切并输出透明 PNG。原始绿底图、实际首次及修正提示词保存在 [OrderUI 素材说明](../resource/art/TianJin/OrderUI/README.md)；原始生成 PNG 内同时保留提示词来源信息。其余图标沿用天津、武汉已有食物素材。
