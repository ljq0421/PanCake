# 天津金币托盘与长按补货

2026-09-08。适用于天津营业工作台（`UseServingTray = true`）。本说明替代旧文档中独立“+”补货按钮及对应槽位留白的规则，其他城市和实验台维持原交互。

## 布局

所有坐标采用1920×1080设计坐标，由 `TianjinWorkbenchLayout` 统一维护。

| 小料顺序 | 上排面糊／鸡蛋／薄脆，下排酱料／香葱／火腿；未解锁保留空位 |

盘碗与食材大小不变，主要压缩横向留白。生熟油条及炸锅保持原位。金币、成品与豆浆采用前景层级，防止顾客遮住高出柜台的物品。

## 鼠标操作

六种小料和豆浆不再显示独立“+”。在盘碗或库存标牌原地按住左键0.45秒开始补货，随后可以松手。空盘同样必须长按；空盘短按只提示“长按补货”。

- 鸡蛋、香葱和酱刷：短按松开执行原操作。
- 面糊、薄脆、火腿和豆浆：移动超过8个设计像素后启动原拖动流程，并取消长按。
- 未满库存即可提前补货，补货资格独立于当前制作步骤；满库存、补货中及豆浆取杯冷却期间不能触发。
- 蓄力期间显示进度和“松开取消”；达到0.45秒后进入原补货倒计时，不要求继续按住。保持现有容量、耗时、食材预览以及完成前禁止取料的规则。
- 同一次按下仅能产生短按、拖动或补货其中一种操作。提前松开、移出目标、暂停、失焦、退出或重开清除待处理手势。拖料首个移动可直接离开盘子，不必在盘内慢慢拖动。
- 低库存与空盘显示“长按补货”，正常库存悬停可查看操作说明。F/G生产快捷键保持原规则。

`StockGesture` 处理输入判定，由工作台营业时钟推进；`IngredientInventory.TryBeginRefill` 和 `SoyMilkTrayRuntime.TryBeginRefill` 继续负责真实补货。其他城市与实验台不启用新手势。

## 金币与结算

金币托盘复用现有木托盘、金币图标和奶油标牌。顾客整单完成且实际收入大于零时，金币从顾客处飞向托盘。部分交付和拒绝交付不产生付款动画。

三只托盘统一使用成品托盘素材及250×86显示框。金币在托盘局部坐标(48,18)、154×42的盘面安全区内排列，最多12枚的完整矩形均在该区域中，并增加裁切保护。付款落点取安全区中心。豆浆六杯重新排开，杯脚保持在盘内，完整杯身仍可拖动。

`CoinTrayView` 展示本日尚未点击收走的收入：每10元显示一枚示意币，向上取整，上限12枚；顶部显示当日累计收入。点击清空当前钱堆并播放收钱反馈，之后只累积新付款。顾客付款仍自动记账，未点击不会损失收入，永久金币及保存规则未改变。天津、武汉共用的交互与验证见 [天津与武汉点击收钱](天津与武汉点击收钱.md)。

暂停与失焦会暂停金币飞行；重开清除动画和钱堆。减少动态效果时直接更新钱堆，不播放金币飞行。
