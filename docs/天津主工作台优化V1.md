# 天津主工作台优化 V1 实施与验收

2026-09-10。按已确认的《天津主工作台详细修改方案》V1.0 实施。背景、y≈995 以下桌体正面、整体布局和经营规则保留。

## 实施结果

- `TianjinWorkbenchLayout` 集中桌面后沿 580、前沿 995、中心 960、五顾客位置参考、订单底部、前景槽位与落桌规格。`TianjinDeskGuide` 仅在 `--dev-ui` 下显示深度线、接触点、食材输入范围和交付／垃圾桶热区。
- 五位顾客的订单卡改为独立定位，订单底部对齐，人物腰线固定。天津单独按正常表情实体边界校准 155 px 头部高度；24 个角色正常头部实测在 151～159 px 范围。其他城市继续使用原人物配置。订单数量与耐心条保留。
- 四个食材盘复用 `IngredientTray_Right.tscn` 与同一透明母版，食物、输入、反馈仍由独立层管理。取消统一纵向拉伸，改用接触锚点。鸡蛋、薄脆、火腿仍是 6／8／10 份逐件显示，取用不重排、不缩放；香葱原数量、消耗、补货与散装表现保留。
- 后排三个托盘统一深度与薄前沿。金币盘有独立深色表面和金币嵌饰；成品盘保持简洁，豆浆以杯子识别。左侧生料盘镜像母版，沥油架使用新增素材。两碗、勺刷继续使用原图及现有尺寸校准。
- 炸锅保留稳定根节点，按各级原图实体底部与锅口局部校准；场景内 `BasketAnchor` 统一承载炸篮、油条和烹饪反馈。煎饼炉三级底部与炉面中心对齐，饼面、划动与拖入使用同一炉面几何。容量、火候、自动升篮、沥油规则未改。
- `WorkstationSlotSpec` 增加可选接触锚点／视觉接触比例，并支持场景元数据往返；`VisualPivot` 和输入矩形分离。`DropZone.FixedHitRect` 为可选参数，天津垃圾桶使用固定父坐标热区，高亮缩放不扩大丢弃范围。豆浆不属于可丢弃物品。
- 首次提示在成功操作后永久收起；制作按钮、合法目标高亮、悬停说明、短时错误反馈、缺货／补货／火候等实时状态保留。食材库存数字隐藏，面糊和酱料继续无限使用。

## 教学存档

`CityProgressData.LearnedWorkbenchActions` 为可选操作 ID 集合；旧档缺少字段或为 null 时初始化为空，不依据历史天数补写记录。仅天津启用。

记录制作步骤、各食材取用、各有限库存补货、生油条装料、下锅／升篮、三种成品交付、收钱和丢弃。工作台只在成功时发事件，天津页面去重后调用原存档服务；刷新循环不写盘。后续解锁的未学操作继续显示提示。

保存失败不回滚已完成的游戏操作，当前内存保留记录，并通过原反馈条显示错误；后续成功保存会一并持久化。开始新游戏沿用现有存档重置行为，清除教学记忆。

## 尚存问题与边界

1. StageThree 的两项失败均在当前工作区既有武汉结构：武汉页有 3 个未登记的运行期装饰 Control；`WuhanWorkstationGestures.cs` 仍含 `button.Position =` 的补货按钮布局代码，违反场景静态化断言。本轮未扩大范围改写武汉布局；武汉实际输入、交付、动画和结算回归通过。天津新增固定节点已写入场景，通过对应结构检查。
2. Godot 在此环境仍输出根证书存储读取错误；截图进程均正常退出、文件生成成功。部分自测退出有 ObjectDB 实例泄漏警告（最新 V1 专项 3 个，完整 StageFour 33 个），未归零。故障注入测试中的“保存失败”和损坏存档错误为预期输出。
3. 启动页、现有存档服务及截图工具的原有改动保留。武汉 Main 回归已增加真实“继续游戏”入口，并使用 `--dev-ui` 才可见的测试直达武汉按钮。

## 复现

使用 `D:/Godot/GodotSharp/Godot_v4.7.1-stable_mono_win64_console.exe`。先构建 C# 项目，再执行 `tools/capture_tianjin_workbench.ps1` 可输出同一批场景；测试需为每套配置隔离 APPDATA 和可写 `--log-file`。

```powershell
$env:APPDATA = Join-Path (Get-Location) '.tmp/tianjin-v1-userdata'
& 'D:/Godot/GodotSharp/Godot_v4.7.1-stable_mono_win64_console.exe' --headless --path . --log-file .tmp/tianjin-v1.log res://Scenes/Tests/StageFourSelfTest.tscn -- --workbench-v1-only
```
