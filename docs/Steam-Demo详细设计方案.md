# Steam Demo 详细设计方案 v2

更新：2026-09-15。配套：[关卡与经济初值](Steam-Demo关卡与经济初值.md)、[开发计划与验收](Steam-Demo开发计划与验收.md)。

本文件将优化方向细化为可评审、可实现的设计，不是已经完成的功能。用户已确认的原则见第 1 节；具体局数、数值、素材和演出时长仍需按对应评审状态实施。数值未经真人平衡测试，不以“已验证”表述。实施状态以开发计划第 7 节为准；本文件描述目标行为，不代表功能已完成。

## 1. 已确认原则与目标内容

公开试玩以积累愿望单为目标；独立精简路线首轮观察目标 35～50 分钟；简体中文与英文同步；独立存档，首发不承诺继承；主线宽松推进；保留金币购买及升级顺序选择；取消固定上线日期。

本次确认以“亲手制作与逐渐熟练”为主轴。保留天津、武汉和轻量早餐手账，西安只预告；独立挑战、熟客身份、回访剧情与人物小记延期，退出本版必做清单。既有顾客行为类型继续使用，不扩完整图鉴。

天津 7 局、武汉 6 局与原经济表作为原型基线，不锁定最终局数。核心流程为亲手完成、独立安排、购买改善、掌握两城手艺、留下旅行记录；使用主线重玩观察进一步熟练的动机。

首批交付天津教学、T1～T3 以及升级后的 T3 同配置重玩。完整两城扩展须在首批陌生玩家 A／B 验证通过后进行。

## 2. 玩家流程与完成规则

流程：标题与语言 → 新旅程／继续 → 天津准备页 → 必要的首次教学 → 营业 → 保存结算 → 自选升级／下一局 → 天津旅行纪念 → 武汉 → 武汉旅行纪念与西安预告 → 主线回玩／本体商店／反馈。

### 主线推进细则（本次确认）

- 正常走到收摊、至少完成 1 单并成功保存，才解锁下一局；不要求最低收入、满意度或购买某件设备。最后一局满足相同条件后完成对应城市的 Demo 段落。完成单数沿用已有完成订单统计，不另改评价规则。
- 零完成不开放下一局，结算如实显示“本次未完成订单”，满意度显示“—”，不显示 Perfect 或优异成绩章；允许免费重试，重试恢复本局初始资源，不扣入场费。已开放进度不会因重玩零完成而回退。
- 主动放弃、直接退出或存档失败不解锁下一局；重开恢复本局初始食材，不扣取额外入场费。
- 操作教学可以跳过，不把“跳过”记录为“已学会”；可随时在帮助中回看。是否掌握依据实际成功动作。
- 主线保留已有完成顾客、满意度、Perfect、收入等结果，第一版不新增每日星级。不增加独立挑战评级。
- 继续回到待营业的主线准备页，不恢复半局锅内状态。首次完成并成功保存后默认准备新开放的下一局；未结算退出及普通重玩保留所选营业日。主线重玩同样属于主线入口。
- 从天津进入武汉后仍可回访天津；结束页可再次打开，演出可跳过，重复查看不重复发奖励。

### 每局状态与退出

准备 → 可选教学 → 开张 → 营业 → 收摊 → 待保存结果 → 已保存结算 → 准备／城市纪念。

任意时刻失焦取消当前输入并暂停相关时钟。保存失败保留待保存快照，允许重试；确认保存成功前不开放升级购买、下一局或收藏庆祝。中途退出不虚构一次完整结算。

## 3. 两城编排

具体时长、顾客、订单、升级节点见配套初值表。营业计时合计为 25 分钟；现有开张与收摊缓冲最多约 3.9 分钟；首次教学预计另占 5～8 分钟，菜单、升级与短演出约 3～5 分钟。首次体验总时长以真人记录为准，重试与主动暂停单列。

| 局 | 主题 | 新增内容 | 玩家应形成的经验 |
|---|---|---|---|
| T1 | 第一张煎饼 | 基础完整制作与交付 | 我可以亲手完成一单 |
| T2 | 看清这份早餐 | 薄脆图标与配方区别 | 看订单再选料 |
| T3 | 找到自己的顺序 | 葱、已学配料组合；结算开放两种升级 | 我知道自己想先改善什么 |
| T4 | 油条下锅 | 炸油条与普通煎饼交错 | 利用等待时间做另一件事 |
| T5 | 一口酥脆 | 油条夹入煎饼、组合交付 | 区分配料油条与单卖油条 |
| T6 | 先递一杯豆浆 | 豆浆、部分交付、少量短耐心客人 | 先交一部分能争取时间 |
| T7 | 天津的早高峰 | 已有产品综合；没有新增配方 | 我能够掌控这个早餐铺 |
| W1 | 第一碗热干面 | 提篮、沥水、调味、拌面 | 新城市有新的手艺 |
| W2 | 葱香与辣香 | 面的配料变化 | 已学订单判断可以迁移 |
| W3 | 面篮有余地 | 巩固面篮安排；开放煮面升级 | 升级让操作更从容 |
| W4 | 豆皮开锅 | 完整豆皮制作 | 一锅能准备多份出餐 |
| W5 | 双灶配合 | 面与豆皮组合；体验已购升级 | 安排两条制作流程 |
| W6 | 武汉的清晨 | 综合收尾，无新手势 | 我想试试更熟练的做法 |

本版不安排火腿、牛肉和蛋酒的新增教学；这不是从正式版删除内容。尤其当前武汉实际工作台将蛋酒设为未开放，Demo 页面不得沿用旧编号插图而宣称可制作蛋酒。两城主线都保留一次“升级后没有立刻增加更多压力”的练习机会。

## 4. 首次教学与手作反馈

### 教学规则

首次关键机制采用开张前的短教学，复用真实食物和设备状态机，教学上下文不启动正式营业收入、顾客耐心或早餐记录。教学有自己的制作时钟：可继续加热至待操作状态，再在教学等待点冻结，避免冻结所有逻辑后永远等不到成熟。

教学结束或跳过时，清空示例食物、工具、顾客、待交付记录与音效；按本局初始资源重新准备正式营业。初次教学不会赠送一份可带入正式局的成品。再次查看教程使用相同隔离上下文。

一次只说明一个动作，提示不超过两行，贴近当前操作目标；目标外装饰不拦截鼠标。按真实状态完成步骤，不根据按钮点击次数、固定延时或中文反馈字符串判断成功。拖放到无效位置、取消、失焦后仍可继续本步。

| 教学 | 触发 | 步骤与通过条件 |
|---|---|---|
| 基础煎饼 | T1 开张前首次 | 面糊入炉 → 摊开达标 → 加蛋 → 第一面成熟 → 翻面 → 刷酱达标 → 折叠 → 装袋 → 正确交付示例客人 |
| 订单配料 | T2 首次 | 指向订单里的薄脆图标 → 加入需要的配料 → 完成并交付；不改现有图标订单结构 |
| 炸油条 | T4 开张前首次 | 装料 → 下锅 → 观察金黄窗口 → 出锅沥油 → 取熟油条 → 正确交付 |
| 部分交付 | T6 首次 | 豆浆先交给组合订单 → 指示耐心条实际恢复；T5 先用短提示说明组合商品可分别交付 |
| 补货提示 | T3 起首次有限食材不足 | 指向缺料位置 → 长按补货完成后解除提示；沿用真实补货耗时，不额外加资源 |
| 热干面 | W1 开张前首次 | 面入篮 → 熟面提篮 → 沥水与入碗 → 调味 → 拌匀 → 交付 |
| 豆皮 | W4 开张前首次 | 浆入锅 → 蛋液 → 定型 → 上划翻面 → 放馅 → 成熟 → 横竖切块 → 自动入盘 → 交付 |
| 丢弃帮助 | 首次需要清理或主动打开 | 右键长按 0.45 秒后拖入垃圾桶；只丢弃实际投入的单位，仍遵守两城原规则 |

运行中的提示只高亮目标或显示短句，不强制打开全屏说明，不暂停一切只让玩家点“知道了”。若需要体验一个危险操作，先进入明确的教学上下文，不能悄悄改变普通营业耐心。

### 操作体验验收

输入与视觉变化同步；物体位置与有效落点对应；连续手势能看见进展；成功后松手、取消和新动作不会粘连；成熟状态可辨认；错误说明具体且不依赖颜色。沿用现有 Godot 控件与轮廓高亮，不改变已确认订单气泡规则。

## 5. 经营决策、经济与升级

每局最多介绍一个主要新制作机制。普通顾客为主，短耐心顾客在玩家已掌握产品后少量加入。五人上限不变，成功匹配部分交付仍恢复耐心总量 15%，重复或错误交付不恢复。

升级采用原有价格和效果作为第一轮基线：天津配料台 Lv2 60、煎饼炉 Lv2 120、炸锅 Lv2 160；武汉煮面锅 Lv2 220、豆皮锅 Lv2 280。主线仅提供这些二级升级；基础炸锅与豆皮锅仍随教学免费开放一级，这是既有设备解锁方式。

- T3 结算后同时可选配料台与煎饼炉升级；T5 后开放炸锅升级。
- W3 后开放煮面升级；W4 认识豆皮后于结算开放豆皮升级。是否能在 W5 前购买取决于此前支出，购买后保留后续营业来体验收益。
- 武汉备料台继续固定供应，不为 Demo 新增购买接口。
- 全 Demo 共享现有金币口径；初始 0 金币；重玩每次营业收入全额入账，历史最佳仅用于成绩记录；无反复领取教学奖励。
- 任意购买顺序都不成为下一局前置。升级只在准备或已保存结算时购买，当前营业设备不在后台被替换。
- 先用正常服务和存在失误的路径模拟可得性；如价格导致路线缺少成长体验，形成 Demo 价格覆盖方案单独确认，不直接改正式版资源。

配套表含全部订单原价结算且不计小费的收入基线，用于判断升级时机。它不是实际收入预测，也不是含小费总收入的上限，更不证明全部订单都能完成。

## 6. 升级后的同配置重玩

T3 首次结算开放配料台 Lv2 与煎饼炉 Lv2。第一批小包从经营手账选择 T3 再次营业，使用本次实际已购设备；不购买也可重玩。

重玩使用相同 StageId、订单、到达时间、耐心与初始资源规则，库存容量由真实设备等级决定；清空上一局成品与输入。沿用正常开张、收摊和每次营业收入全额入账，不增加第 14 局、独立挑战模式、固定高等级设备或额外奖励。

分别记录首次和升级后重玩的焦糊、补货中断、完成情况、提示依赖与安排变化。操作熟练也可能改善结果，因此同时询问玩家感受到的具体设备作用，不把差异全部归因于升级。

低收入玩家可以继续和重玩；不能为完成验证暗赠金币或自动升级。余额不足时记录成长体验缺口，按经济表的调参顺序处理。

## 7. 早餐旅行手账

复用现有“经营手账”入口，在书内切换“营业记录／旅途收藏”；收藏仅展示早餐与城市旅行记录。保持现有共享双页几何和三处主要书签，不另建平行首页。主操作仍为开张，经营手账提供已开放主线的重玩入口。

第一版早餐卡为煎饼果子、油条、豆浆、热干面、三鲜豆皮共 5 张；配料变体不单独占卡，豆浆标注“供应记录”，避免宣称玩家制作了现成饮品。

解锁提案：正式 Demo 主线中成功交付与订单匹配的该类商品，且商品达到正常或更好品质，生成本局待解锁标识；正常收摊成功保存后生效。部分交付可以满足该商品条件，不必等待其他商品交齐。教学、失败交付、错配料、未售出的成品和主动放弃不解锁。实现需读取交付商品的品质及匹配结果，不能只看总订单是否结束。

品质映射提案如下，需要在 B09 实施前确认。这里判断成品质地，不要求整单获得 Perfect 评价；顾客等久后才拿到正常食物，仍可收录早餐。

| 早餐卡 | 现有字段上的合格条件提案 | 卡片重点 |
|---|---|---|
| 煎饼果子 | PancakeQuality.Perfect；油条配方还要求内部油条为 Golden | 摊开、翻面、刷酱、折叠的手作过程；所有配方共一张 |
| 油条 | YoutiaoQuality.Golden，作为单卖商品正确交付 | 金黄出锅与沥油；夹入煎饼不代替单卖记录 |
| 豆浆 | 实际接受并消耗一杯订单所需豆浆 | “供应记录”，介绍如何搭配交付，不虚构制作步骤 |
| 热干面 | 已拌匀 MixedComplete，且没有 NoodlesSoft／NoodlesOvercooked | 提篮、沥水、调味、拌面 |
| 三鲜豆皮 | 可交付的熟豆皮，且没有 DoupiOverbrowned | 一锅成形、切块与分份出餐 |

品质缺失或无法判断时不默认合格；从真实食物状态补齐事件数据。界面只向玩家说明“正确送出一份火候合适的早餐”，不展示内部枚举。

卡片内容：中英名称、所属城市、已有插图、一句介绍、关键制作步骤或供应说明、首次获得的 Demo 营业日。重复交付不弹重复庆祝，暂不增加熟练度条或额外属性。

收藏页默认展示已经获得的记录及本城可获得内容；未到武汉时使用简短的下一站提示，不铺开全五城问号。不增加人物页、人物小记或熟练度进度。通关时没有集齐不视为失败，收藏入口明确允许回访补齐。

营业中最多一次轻提示，不抢焦点；详细卡片在结算“本次新记录”或玩家主动打开时查看。结算失败先显示未保存，不能提前盖永久收藏章。两城总结使用真实成绩，准确区分“最高收入那次的满意度”和独立最高满意度。

## 8. 延期内容与顾客行为

独立挑战、固定设备成绩、8 位人物／18 次指定出场、回访剧情、人物小记和好感度均延期。公开 Demo 不出现相关占位入口，不为这些系统预建数据与角色外观约束。

继续使用现有普通、上班族、熟客等行为类型及已有画像。regular 只表示现有顾客行为，不能据此宣称拥有稳定身份或人物关系。主线不同耐心的出现位置保留在关卡表中。

后续根据主线自愿重玩与记忆观察另行评审；延期项不作为本版质量与发布依赖。

## 9. 声音、演出与双语

声音分层：Music 配乐、Cooking 制作质感、Business 共享经营提示、UI 书页与导航；后面三者可以复用 Effects 总线及现有播放器，不要求先重建音频架构。现有经营音效语义、次数和暂停规则全部沿用。

配乐候选：通用首页一段、天津一段、武汉一段，建议各具备 90～150 秒自然循环素材；风格、来源及授权信息在选定时确认。第一次做一小段听感样本，和实际高峰混播后再制作完整曲目。业务提示不能被音乐遮盖，耳机与扬声器都试听。

配乐行为提案：主菜单播放首页曲；进入城市准备页切该城曲并与营业连续；手动暂停或查看明细时配乐减弱，营业音效停止；失焦时所有音频暂停；离城淡出切换。恢复不补播营业音效。具体淡变与音量以听感定稿，不能用声音数量代替反馈质量。

开张沿用已有短开门缓冲；收摊账本动效允许点击跳过。天津完成复用盖章路线进入武汉；武汉结尾约 10～20 秒且可跳过：两城真实成果 → 武汉印章 → 西安已有明信片及早餐预告 → 本体商店／反馈／继续游玩。重复查看不重复奖励。

双语范围包括所有 Demo 可达菜单、食物与设备、教学、关卡目标、早餐记录、设置、帮助、保存错误、退出确认和结尾。少／多酱等图片中文字单独处理，保留已确认的订单信息密度。先建立字符串键与参数化文案，再排版；食物英文名称和产品英文名需校对，不默认自创品牌译名。

## 10. 失败、暂停与记录的一致性

- 同屏上限、耐心恢复、满意度分母、小费舍入、自动收银、丢弃单位维持项目已确认规则。
- 教学与主线两种运行上下文分别定义计时、资源和保存范围；T3 重玩属于主线，不增设挑战模式。
- 主线的金币、成绩、解锁和早餐记录在一次保存事务中提交。失败回滚全部永久变化，保留可重试结果；重试相同结算不重复支付。
- 当前局的逐单评价保留到离开结算所需时刻，随后清理，不写入长期存档。主线历史最佳只保存汇总，不带逐单明细。
- 查看明细不会放开其他暂停原因；退出教程、丢失焦点、切语言和返回地图都要清理未结束的拖拽与工具持有状态。
- 公开 Demo 所有入口统一限制范围，旧档中存在西安完成记录也不能进入西安。开发命令行不能在公开包中解除范围限制。

## 11. 质量判断与评审状态

本版已确认的范围、实施顺序和验收门槛见方向总览与开发计划；原型局数、经济初值不是已验证的玩法结果。旧版“挑战、手账、熟客全部纳入”的范围由本次选择取代。

首份教学观察 5 人，至少 4 人无需口头指导完成；安排与成长观察至少 3／5 人主动使用一种安排、4／5 人理解所选升级，并保留首次与重玩行为记录。完整两城另外邀请 5～8 人记录时长、退出、疲劳与差异。

两城 35～50 分钟是观察目标，不通过重复教学或不可跳过演出来凑。既有升级功能只能证明存在，不能证明玩家已经感到成长。没有实际视口、试听、导出和真人证据时标为待验证。

零完成不推进、至少完成 1 单并成功收摊保存才推进已于本次确认。早餐品质映射及具体音频／英文文案按对应功能评审，不从方向批准推定所有旧细则已获确认。实施与测试状态统一记录于开发计划第 7 节。
