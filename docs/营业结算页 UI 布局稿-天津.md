# 《营业结算页 UI 布局稿（天津首版）》

## 一、页面定位

这页不再叫单纯的“本次营业明细”，而定义为：

> **营业结束后的「收摊账本」**

玩家的阅读顺序固定为：

**今天赚了多少 → 今天经营得怎么样 → 哪里出了问题 → 有没有奖励/成长 → 收好账本进入下一阶段**

同时拆成两个页签：

**① 今日小结**：默认打开，负责情绪反馈和经营总结。
**② 顾客明细**：需要复盘时才查看，负责逐单信息。

不建议再把十几位顾客的订单默认铺满第一页。

# 三、背景层

## 1. 游戏背景

不要完全切换成一个纯色系统界面。

建议仍然隐约看到刚刚营业的早餐铺背景，但：

* 整体暗化约 **35%～45%**
* 稍微降低饱和度
* **不需要模糊**
* 禁止做现代软件式毛玻璃

效果应该像：

> 玩家刚刚收摊，在店里打开一本账本。

而不是：

> 游戏弹出了统计后台。

# 十四、“今日手记”不要随机写

建议直接用经营数据规则驱动。

例如：

### 完成率低 + 满意度高

> **味道不错，就是让客人等太久啦。**

正好适用于当前 Day 15。

### 完成率高 + 满意度低

> **今天出餐挺快，不过味道还得再稳一些。**

### 完成率高 + 满意度高

> **今天又快又稳，街坊们都吃得很满意！**

### 流失为0

> **今天每位客人都吃上早餐啦！**

### Perfect很多

> **今天出了好几份漂亮的早餐！**

这套文本其实比再加三个统计指标更有价值。

---

# 十五、成长 / 解锁信息不要长期占据固定区域

例如：

> 可升级煎饼炉
> 解锁新顾客
> 新菜品加入

采用：

### 条件式小贴纸

直接贴在账本边缘。

例如右下角：

```text
┌──────────────┐
│ ⭐ 有设备可以升级 │
└──────────────┘
```

有内容才显示。

没有升级 / 解锁时，整个区域消失。

这样避免每日页面越来越拥挤。

# 二十三、彻底删除这些重复句子

例如现在：

> 顾客未完成订单离开，不计入满意度。

不需要在**每一位顾客**下面重复。

只需要在页面底部放一个：

`ⓘ`

点击/悬停后显示：

> 离店顾客不计入完成顾客满意度。

同理删除：

> 订单正确完成。

因为已经有：

✓ 顺利完成

信息完全重复。

# 三十四、最终建议锁定版

天津首版结算页面建议正式确定为：

### 默认页「今日小结」

左页：

**今日收入 → 收入构成 → 今日热销**

右页：

**接待情况 → 完成顾客满意度 → Perfect → 今日手记**

底部：

**收好账本**

顶部标签：

**今日小结 / 顾客明细**

---

### 第二页「顾客明细」

左页：

**顾客 + 点单**

右页：

**结果 + 收入 + 评分 + 错误原因**

采用：

**同行对照式账本结构**

而不是继续使用现在的大尺寸系统卡片。

---

我认为这套结构最关键的变化是：**不是给现有“营业明细窗口”做美化，而是彻底把它转化成游戏循环中的“收摊记账”动作。** 这样即使实际统计数据一项都没有增加，模拟经营感也会明显比当前版本更强。
