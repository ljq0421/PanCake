## 问题与解决

| 问题 | 影响 | 本次处理 |
| --- | --- | --- |
| 顾客以全身小人站在街面，人物比例与柜台视角脱节 | 表情难读，缺少面对顾客营业的感觉 | 使用天津同款 CounterHalfBody，人物在柜台边裁切，下半身位于柜台后方 |
| 煮面锅、豆皮锅、蛋酒机偏大，锅面越过顾客耐心条 | 工作台拥挤，设备遮挡经营信息 | 缩小三档设备，按台面重新定位；显示与输入共用几何坐标 |
| 底部大按钮承担绝大多数制作步骤 | 玩家在看按钮状态，实物像装饰 | 移除底部制作按钮，改成拖拽、提起、划动操作，保留状态对应的短提示 |
| 订单卡过宽、耐心条远离订单且被设备挡住 | 读单与判断紧迫程度需要来回扫视 | 收窄顾客区，把耐心条收入对应订单卡，保留逐商品交付数量 |
| 底部浅色出餐说明贴边 | 难辨认、容易与桌沿混在一起 | 使用墨绿文字和浅色描边，提示留在台面安全范围；双勺状态分两行并避开原料补货 |
| 配料数量只在按钮上，操作与物品相隔较远 | 不容易知道库存属于哪个容器 | 将配料名称、数量放到各自容器旁；备餐数量放到托盘下方 |
| 低库存时无效加料点击会自动开始补货 | 同一次点击的含义不稳定 | 取消这种隐式补货，新增独立“补”入口，满库存隐藏、补货期间禁用并显示进度状态 |
| 拖动制作原料可能误投、取消或遇到设备状态变化 | 容易造成错误扣料或错转生产步骤 | 松手时重新验证来源、目标、设备状态与容量；无效操作保留库存和食物，给出具体提示 |

## 上一轮操作（历史记录）

- 热干面：拖生面到空漏勺 → 最佳火候时向上提起 → 上下抖水或等自然沥干 → 拖漏勺到空碗 → 点击酱罐和小料 → 在碗口划动拌匀 → 松手，再拖整碗给顾客。
- 豆皮：点击浆碗浇浆 → 点击锅面加蛋 → 按住锅面上划翻面 → 点击馅碗铺馅 → 煎熟后在锅面划四刀，每刀松手 → 拖锅内豆皮到备餐盘 → 从盘里逐块拖给顾客。焦糊后点击锅面清理。
- 蛋酒：拖底料杯到出水嘴下 → 等待冲泡 → 拖成品杯给顾客。杯旁“补”只补充底料。
- 补货：点击对应容器旁的“补”。没有制作或交付动作会代替该入口。
- Esc、失焦、暂停、隐藏或重开取消未提交的制作手势；原料扣除和入盘都在合法操作提交时发生一次。

提篮需向上移动至少 38 个设计像素，翻面至少 40；划刀需在锅面内形成至少 42 像素的近似直线，短点不算一刀。抖水需上下累计至少 90 像素并回到锅上方。目标区有宽松容差，不要求沿预制刀缝精准描画。升级的自动提篮、锁熟、自动翻面继续由原有设备规则触发。

## 实现与边界

`WuhanDayScreen` 管理顾客、状态提示和制作提交；`WuhanWorkstationView` 及其 `WuhanWorkstationGestures` 分部管理实物几何、手势输入、跟随预览、落点提示和补货控件。成品交付继续使用已有 DragService。

本次复用现有 PNG，没有生成或修改美术源图。配方、生产耗时、经济、耐心、存档、设备升级规则不变。手势的连续经营舒适度属于主观体验，需实际试玩评价；自动测试不等同于玩家手感验证。
