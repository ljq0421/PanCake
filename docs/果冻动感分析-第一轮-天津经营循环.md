**第一轮建议把天津六种配料做出六种不同的“材质手感”，而不是给它们套同一个果冻动画。**

最值得建立的区别是：

> **面糊黏、蛋液软、酱料顺、香葱轻、薄脆硬、火腿有弹性。**

下面沿用你此前已经实现的操作：**面糊拖入后摊开；鸡蛋、香葱点击；薄脆、火腿拖入；酱料按住划动。**这轮先不改变操作方式，也不增加新的操作次数。

我也整理了对应的两个 Godot C# 表现组件，放在文末：一个负责食材移动与落稳，一个负责沿笔尖轨迹显示酱料。

---

## 一、先统一这一轮的动效规则

### 动的是“一份食物”，不是整个配料台

每次操作，建议按这个顺序表现：

**来源有回应 → 单份食材离开 → 到达煎饼 → 按材质落稳 → 留在饼上。**

其中，托盘、碗和工作台应该稳定。悬停时延续你已经确定的高亮规范，最多让被选中的食材轻轻抬起，不让整个托盘一起弹。

你现有托盘规范中的 **5°、8°是画进素材的纵深透视偏角，不是让整个托盘旋转的角度**。这轮动效不要破坏它。

### 六种配料的动作总表

下表中的参数是**第一轮调参起点**，不是已经在项目中验证过的最佳值。像素指 **1920×1080 设计画面中的显示尺寸**，不是原始 PNG 的像素。

| 配料 | 最重要的视觉动作        | 果冻感放在哪里         | 不应该做什么           |
| -- | --------------- | --------------- | ---------------- |
| 面糊 | 从勺子落下一小滩，再随操作摊开 | 刚落下的面糊边缘轻微铺展    | 整个面糊碗弹跳、面糊像球一样反弹 |
| 鸡蛋 | 蛋壳分开，蛋液落下并铺开    | 蛋液的小幅扩张与收住      | 整颗鸡蛋砸到饼上弹起来      |
| 酱料 | 刷头经过哪里，哪里出现酱料   | 刷毛轻压，笔画末端轻微收住   | 点击后自动播放完整刷酱动画    |
| 香葱 | 一小撮散成数个小颗粒，错开落下 | 少量颗粒极轻的落稳       | 整团绿色素材像布丁一样弹     |
| 薄脆 | 吸附摆正，轻轻落稳       | 主要用约 1～2 px 的位移 | 明显拉伸、投放时碎裂       |
| 火腿 | 轻轻压扁，再贴合饼面      | 约 4%～5% 的短暂形变   | 持续扭动、反复跳离饼面      |

**动效时长不等于操作锁定时长。**玩家已经成功加入一种配料后，应该能继续操作；配料可以在视觉上完成最后一点回弹。

## 二、六种配料分别怎么设计

### 1. 面糊：重点是“黏稠地落下”，不是“弹一下”

#### 玩家应该看到什么

拖出面糊时，鼠标带走的是**一勺面糊的操作表现**，不是把整个碗拿走。

到达炉面、松手以后：

**勺子稍微倾斜 → 一小段面糊落下 → 炉面出现一小滩面糊 → 勺子退出 → 玩家继续摊开。**

最重要的是最后一句：**刚倒下时只能是一小滩，不能顺便自动变成完整煎饼。**

#### 建议动作参数

拖拽过程中，勺子位置直接跟随鼠标，只给视觉层增加很小的倾斜，控制在约 **±3°**，不要用位置延迟制造“黏”。

合法松手以后，可以先试这一组：

```text
0.00～0.07 秒：勺子向出料方向倾斜约 15°～20°
0.05～0.14 秒：出现短小的面糊液流
0.08～0.20 秒：中心小面糊滩展开到目标大小
0.16～0.24 秒：勺子退出，液流消失
```

这些动作有重叠，不是全部依次等待。

面糊滩可以从相对最终小滩尺寸的 `0.75` 增长到 `1.02`，再收回 `1.00`。这里表现的是“摊开”，**不是把整张煎饼做强烈的横竖挤压**。

#### Godot 实现方式

建议分成独立的勺子、液流、初始面糊滩、摊开后的基础层。

勺子用旋转 Tween；液流用一张短液流 PNG 控制显隐和长度；小面糊滩用缩放或显现动画。**第一轮不需要流体模拟。**

进入摊饼操作以后，刮板位置与面糊变化由当前输入和制作进度驱动。Tween 只负责完成时很短的整理动作，不负责替玩家摊完整张饼。

同时继续保持你此前的规则：**面糊不限库存，这轮不加入碗内液面下降或补货动画。**

**声音建议：**短促、柔和的“倒入”声，加上接触炉面时很轻的滋啦声；不要配成“啵”的弹球声。

---

### 2. 鸡蛋：蛋壳是硬的，蛋液才是软的

#### 玩家应该看到什么

点击鸡蛋以后，建议表现为：

**单个鸡蛋离开托盘 → 移动到饼面上方 → 蛋壳分开 → 蛋液落下 → 蛋壳在上方退出。**

不要让整颗鸡蛋先砸到饼上，再变成蛋液。那样更像投掷一个物体，而不是打蛋。

#### 建议动作参数

```text
0.00～0.14 秒：鸡蛋快速移至饼面上方
0.12～0.20 秒：蛋壳分开，左右各偏移少量距离
0.17～0.28 秒：蛋液落下、铺开
0.24～0.32 秒：蛋壳淡出，蛋液收住
```

蛋壳两半可以分别向外移动约 **8～14 px**，旋转约 **10°～15°**。退出方向保持在饼面上方，不让蛋壳看起来掉进食物里。

蛋液落下时，可以有约 **3%～5%** 的轻微扩张；随后进入你已有的加蛋结果层。

**若当前素材入口已经改成蛋液，保留“落下—铺开—收住”这半段即可，不需要为了动效重新增加整蛋。**

#### Godot 实现方式

这一项不要强求“一张图从头演到尾”。建议在接近饼面时做一次素材切换：

```text
完整鸡蛋
    ↓
左半蛋壳 + 右半蛋壳 + 蛋液层
    ↓
已有的煎饼加蛋结果层
```

移动阶段可以共用食材路径组件；壳分离和蛋液显现用一个短 Tween 序列即可。

整个动画不应增加第二次点击，也不应擅自新增“再摊一次蛋液”的玩法。**是否还有摊蛋步骤，继续由当前制作流程决定。**

**声音建议：**一次清楚但不尖锐的“咔”，随后一点轻微的滋啦声。声音重点落在壳分开、蛋液接触的时刻。

---

### 3. 酱料：这一项最值得做成“真正跟手”

在六种配料中，**我最建议认真打磨的是刷酱**。它很适合让玩家感受到“这是我亲手做出来的”，而不仅仅是触发一次动画。

#### 玩家应该看到什么

**按住鼠标 → 刷头接触饼面 → 随着划动留下酱料 → 松手停止。**

刷头走到左边，左边出现酱料；刷头还没有经过的地方，不应该提前出现完整酱料。

不要做成：

```text
玩家随便划一下
→ 自动播放固定的左右刷动
→ 整张饼完成上酱
```

#### 建议动作参数

刷头位置直接跟随操作点，不增加明显的位置滞后。

按下时，可以只把刷毛部分轻压约 **3%～4%**，松开后在约 **0.08 秒**内恢复。刷柄保持硬，碗保持稳定。

移动方向改变时，刷柄允许有轻微倾斜，但不要不断大角度摆动。**有条件时只动刷毛；暂时只有整张刷子 PNG 时，以小幅旋转代替整把刷子的挤压。**

#### Godot 实现方式：显示已有的酱料图，而不是重新画一种画风

最适合你现有素材的第一版方案是：

**已有最终酱料覆盖图 + 一张记录刷过位置的遮罩。**

遮罩开始全黑，表示完全隐藏；刷头经过的位置画成白色，对应酱料就显现出来。

这样最终酱料仍然是你原本的卡通 PNG，不会因为程序画线变成另一种美术风格。Godot 的 CanvasItem Shader 可以利用纹理采样控制透明度，适合这种显现方式。([Godot Engine documentation][1])

第一版建议采用 **256×256 的遮罩**，食物 PNG 本身仍保持原分辨率。

这里有两个必须处理的细节：

**快速划动不能断线。**不要只在鼠标事件位置画一个圆，而要在前后采样点之间补画路径。

**抬笔以后不能继续连接旧路径。**松开鼠标、离开饼面、暂停或切换阶段时，清掉上一笔的位置，否则下一次按下会突然出现一条横跨饼面的酱料。

遮罩改变时更新已有纹理，不要每画一笔就新建一张纹理。Godot 的 `ImageTexture.Update()` 就是用于更新既有纹理数据的接口，尺寸和格式需要保持一致。([Godot Engine documentation][2])

**制作完成条件继续使用现有规则。**这轮先改善轨迹反馈，不顺手提高覆盖率要求，也不增加反复蘸酱操作。

**声音建议：**只有刷头实际接触并移动时才有轻柔的刷涂声；按住不动时，不要持续高音量播放。

---

### 4. 香葱：重点是“一小撮散开”，不是“一大团变形”

#### 玩家应该看到什么

点击香葱以后：

**一小撮香葱离开来源 → 到达饼面上方 → 散成几片 → 错开一点时间落下 → 留在饼上。**

它应该是六种配料里最轻、最灵巧的一种。

#### 建议动作参数

第一轮建议显示约 **8～12 个有辨识度的小葱段或叶片**。这是视觉数量，不是库存数量。

可以把它们分为两三小批，落下时间错开约 **0.015～0.03 秒**，整段撒料控制在约 **0.22～0.30 秒**。

每片旋转略有不同即可，不需要飞舞几圈。落地以后，少数颗粒轻动约 **1 px** 就够了，其余直接停住。

不要让每片葱花都产生闪光，也不要同时让整张饼跟着弹。

#### Godot 实现方式

第一轮更建议使用少量独立 `Sprite2D`，而不是先上复杂粒子系统。

原因是这些香葱不只是特效，**它们还要作为最终配料留在饼上**。

提前在饼面内配置若干落点锚点，再给每次撒料加入小幅随机偏移。落点要检查食材实际边界，不能只保证中心在饼内、边缘却飞出饼外。

这里有一个容易忽略的问题：

> **落下的小葱段，最好直接就是最终留在饼上的小葱段。**

不要先让十片葱落在 A 位置，然后突然切换成另一张分布完全不同的“加葱完成图”。这个跳变会抵消刚刚建立的连续感。

这轮也不需要借机增加香葱库存玩法。

**声音建议：**一次轻、短的撒料声即可。不要给每片葱分别播放声音。

---

### 5. 薄脆：用“硬质落稳”，不要做成果冻

#### 玩家应该看到什么

薄脆被拖出来时，形状保持硬挺。

松手进入有效目标区后：

**快速吸附到放置位 → 角度摆正 → 接触饼面 → 极小幅度地落稳。**

它的可爱感来自“小巧、干脆、准确”，而不是软。

#### 建议动作参数

拿起时，单份薄脆可以放大约 **2%～3%**，表示离开台面。拖动过程保持跟手，视觉倾斜控制在约 **±3°**。

有效松手后：

```text
约 0.08～0.12 秒：吸附到放置位置，同时摆正
接触后：保持形状，轻微上移约 1～2 px，再落定
```

**第一版直接把挤压强度设为 0。**

你之后觉得太硬，再尝试极轻的形变，而不是一开始就使用明显的横宽竖扁。

#### Godot 实现方式

共用“食材移动与落稳”组件即可，主要参数是：

```text
短吸附路径
形变强度 = 0
落稳位移 ≈ 2 px
最终角度 = 已配置的放置角度
```

薄脆不要在投放时裂开，也不必掉碎屑。那会让人误以为放坏了，或者引入新的损坏含义。

**声音建议：**偏干、偏轻的接触声。不要用明显的“咔嚓碎裂声”。

---

### 6. 火腿：这是最适合做轻果冻的一项

#### 玩家应该看到什么

火腿拖入时保持清楚的轮廓。

落到饼上以后：

**短吸附 → 轻轻压扁 → 小幅恢复 → 贴住饼面。**

与薄脆最大的区别是：**火腿的轮廓可以有一点软，落下以后不再明显跳离饼面。**

#### 建议动作参数

拖拽拿起时放大约 **3%**。松手吸附约 **0.10～0.12 秒**。

接触之后，可以先试这组相对缩放：

```text
正常：       (1.000, 1.000)
轻压：       (1.045, 0.957)
轻回弹：     (0.980, 1.020)
恢复：       (1.000, 1.000)
```

落稳尾段约 **0.18 秒**。

这个幅度足以和薄脆区分，又不至于把火腿变成橡皮玩具。

#### Godot 实现方式

仍然共用薄脆的组件，只调整材质参数：

```text
形变强度 ≈ 0.045
落稳位移 = 0
```

不需要立刻给火腿制作骨骼或网格变形。**第一轮用整张食物 PNG 的轻微缩放，就值得先做对比测试。**

**声音建议：**很轻的、偏柔的落下声，和薄脆的干硬接触声区分开。

---

## 三、程序结构：来源、移动份额、饼上配料必须分开

建议不要直接拿托盘里的库存节点一路移动到饼上，同时又让它负责库存显示。

第一轮可以分成下面三部分：

```text
IngredientStation                    配料来源
├── ContainerSprite                  托盘或碗，保持稳定
├── StockContents                    来源内容物
├── PickAnchor                       取料表现的起点
└── InteractionArea                  固定的交互范围

PancakeRoot                          当前这一张煎饼
├── BaseLayer
├── EggLayer
├── SauceLayer
├── FillingsRoot
│   ├── 薄脆份额
│   ├── 火腿份额
│   └── 香葱颗粒
└── PlacementAnchors                 预先配置的落点

每个需要移动的单份食材
└── PortionRoot                      管理路径位置
    └── Visual                       管理形变、倾斜
        └── Sprite2D                 食物贴图
```

这样，来源负责“还剩多少”，单份食材负责“这次正在拿哪一份”，煎饼负责“已经加了什么”。

**命中区不要挂到果冻形变层下面。**否则视觉压扁时，点击范围也可能跟着变化。

### 坐标要转换，不要硬写某个屏幕位置

配料与落点不一定有相同父节点。因此，不要直接把目标的局部 `Position` 赋给正在移动的食材。

在同一 Canvas 坐标系下，先把目标全局位置转换到食材父节点的局部坐标。Godot 的 `Node2D.ToLocal()` 用于这种转换。([Godot Engine documentation][3])

示例组件的调用方式是：

```csharp
// portion：当前这一份食材的 IngredientMotion2D。
// slot：在饼面上预先配置的落点 Marker2D。
Node2D parent = (Node2D)portion.GetParent();
Vector2 target = parent.ToLocal(slot.GlobalPosition);

// 薄脆：不挤压，落稳时轻跳 2 个设计像素。
portion.PlayPlacement(
    target,
    travelSeconds: 0.10,
    arcHeight: 4.0f,
    squash: 0.0f,
    reboundHeight: 2.0f
);
```

火腿使用同一个组件，只改参数：

```csharp
portion.PlayPlacement(
    target,
    travelSeconds: 0.11,
    arcHeight: 6.0f,
    squash: 0.045f,
    reboundHeight: 0.0f
);
```

这是两种食材的不同调用示例，不是让同一个实例连续播放两次。

组件内部采用 `TweenMethod()` 更新短弧线路径，用 `TweenProperty()` 处理落稳。每次重播创建新 Tween，避免多个 Tween 同时争抢同一属性；这些用法与 Godot 官方 Tween 接口一致。([Godot Engine documentation][4])

## 四、刷酱的实现要点：让现有素材沿轨迹显现

我提供的第二个组件是 `BrushReveal2D`，挂在酱料覆盖层的 `Sprite2D` 上。

运行时，只在现有控制器判断“允许刷酱、鼠标按住、刷头接触有效饼面”时调用：

```csharp
sauceReveal.PaintAtGlobal(brushTip.GlobalPosition);
```

松开、越出饼面或切换阶段时调用：

```csharp
sauceReveal.EndStroke();
```

开始新煎饼时清空：

```csharp
sauceReveal.ResetReveal();
```

组件负责沿途补采样、更新遮罩，**不负责判断配方或刷酱是否完成**。

Shader 的关键逻辑很短：

```glsl
shader_type canvas_item;
render_mode unshaded;

uniform sampler2D reveal_mask : filter_linear, repeat_disable;
uniform float complete_reveal : hint_range(0.0, 1.0) = 0.0;

void fragment() {
    float painted = texture(reveal_mask, UV).r;
    COLOR.a *= mix(painted, 1.0, complete_reveal);
}
```

这里保留原贴图颜色，只根据遮罩改变透明度。主贴图本身的透明边界仍然生效，所以酱料素材首先就应当画在正确的饼面范围内。([Godot Engine documentation][1])

**每张饼必须有独立的遮罩和对应材质参数。**共享同一个 `ShaderMaterial` 再直接修改参数，可能导致其他实例一起变化；Godot 官方也明确说明了共享材质参数的作用范围。示例中为每个实例创建独立材质。([Godot Engine documentation][5])

面糊摊开的局部显现也可以借用这一思路，但不建议第一轮把摊面糊和刷酱做成完全相同的视觉：**面糊强调中心向外铺开，酱料强调笔尖走过的轨迹。**

## 五、这一轮必须一起解决的三个问题

### 1. 玩家连续点击，不能重复扣料

不能以“动画还没播完，所以配料还没加入”作为业务判断。

建议顺序是：

```text
收到操作
→ 检查当前制作阶段、库存、重复添加规则
→ 接受操作，记录配料并提交库存变化
→ 播放这一份食材的表现
```

点击鸡蛋或香葱被接受后，业务状态已经变化；下一次点击应按原规则检查，而不是等视觉落地以后才检查。

有库存的拖拽食材，可以在拿起时预留一份，取消时释放预留，有效投放时提交消耗。这样拿起、取消和快速连续操作之间不容易出现库存复制或丢失。

同时继续保持：**库存不显示数字，面糊和酱料不增加消耗逻辑。**

### 2. 玩家立即折叠，不能等所有配料慢慢落地

例如：

**点香葱 → 放火腿 → 马上折叠。**

这时，不应该因为葱花动画还在空中，就让折叠按钮失效。

建议折叠被原有规则接受时，将当前煎饼已经接受的配料表现**立即推进到终态**，然后开始折叠：

```csharp
portion.FinishImmediately();
```

这个快进只整理视觉，不重新扣库存、不重新添加配料，也不补播一堆过时的音效。

同样，丢弃旧煎饼以后，旧配料的飞行动画不能晚到一步又加进新煎饼。所有表现都要归属于某一张明确的煎饼，切换时取消旧表现。

### 3. “允许投放”不等于“符合顾客订单”

这轮不要为了表现流畅，顺手把所有错误配料都自动弹回托盘。

**无效操作**，例如当前阶段不能投放、投到非目标区，可以返回来源。

**规则允许加入、但不符合顾客订单的配料**，仍按你原来的错配料规则处理。否则加入动效时，会不知不觉改变游戏难度和判断空间。

## 六、美术需要补什么？先补拆层，不要重画整套

优先检查现有素材是否已经能拆开使用。建议按下面这张表补缺：

| 配料 | 最小素材准备                      | 第一轮暂不需要       |
| -- | --------------------------- | ------------- |
| 面糊 | 独立勺子、中心小面糊滩；短液流可单独补一张       | 多帧流体动画、整碗液面变化 |
| 鸡蛋 | 单个完整蛋、左右半壳、独立蛋液；已有的蛋液版可省略蛋壳 | 完整角色手部打蛋动画    |
| 酱料 | 独立刷子、与饼对齐的透明酱料覆盖图           | 每个刷酱进度一张 PNG  |
| 香葱 | 2～3 种简洁葱段或叶片，程序复用           | 十几张不同撒料帧      |
| 薄脆 | 一份独立薄脆、清楚的放置锚点              | 专门的果冻形变帧、碎裂动画 |
| 火腿 | 一份独立火腿、清楚的放置锚点              | 骨骼、网格、复杂软体效果  |

**不要把投放路径、阴影和动态效果烘焙进托盘背景。**静态画面继续保持干净，动作由独立层产生。

## 七、这一轮的实际落地顺序

我建议先用**薄脆和火腿**建立对比：它们可以共用一个组件，却应该让人明显感觉到一个硬、一个软。这个对比成立，说明你的动效系统不是简单地让所有东西“弹一下”。

接着做**香葱**，验证分散落点、最终留存，以及快速加料后立即折叠的处理。

然后优先打磨**刷酱跟手显现**，最后接入**面糊倾倒、鸡蛋变化**。这样先解决最通用的移动与状态同步，再处理工具和素材切换。

验收时，重点不是“单独播放好不好看”，而是实际连续做一张煎饼：

**快速加料、马上折叠、拖出后取消、刷到一半松手、暂停后继续、丢弃后重做。**这些情况下都跟手、状态正确，动效才真正为经营服务。
