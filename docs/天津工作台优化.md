这 4 个问题基本不是单独的素材问题，而是同一个根因：**目前页面缺少统一的“工作台槽位坐标体系 + 素材视觉尺寸规范”**。如果继续逐个 Sprite 调坐标，武汉章节之后还会重复出现。

我建议这次直接做一次天津页面的**布局收口**。

### 1. 生油条明显大于盘子

当前左侧生油条是最明显的比例错误：油条不仅超出托盘，而且已经产生“油条放在托盘前面”的视觉关系。

建议不要只改当前位置，建立统一规则：

**托盘内食材视觉尺寸 = 托盘内部有效区域的 65%～80%。**

以当前这个生油条托盘为例，建议：

- 油条整体缩小约 **30%～40%**
- 两根油条继续保留，但靠拢一些
- 整体中心严格对齐托盘中心
- 四周至少留 **8～12 px视觉安全边距**
- 点击区域可以比图片大，但图片本身不能越界

最终应该类似：

```text
┌────────────┐
│            │
│   ╱╱ ╱╱    │
│            │
└────────────┘
```

而不是现在：

```text
    ╱╱
   ╱╱
┌────────┐
│        │
└────────┘
```

Godot 里不要再直接：

```gdscript
ingredient.position = some_global_position
```

而是让它成为槽位子节点：

```text
RawYoutiaoSlot
├─ Tray
├─ IngredientAnchor
│  └─ RawYoutiao
└─ ClickArea
```

`RawYoutiao.position = Vector2.ZERO`，以后只调 `IngredientAnchor`。

### 2. 顾客和工作台之间的空白过大

这是目前页面第二明显的问题。

现在视觉结构是：

```text
订单
顾客
────────────────
        大量空白
────────────────
工作台
```

玩家的视线实际上被分成了两个页面：

**上面是顾客系统，下面是做饭系统。**

经营游戏应该更接近：

```text
订单
顾客
──────柜台──────
工作台操作区
```

建议把中间空白区域压缩 **约 45%～60%**。

最优方案不是单纯把顾客放大，而是：

**顾客区整体下移约 45～70 px，同时工作台视觉上沿适当上提约 20～30 px。**

最终让：

> 顾客身体底部 → 工作台上沿

只保留大约 **40～60 px** 的视觉缓冲。

尤其可以让顾客下半身稍微被柜台遮挡，这反而会更像“顾客站在早餐铺柜台前”。

目前：

```text
🙂

           ← 空
           ← 空

=================
       锅
```

建议：

```text
🙂
🙂
────柜台────
   锅 / 食材
```

这样还有一个很大的好处：

**玩家眼睛从订单 → 顾客 → 工作台，是连续向下移动的。**

---

### 3. 出餐 / 豆浆 / 丢弃应该进入工作台

这一块现在确实处于最尴尬的位置。

它既不像顾客区域，也不像工作台区域：

```text
顾客区
──────────
       [出餐][豆浆][补料][垃圾桶]
──────────
工作台
```

尤其垃圾桶悬在中间，会产生很强的“UI贴图”感。

建议将这一组正式定义为：

## 「辅助操作区」

直接落到工作台右上角。

推荐布局：

```text
                       工作台
────────────────────────────────
                 [出餐] [豆浆]
                 [补料] [丢弃]
               
                     煎饼小料区
```

或者如果希望减少占用：

```text
[出餐] [豆浆] [丢弃]
```

排成一行即可。

其中我尤其建议：

- **出餐**：最靠近顾客方向
- **豆浆**：靠出餐
- **补料**：靠食材区域
- **丢弃**：最右侧或者右下角

符合操作语义：

```text
制作 → 配料 → 出餐
           ↓
          丢弃
```

而不是现在几个功能散落在顾客和桌面的夹层。

另外，“补料”如果只是系统功能按钮，我甚至建议以后从实体道具里弱化，做成小按钮，不要跟“出餐盘 / 豆浆杯 / 垃圾桶”抢视觉层级。

---

### 4. 煎饼小料必须全部回到各自托盘内部

右侧现在最大的问题不是单纯尺寸，而是**食材和容器关系完全断开了**。

例如：

```text
🥚 [ 鸡蛋 ]

🥓 [ 火腿 ]

🧅 [ 香葱 ]
```

视觉上表达的是：

> 食材在盘子旁边。

但玩家实际需要理解的是：

> 这是装鸡蛋的槽位、装火腿的槽位、装香葱的槽位。

所以应该统一改成：

```text
┌──────────┐
│    🥚     │
└──────────┘

┌──────────┐
│    🥓     │
└──────────┘

┌──────────┐
│    🧅     │
└──────────┘
```

建议全部做成统一组件：

```text
IngredientSlot
├─ TraySprite
├─ IngredientAnchor
│  └─ IngredientSprite
├─ Label
├─ CountLabel
└─ ClickArea
```

并设置一套统一比例。

| 类型 | 建议占托盘内部 |
|---|---:|
| 鸡蛋 | 55%～65% |
| 面糊碗 | 65%～75% |
| 薄脆 | 50%～60% |
| 火腿 | 55%～65% |
| 酱料 | 55%～65% |
| 香葱 | 60%～70% |

尤其是香葱，目前散得太开。**不要表现成十几颗真实散落葱花**，缩成一小撮卡通葱段放进槽位即可。

## 我建议把天津工作台重新划成 4 个固定区域

现在最值得做的是把页面坐标体系固定下来：

```text
┌───────────────────────────────────────────┐
│ HUD                                       │
├───────────────────────────────────────────┤
│                                           │
│              顾 客 / 订 单                │
│                                           │
├───────────────────────────────────────────┤
│                   柜台                    │
├────────────┬──────────────┬───────────────┤
│            │              │  出餐 / 豆浆  │
│ 油条制作区 │   煎饼制作区  │  补料 / 丢弃  │
│            │              ├───────────────┤
│ 炸锅       │    煎饼锅     │  煎饼配料区   │
│ 生油条     │              │               │
└────────────┴──────────────┴───────────────┘
```

也就是：

**① 左：油条区  
② 中：核心煎饼锅  
③ 右上：辅助操作  
④ 右下：煎饼配料**

这会比现在“很多素材凭坐标摆在桌上”稳定得多。

## Godot 里这次最好顺手解决根因

以后所有可放入容器的素材都不要记录：

```text
Sprite全局坐标
Sprite独立缩放
```

而记录：

```text
Slot位置
Slot尺寸
IngredientAnchor位置
IngredientMaxSize
```

比如：

```gdscript
func fit_ingredient(sprite: Sprite2D, max_size: Vector2):
    var tex_size = sprite.texture.get_size()
    var scale_factor = min(
        max_size.x / tex_size.x,
        max_size.y / tex_size.y
    )

    sprite.scale = Vector2.ONE * scale_factor
    sprite.position = Vector2.ZERO
```

这样以后无论油条、鸡蛋、火腿还是武汉章节的热干面、萝卜丁、牛肉，都不会再频繁出现：

> “换了一张素材，位置和比例全坏了。”

### 修改优先级

我会按照这个顺序修：

**P0：小料全部回槽 + 生油条缩小回槽。**  
这是当前最明显的“素材错位”。

**P0：出餐 / 豆浆 / 补料 / 丢弃进入工作台。**  
修正交互区域逻辑。

**P1：压缩顾客与工作台的垂直距离。**  
这个会显著改善整个页面的紧凑度和经营感。

**P1：全部食材槽位组件化。**  
从根本解决天津、武汉后续的素材适配问题。

**P2：再统一标签、数量数字、盘子尺寸和点击反馈。**

其中前 3 项改完后，当前页面的“拼贴感”会下降很多；**第 4 项组件化则是最值得开发侧做的长期修复**。
