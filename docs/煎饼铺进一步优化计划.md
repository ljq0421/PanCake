# 煎饼铺进一步优化计划

> 项目：Project Cake  
> 范围：第一章 · 清晨煎饼铺  
> 整理日期：2026-09-01  
> 依据：当前四区单鏊运行时、玩法说明、玩法建议与真人试玩结论  
> 总原则：暂不增加第五生产区、第二口鏊子或更多常驻设备；优先把现有系统打磨成有节奏、有记忆点、有重复游玩动力的成品体验。

## 1. 总体结论

当前煎饼铺已经具备完整的经营框架：

- 手工摊煎饼；
- 单鏊长期约束；
- 油条、豆浆、成品饮品与煎饼四区同屏经营；
- 顾客、订单、耐心、库存、浪费与收款；
- 日结、成长、熟练度、口碑和每日目标；
- 自动化逐步改变劳动结构。

下一阶段不再以“增加功能数量”为目标，而应依次强化：

```text
手工感
→ 调度感
→ 决策感
→ 节奏感
→ 人情味
→ 长期目标
```

真人试玩已经完成，因此“组织首次真人试玩”不再列为待办。后续工作应把试玩发现转化为问题基线，并在每次改版后进行针对性复验。

## 2. 优化阶段总览

| 阶段 | 核心目标 | 主要内容 |
| --- | --- | --- |
| P0 | 收口试玩结果与当前改版 | 回填试玩结论、统一规则口径、完成正在进行的工作台布局和交互调整 |
| P1 | 降低注意力负担 | 重构视觉层级、订单状态、紧急提醒、设备反馈和声音提示 |
| P2 | 强化招牌煎饼与自动化转型 | 加强制作辨识度，并让后期挑战从手工精度自然转向经营调度 |
| P3 | 提高重复可玩性 | 特殊营业日、顾客类型、订单策略和轻量连击 |
| P4 | 建立长期动力 | 经营流派、店铺视觉成长、长期评级和熟客故事 |

## 3. P0：收口真人试玩与当前改版

### 3.1 回填真人试玩结果

真人试玩已经完成，但仓库中的正式验收记录仍需要回填。至少整理以下数据：

- 第一张煎饼完成时间；
- 首次理解倒面、摊面、翻面、刷酱、打包和交付所需时间；
- A/B/C 等级分布；
- 错单率及具体原因；
- 误触位置与出现频率；
- 油条焦糊率；
- 豆浆未接满率；
- 顾客失败率；
- 每日收入与浪费；
- 实际购买的成长顺序；
- 是否存在明显必买项；
- 10 分钟后的手腕、手指和视线疲劳；
- 玩家开始觉得重复或主动退出的时间点。

问题按以下方式分类：

| 类型 | 定义 | 处理原则 |
| --- | --- | --- |
| 阻断问题 | 无法理解、无法点击、流程卡死或状态无法恢复 | 当前版本优先修复 |
| 高频摩擦 | 反复误触、状态难找、步骤冗余、反馈过慢 | 纳入 P1 |
| 平衡问题 | 订单压力、收入、成长速度或必买项异常 | 有数据后再调数值 |
| 主观偏好 | 画风、动画强度、音效风格、文案语气 | 多人重复出现后处理 |

每个问题需要记录：

```text
问题描述
→ 出现场景
→ 复现步骤
→ 出现次数
→ 影响程度
→ 处理优先级
→ 修改后的验收方法
```

### 3.2 统一顾客容量口径

当前资料存在需要统一的口径：

- 当前目录配置中存在 `queue_size = 3`；
- 工作台布局规范按五个顾客槽位设计；
- 部分现有文档仍以三名顾客高峰描述压力。

在继续调整订单卡宽度、到客节奏和难度前，需要明确：

1. 正式同时在场顾客上限；
2. 订单卡固定槽位数量；
3. 空槽是否长期保留；
4. 不同营业日是否允许临时改变顾客上限。

统一后同步修改运行时配置、场景、测试和文档，避免布局与平衡使用不同基线。

### 3.3 完成当前工作台调整

当前工作区已经存在订单完成勾选、提醒轨道、工作区重排等相关修改。下一步应先完成并验收现有改版，不重新设计另一套界面。

P0 完成条件：

- 真人试玩结果已回填；
- 最影响可玩性的三个问题已有处理结论；
- 最影响操作流畅性的三个问题已有处理结论；
- 顾客容量和订单槽位口径统一；
- 当前工作台改版形成一个可完整回归的稳定基线；
- 没有在收口过程中加入新设备或新配料。

## 4. P1：注意力与操作舒适度

后期四区全开后，游戏的主要挑战已经从“会不会做煎饼”转变为“能否快速看懂整屏并决定下一步”。本阶段核心是注意力设计。

### 4.1 建立统一注意力层级

全屏内容按以下优先级组织：

| 层级 | 内容 | 展示原则 |
| --- | --- | --- |
| L+ | 即将失败的顾客或设备、当前必须执行的动作 | 同一时刻最多一个最高焦点 |
| L | 当前订单、当前正在制作的食物、当前交互反馈 | 持续清晰，但不压过紧急事件 |
| M+ | 油条炸锅、豆浆机等计时设备 | 平时安静，状态变化时醒来 |
| M | 成品饮品、包装、暂存与收款 | 需要时突出 |
| S | 配料容器、杯子、工具和库存数量 | 保持可辨认，降低视觉权重 |

设备不能一直保持最高亮度。视觉中心应随当前任务移动。

### 4.2 把订单卡改成任务清单

订单卡首先回答“还缺什么”，而不是要求玩家反复解析小图标。

每个订单商品提供明确状态：

| 标记 | 状态 |
| --- | --- |
| `✓` | 已交付 |
| `◐` | 已有成品或正在制作 |
| `○` | 尚未开始 |
| `!` | 缺货、产品不匹配或即将超时 |

要求：

- 商品、份数和完成状态优先展示；
- 详细配料通过悬停、键盘聚焦或展开查看；
- 已完成项降低视觉权重；
- 当前可交付项保持稳定标记，不依赖短暂动画；
- 耐心不足时同时使用图标、文字和进度条变化；
- 多商品订单不能无限增加卡片高度。

### 4.3 完成工作台视觉降噪

- 降低静态设备、木纹和普通库存的饱和度与对比度；
- 食物、当前操作和危险状态保留较高视觉强度；
- 重复库存改成代表物加数量角标；
- 无限库存不显示虚假数量；
- 状态文字贴近所属设备；
- 油条成品靠近炸锅；
- 豆浆杯与豆浆机保持同组；
- 配料与调味形成清晰模块，不继续拆成大量视觉碎片；
- 全屏同时最多保留一个 L+ 视觉焦点。

### 4.4 优化操作热区

- 所有主要交互目标的有效范围至少为 `56×56 px`；
- 小图片使用透明点击容器补足热区；
- 长按补货显示 `0.20 秒`进度；
- 按下后移动应取消原地长按，避免补货与拖动冲突；
- 不可用控件不得继续抢占其他有效控件的鼠标命中；
- 悬停、选中、进行中、完成、风险和禁用状态必须可区分；
- 暂停或弹窗关闭后不能保留输入粘连。

### 4.5 用声音分担视线压力

建立稳定且不混淆的声音词汇：

- 煎饼达到适合翻面的窗口；
- 油条成熟；
- 油条开始衰减；
- 油条焦糊；
- 豆浆接满；
- 顾客耐心不足；
- 商品已经可交付；
- 收款完成。

声音规则：

- 同一状态持续期间只播放一次；
- 状态离开后再次进入，才允许重新播放；
- 完成、警告和失败使用不同音色；
- 四区同时提示时按紧急度混音，不全部同音量播放；
- 静音状态下仍可只靠画面完成全部操作；
- 遵守“减少动态效果”设置，不把频繁闪烁作为唯一提醒。

### 4.6 P1 验收标准

- 全解锁高峰状态下，玩家能在约 3 秒内找到最紧急事项；
- 玩家能判断该事项属于哪个工作区；
- 玩家能看清下一步可执行动作；
- 不依赖颜色也能判断完成、危险、缺货和不可用；
- 静音状态下能够完成四区各一份商品；
- 不再出现透明热区、禁用控件或订单卡抢占无关点击；
- 提醒同时出现时有稳定优先级；
- 同类警告不会连续重复播放；
- 1920×1080、1600×900、2560×1440 下无裁切和重叠。

## 5. P2：强化招牌煎饼与自动化转型

煎饼是项目最具辨识度的产品，但“招牌感”不等于要求玩家从开店到全解锁都重复同一套手工操作。后期允许发展成全自动流水线，并把挑战完整转移到订单、库存、设备、产能和交付调度。

因此，后期煎饼品质趋于稳定应被视为成长奖励，而不是需要重新制造误差的问题。P2 的目标改为：

```text
前期学习手艺
→ 中期用工具降低失误与重复劳动
→ 后期形成稳定流水线
→ 玩家转而经营整家早餐铺
```

### 5.1 明确三个生产阶段

| 阶段 | 煎饼品质来源 | 玩家主要挑战 | 招牌感来源 |
| --- | --- | --- | --- |
| 手工期 | 摊制、火候、配料与顺序 | 学会制作一张合格煎饼 | 操作手感、成品差异和即时反馈 |
| 半自动期 | 工具提高下限，玩家完成关键动作 | 在制作与多区经营之间切换 | 设备升级带来的效率变化 |
| 全自动期 | 流水线稳定产出标准煎饼 | 订单分配、产能、库存、等待与交付 | 连续生产演出、品牌产品和高峰调度 |

各阶段的核心考题必须发生变化，不能在全自动后继续用手工期的厚薄、破洞和摊制精度反复考核玩家。

### 5.2 保留自动化升级的真实价值

现有“定量面糊勺”“压饼器”等升级可以继续消除对应品质波动：

- 定量面糊勺解决面糊份量不稳定；
- 压饼器解决厚薄、覆盖和手工摊制误差；
- 不会糊鏊子消除焦糊这一类严重失败；
- 一键鸡蛋、自动酱料等工具减少重复操作；
- 完整自动化后，正确配置的流水线可以稳定生产高品质煎饼。

不建议采用以下做法：

- 给压饼器设置隐藏品质上限；
- 为了制造差异，给自动产品添加不可控制的随机瑕疵；
- 强制玩家进行人工收边、二次压制等重复操作才能达到 A 级；
- 升级后仍用已经自动完成的维度惩罚玩家。

这些做法会削弱成长反馈，让升级看起来像以效率换取品质的倒退。

### 5.3 将后期差异转移到经营结果

全自动不等于没有挑战，而是挑战对象由“这一张饼摊得怎么样”变成“整条生产与交付链是否运转良好”。后期重点考核：

| 经营维度 | 典型问题 | 玩家决策 |
| --- | --- | --- |
| 订单优先级 | 哪位顾客即将失去耐心 | 调整制作与交付顺序 |
| 成品新鲜度 | 成品放置过久 | 控制预制数量和出锅节奏 |
| 产能分配 | 煎饼、油条、豆浆需求同时上升 | 决定先处理哪个工作区 |
| 库存衔接 | 面糊、鸡蛋或配菜不足 | 提前补货，避免流水线停机 |
| 设备状态 | 自动设备占用、冷却或需要处理 | 安排启停和操作窗口 |
| 订单正确性 | 多个相似订单容易拿错 | 匹配成品、订单与顾客 |
| 浪费控制 | 预制过多或预测错误 | 在吞吐与库存风险之间取舍 |

自动化产品可以保持稳定高品质，但仍会因为错单、等待过久、缺货、产能堵塞或交付失败影响收入、口碑和顾客满意度。

### 5.4 强化流水线的招牌演出

全自动之后，煎饼仍应是画面和声音的主角。重点不是继续显示失败痕迹，而是让玩家感受到一条成熟流水线正在高效工作：

- 定量面糊落下、压饼器展开、翻面、加料、刷酱、折叠和装袋形成连续可读的动作链；
- 每个自动步骤有明确但不过度抢眼的机械动作和声音标识；
- 不用瞬间贴图替换跳过关键生产过程；
- 高峰期连续出饼时形成节奏感和成就反馈；
- 煎饼成品在订单卡、托盘、交付和顾客反馈中保持统一的招牌视觉；
- 标准产品可以有不影响评分的轻微自然外观变化，避免复制粘贴感，但不能伪装成品质缺陷。

### 5.5 分阶段调整结果反馈

手工期和半自动期继续反馈具体制作问题：

1. 当前最低的制作维度；
2. 发生原因；
3. 下一张可以执行的改进建议。

全自动期不再反复表扬或诊断已经被设备解决的厚薄、覆盖等维度，结算重点改为：

- 本单是否正确；
- 从接单到交付耗时；
- 成品等待时间与新鲜度；
- 顾客耐心剩余；
- 是否发生缺货、停机或浪费；
- 当前高峰期的吞吐表现。

结果界面只突出一个最主要的问题或一个最值得肯定的经营表现，避免同时堆叠制作分和经营分。

### 5.6 增加阶段化顾客反馈

手工期顾客可以评论具体成品：

- “今天这张摊得真薄。”
- “边上焦了一点，不过还挺香。”
- “老板，我点的香菜没放。”

全自动期顾客反馈应转向店铺经营表现：

- “这么多人，出餐还挺快。”
- “煎饼是热的，没白等。”
- “我点的套餐这么快就齐了。”
- “等了半天，拿到手都凉了。”
- “老板，好像拿错我的那份了。”

反馈必须由真实状态生成；已经由自动化彻底解决的问题不能继续被顾客抱怨。

### 5.7 P2 验收标准

- 玩家能明确感受到手工、半自动和全自动三个阶段的玩法重心变化；
- 定量面糊勺和压饼器不会被隐藏降级，完整自动化可以稳定产出高品质煎饼；
- 全自动后不再要求玩家重复完成摊制、收边等手艺动作；
- 自动生产过程仍有完整、连续且可辨认的煎饼制作演出；
- 全自动后，订单、库存、设备、等待和交付至少形成三项同时存在的调度压力；
- 高峰期的成功与失败能够由玩家经营决策解释，而不是由不可控制的品质随机数决定；
- 结算与顾客反馈会随生产阶段切换关注点，不抱怨已被升级消除的问题；
- 自动化显著降低重复劳动，但不会替玩家自动解决整家店铺的经营决策。

## 6. P3：增加重复可玩性

本阶段不增加新的生产机器，而是让同一套四区系统在不同营业日产生不同节奏和决策。

### 6.1 数据化特殊营业日

第一批只做五种日型：

| 日型 | 主要变化 | 设计目的 |
| --- | --- | --- |
| 普通日 | 当前标准规则 | 作为平衡基线 |
| 早高峰 | 到客更集中，简单订单增加 | 强调吞吐和提前备货 |
| 学生日 | 低价订单多，饮品需求增加 | 强调数量与库存 |
| 雨天 | 顾客较少，但耐心更短 | 强调优先级判断 |
| 周末 | 组合订单和高价订单增加 | 强调多区调度 |

每种日型只改变一到两个变量：

- 到客间隔；
- 顾客耐心；
- 订单权重；
- 商品数量；
- 组合单比例；
- 每日目标。

不修改食品评分规则，不同时堆叠大量隐藏倍率。

### 6.2 顾客原型

建立少量、可预测的顾客类型：

| 类型 | 特点 | 玩家预期 |
| --- | --- | --- |
| 上班族 | 耐心短、支付较高 | 必须快速判断是否优先处理 |
| 老人 | 耐心长、偏好传统配方 | 适合作为稳定订单 |
| 学生 | 预算低、偏好饮品 | 数量多、利润较低 |
| 健身顾客 | 无糖、少酱、不加薄脆 | 配方准确性压力 |
| 外卖员 | 一次多份 | 批量生产压力 |
| 美食博主 | 要求高、口碑奖励高 | 低频高风险目标 |

项目已经存在学生、大胃王和探店博主等特殊顾客解锁，应扩展现有目录和顾客框架，不再另做一套平行系统。

### 6.3 增加订单决策信息

订单卡应让玩家清楚看到：

- 剩余耐心；
- 商品和份数；
- 是否已经有匹配成品；
- 是否正在制作；
- 是否缺货；
- 预计收益或价格等级；
- 失败或拒绝的代价。

压力应从“找不到按钮”转变为：

> 我现在应该先救哪一单？

### 6.4 轻量连击

利用已有连续正确订单统计，试做克制的经营状态：

- 连续 3 单达到 B 级以上：进入“顺风营业”；
- 连续 A 级达到阶段目标：触发“人气小店”；
- 错单或订单失败：连击中断；
- 奖励以少量金币、口碑或表现效果为主；
- 不提供会压倒其他系统的高倍收益。

连击不能迫使玩家只追求速度。手工期同时考虑品质与准确度；全自动期则同时考虑订单准确度、新鲜度、浪费和设备调度。

### 6.5 每日目标升级为小挑战

在现有目标系统上扩展条件挑战，例如：

- 今日不使用自动升篮；
- 今日豆浆订单权重提高；
- 今日组合订单比例增加；
- 今日顾客耐心降低；
- 今日不能出现焦糊；
- 今日连续完成三份 A 级煎饼；
- 今日浪费成本不得超过指定值。

挑战应提前公开，不能在营业中突然修改核心规则。

### 6.6 P3 验收标准

- 不同营业日能够明显改变优先级和备货策略；
- 玩家在进入营业前就能看懂当天规则；
- 特殊日不生成未解锁或无法完成的订单；
- 顾客类型可以通过外观、称号或简短说明预测；
- 顾客特性不依赖隐藏规则；
- 连击奖励不会让普通经营收益失去意义；
- 五种日型共用现有四区，不增加工作台物件；
- 特殊日、顾客原型和每日挑战均可通过数据配置扩展。

## 7. P4：长期成长与二次游玩

全部解锁后，玩家仍需要明确的继续经营理由。本阶段解决“为什么还要再开一天”和“为什么值得重新开档”。

### 7.1 经营流派

不立即推翻现有成长树。先在全解锁后提供有限选择、经营方针或可更换槽位。

建议先原型验证两种，再扩展：

| 流派 | 主要收益 | 主要代价 |
| --- | --- | --- |
| 高周转流水线 | 生产更快、吞吐更高 | 库存、错单和浪费风险上升 |
| 稳健经营 | 设备容错、库存安全和顾客耐心更高 | 极限产能和单日收入上限较低 |
| 早餐套餐流 | 豆浆和油条组合获得额外奖励 | 单品订单收益一般 |
| 精品小铺 | 顾客较少、售价和品牌收益更高 | 新鲜度、服务和错单要求更严格 |

两种流派必须让实际操作和优先级不同，不能只是数值颜色不同。

### 7.2 店铺视觉成长

不再增加工作台机器，改为升级环境：

```text
路边小摊
→ 社区早餐铺
→ 人气早餐店
→ 老街名店
→ 城市招牌店
```

可变化内容：

- 门头；
- 灯笼；
- 墙面；
- 菜单；
- 桌椅；
- 收银台；
- 奖杯；
- 街道人流；
- 顾客背景；
- 店铺称号。

环境成长不得增加新的操作热区或遮挡现有工作台。

### 7.3 长期目标

全解锁后同时保留三类目标：

| 类型 | 示例 |
| --- | --- |
| 技术目标 | A 级率、最佳煎饼、无破洞连续记录 |
| 经营目标 | 单日营业额、连续成功、低浪费、特殊日成绩 |
| 收藏目标 | 熟客故事、店铺评级、图鉴、称号和成就 |

### 7.4 熟客故事

熟客通过营业日、口碑或区域熟练度推进短事件：

```text
第一次来店
→ 记住常点配方
→ 为家人带餐
→ 评价店铺变化
→ 见证店铺成为老街名店
```

原则：

- 不做大型分支剧情树；
- 单次对话保持简短，不打断营业节奏；
- 故事内容与顾客偏好和真实订单结合；
- 熟客重新出现时可以预测订单，但不能完全固定；
- 情感成长不额外增加生产操作。

### 7.5 P4 验收标准

- 全部设备和配料解锁后，玩家仍有至少三类明确目标；
- 两种经营流派能够产生不同的升级和订单策略；
- 店铺成长在画面上明显，但不增加工作台拥挤度；
- 熟客故事不会遮挡订单或暂停关键生产；
- 长期目标能够读取现有口碑、熟练度、订单和日结数据；
- 重开存档时至少存在一种值得尝试的不同经营路线。

## 8. 工程与数据支持

玩法扩展需要以下底层支持，避免把新内容继续硬编码进大型工作台脚本：

### 8.1 数据资源

建立可验证的数据定义：

- `business_day_profile`：营业日型；
- `customer_archetype`：顾客原型；
- `customer_feedback_line`：顾客反馈；
- `challenge_definition`：每日挑战；
- `business_style`：经营流派；
- `shop_visual_stage`：店铺视觉阶段。

### 8.2 权威规则校验

自动校验：

- 顾客容量与订单槽位一致；
- 特殊日不引用未解锁商品；
- 顾客偏好引用有效商品和配料；
- 成长价格、前置条件和显示顺序一致；
- 顾客反馈引用有效评分标签；
- 店铺视觉阶段不修改运行时设备合同；
- 新内容不会添加第五区域或第二口鏊子。

### 8.3 遥测与报告

继续使用本地、显式启用的试玩遥测，新增汇总：

- 不同日型完成率；
- 各顾客类型失败率；
- 订单放弃与拒绝原因；
- 连击长度；
- 不同经营流派收入和品质分布；
- 全解锁后的继续营业天数；
- 熟客事件触发率。

不采集账号、设备信息或自由文本，不上传网络。

## 9. 推荐实施顺序

严格按以下顺序推进：

1. 回填真人试玩结果；
2. 统一顾客容量和订单槽位口径；
3. 完成当前工作台布局、提醒轨道和订单状态改版；
4. 修复真人试玩中最高频的三个操作问题；
5. 完成注意力优先级、设备状态和声音词汇；
6. 强化煎饼从制作到交付的视觉连续性；
7. 接入基于真实评分的顾客短反馈；
8. 实现数据化特殊营业日；
9. 扩展顾客原型和订单策略信息；
10. 小规模试做连击；
11. 原型验证两种经营流派；
12. 增加店铺视觉成长；
13. 最后加入熟客故事和长期收藏目标。

每完成一个阶段，都先做对应问题的针对性真人复验，再进入下一阶段。不重新执行已经完成的首次综合试玩，但所有改变操作、信息密度或难度的改版都必须验证。

## 10. 近期优先级

如果只安排下一批最值得做的五件事，顺序如下：

### 1. 收口真人试玩结论

把试玩发现转化为正式问题清单、优先级和验收标准，避免凭印象继续调整。

### 2. 完成全解锁界面的注意力层级

先解决当前订单、紧急设备、静态设备和库存同时争抢注意力的问题。

### 3. 强化煎饼的流水线演出和阶段反馈

让煎饼在手工期依靠制作体验建立辨识度，在全自动期依靠流水线演出、招牌产品和高峰调度继续承担核心地位。

### 4. 加入特殊营业日和顾客原型

复用现有四区系统，以较低成本增加节奏变化和订单决策。

### 5. 建立长期目标

用经营流派、店铺评级、环境成长和熟客故事解决全部解锁后的目标消失问题。

## 11. 暂不实施

现阶段不建议优先开发：

- 第五生产区；
- 第二口或第三口煎饼鏊子；
- 更多常驻机器；
- 大量新配料；
- 复杂食谱树；
- 复杂装修编辑器；
- 大型剧情系统；
- 角色数值养成；
- 员工自动经营；
- 外卖大系统；
- 开放世界；
- 多人模式。

这些内容会继续扩大界面、平衡和维护成本，但无法直接解决当前最关键的注意力、节奏、重复感和长期目标问题。
