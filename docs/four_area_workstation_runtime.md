# 四区单鏊工作台运行时合同

> 正式基线：2026-08-30，Godot 4.7.1。本文件是当前玩法、场景、存档和自动验证的唯一规则来源。若其他文档、历史测试名或兼容代码中的“五区”表述与本文件冲突，以本文件和当前运行时实现为准。

## 正式玩法

- 固定四区：`area.pancake`（煎饼）、`area.youtiao`（油条）、`area.fresh_soy_milk`（现磨豆浆）、`area.packaged_drink`（成品饮品）。
- 煎饼区只有 `device.pancake_griddle`，其 `griddle_count` 固定为 `1`；成长不提供第二或第三个鏊位。
- 正式工作台入口是 `res://scenes/gameplay/four_area_workstation.tscn`。它继承旧路径 `five_area_workstation.tscn` 的资源内容，后者只作为存量资源兼容层，不代表五区玩法，也不得作为新功能入口。
- 订单、库存、成长和设备只能引用上列四区目录中存在的稳定 ID。

## 开局、营业时间与教学

- 新游戏只开放煎饼区、基础面糊和无限量秘制酱料；鸡蛋、薄脆、葱花及其他付费配料均未解锁。不得从历史文档恢复“首日三配料、各 6 份”的规则。
- 每个营业日先提供 5 秒开场备货窗口。
- 第 1 日煎饼教学单不消耗营业倒计时，也不能被拒绝；教学结束或跳过后，从保留值继续倒计时。
- 第 1 日营业时长为 60 秒，第 2 日及以后为 120 秒；剩余 10 秒进入打烊提示，归零后立即日结。

## 正式输入合同

- 面糊勺：点击拿起，在鏊面按住左键完成定量倒面；有效的 GUI 按下必须以鏊面自身的按压状态为准，不能因同一帧全局鼠标状态尚未同步而取消。
- 摊饼器：点击拿起，在鏊面按住并移动完成摊面；轨迹按移动距离采样。
- 生配料：点击已解锁且有库存的容器，系统按该容器定义的固定落点加入一份。生配料不支持拖到鏊面，配料位置只保留为诊断与画面信息。
- 补货：在可补货容器上原地长按。生配料使用 0.20 秒手势判定；秘制酱料为无限量，不进入付费补货。补货进度和扣费仍由库存服务决定。
- 秘制酱料：翻面后点击酱料源，系统自动完成一次均匀刷酱；不要求玩家拿起酱刷画轨迹。
- 翻面/打包：同一主操作按钮按当前阶段执行翻面或打包。点击“打包”后系统自动完成两侧折叠、装入纸袋并进入成品状态；不提供手动折边手势。
- 交付：点击顾客订单卡中的目标商品，将一个匹配的可交付成品交给该顾客。已打包煎饼既可来自单鏊成品，也可来自已解锁的成品暂存位。

## 评分合同

- 配料维度只比较订单要求的配料种类与份数、实际加入内容及意外多加内容；正确配方即获得完整配料分。
- 点击配料的固定落点分布仍保存在成品快照中，供渲染、诊断和未来规则使用，但当前不参与配料得分，也不得产生“配料靠边易漏”等顾客负面标签。
- 面饼覆盖、厚度、火候、酱料、折叠结构、订单匹配和制作时间继续按各自现行模型计分；不得用屏幕像素反推业务得分。

## 存档与成长

- 当前存档格式为版本 10、`save_kind = breakfast_stall_four_area_v1`。所有更早开发存档均不兼容并在启动时清除。
- 继续游戏恢复活动订单、顾客到店状态、生产快照、金币、成长和库存；恢复过程不得重新生成或重放已保存顾客。
- 日结收取待付款，然后清空未结订单、进行中的设备、单鏊成品、暂存成品和库存。次日回到备货窗口。
- 当日购买的成长在下一营业日激活；其新解锁库存从零开始，必须通过备货获得。
- 高频营业状态使用 2 秒合并写盘窗口。计时从本轮首次脏写开始，后续连续变更不能反复重置窗口；退出场景或进程时立即刷新待写存档。

## 公开接口与测试

- 新测试使用 `GameSession` 的中性公开接口：`is_four_area_save_active`、`four_area_progression_snapshot`、`four_area_production_snapshot`、`pancake_griddles_snapshot`、`save_pancake_griddles`、`production_machine_snapshot`、`advance_production`、`restock_status` 与 `advance_restock_hold`。
- `tools/run_checks.ps1` 自动发现全部 unit/integration 自检，每项以独立 Godot 进程和 60 秒超时运行，并在全部完成后汇总。
- `tools/run_gpu_smoke_checks.ps1` 自动发现当前 `*_gpu_smoke.gd`；历史交互检查必须移入 `tests/archive`，不能继续污染正式 GPU 结果。
- `tools/run_release_checks.ps1` 是完整发布门禁。使用 `-SkipGpu` 只能做无 GPU 环境的局部验证，不等于正式通过。
- `four_area_first_day_e2e_self_check.gd` 建立空白首日存档；`four_area_existing_save_e2e_self_check.gd` 在新进程中恢复该存档并验证继续、日结、跨日与成长激活。
- 自动 GUI 事件和截图不能替代真人操作验收；连续制作疲劳、误触率、目标辨识度和音效听感必须记录在当前四区人工试玩清单中。
